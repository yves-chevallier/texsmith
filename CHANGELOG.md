## [Unreleased]

### Added

- **The documentation site builds with Zensical, from the same `mkdocs.yml`.** Zensical has no plugin hooks — the only thing it calls Python for is rendering Markdown — so the web lowering is also a Python-Markdown extension, `texsmith.site.web`, driving the same `texsmith.site` code as the MkDocs plugin: a preprocessor pre-passes every page in navigation order (through the resolver of `texsmith.site.nav`, since Zensical resolves `nav` in Rust and shows Python an empty one) and lowers the page with `tmark.lower_web`, and a postprocessor rewrites the `.snippet` fences to their previews; `texsmith.css` now ships with the `texsmith` package rather than with the plugin, which reads it from there. What a build generates, it generates *before* Zensical runs: Zensical clears the site directory when a build starts and replays a cached page without calling Python at all, so a file written while a page renders is deleted and never written again — which is what left `examples/colorful/` with a broken preview and a 404 behind its PDF link. The new `texsmith site assets [CONFIG]` command makes them sources instead: it reads the same configuration file the extension reads, resolves the navigation, walks every page's IR for `.snippet` fences (`include=` splices resolved the way `pymdownx.snippets` splices them), renders each preview into `docs/assets/snippets/`, writes `docs/assets/texsmith/texsmith.css` and prunes the previews no page asks for any more, reporting a fence it cannot build with the name of its page and carrying on. The extension no longer writes the stylesheet — it says to run the command when the file is missing — and writes a preview under `docs_dir` rather than `site_dir`, so a snippet edited under `zensical serve` still appears in the rebuild the new file triggers. `texsmith site` is the CLI's first command group; `texsmith doc.md` is unchanged. The extension acts only when Zensical's rendering context is on the `Markdown` instance *and* that instance carries Zensical's link rewriting, which the inner instances mkdocstrings builds for each docstring do not: listing it under `markdown_extensions` is harmless under MkDocs, where the plugin does the work, and it lowers each page once rather than once per docstring. `mkdocs.yml` gains the extension, names `assets/texsmith/texsmith.css` under `extra_css` (Zensical reads that list before Python runs) and spells `pymdownx.snippets`' `base_path` without the `!relative` tag Zensical's loader does not know; `make docs-zensical` and `make serve-zensical` run `texsmith site assets` and then build or serve. Two things Zensical does after Python is done, or not at all, are done by the same command group. `texsmith site search [CONFIG]` puts the index entries a page declares (`#[term]`) into the search index the build wrote: it walks the built site for the `ts-index` markers the lowering leaves in the pages, keys them by page and by section heading the way the index does, and patches whichever format is there — the `tags` field of MkDocs' `search/search_index.json`, which Material searches and boosts, and the `text` of Zensical's `search.json`, since `tags` there are the filter chips, an aggregation of exact values a reader clicks rather than something they type; `SearchTags` moved out of the MkDocs plugin into `texsmith.site.search`, which the plugin now imports, and `make docs-zensical` runs the command after `zensical build`. And `texsmith site assets` exports every `.drawio` image the pages reference to `docs/assets/drawio/<path>.svg`, which the extension's postprocessor points the `<img>` at — Zensical has no `drawio` plugin, so the page used to show an `<img>` pointing at an XML file: the draw.io strategy takes its export format as a parameter (`DrawioStrategy`, `drawio_export`, one code path where the target's suffix is the `--format` the CLI, the container and the Playwright backend are given), the `.drawio` file stays where it is for MkDocs' plugin and for the PDF, and a diagram nobody exported keeps its tag and a warning naming the command. The PDF book hangs off `on_post_build` too, so it is `texsmith site build [CONFIG]`: the book logic left the plugin for `texsmith.site.book`, which knows nothing of any generator — the `books:` options and the plugin-level defaults, the flattening of a `texsmith.site.nav` navigation into chapters and headings (a section becomes the heading it always did, a page a chapter, `root: "__texsmith_full_navigation__"` the whole site, `slots:` a title routed to a template slot), the per-page sources and the render, the template wrap and the engines. The command reads the configuration file, resolves the navigation, pre-passes every page so the book carries the site's own numbers, writes each book's bundle under `build_dir` and compiles the PDF, with `--build-dir`, `--book TITLE`, `--no-pdf` and the root command's `--strict` and `--diagnostics-json` (the strict check runs once the `.tex` is written and before the engine); no `mkdocs` is imported anywhere on its path, which a test pins with an import blocker. The plugin is now the adapter that hands the same builder MkDocs' navigation, its site metadata and the site index its hooks filled in, and the `.tex` of this repository's own 303-page book is byte for byte the one `mkdocs build` writes — bar one listing that quotes a page's Markdown, where MkDocs' `drawio` plugin had added a class of its own before TeXSmith saw the page. `make docs-zensical` builds the book after the site. **Breaking:** the plugin's `save_html` option is gone, with the HTML snapshot it wrote: the book has been built from the Markdown sources since the TMark migration, and nothing read that HTML any more. `mike` does not carry over — it hangs off hooks Zensical does not have — and neither does `exclude_docs`, whose pages Zensical builds; `docs/guide/mkdocs.md` says so. The `pills` plugin, which no page used, is gone.
- **The Typst backend has the three callout styles, a real index, stacked margin notes and the letter standards.** `texsmith.typ` reads the `callouts.style` attribute through the `ts-callout-style` state (`fancy` is the coloured frame with its icon, `classic` a rule on the left with a monochrome icon, `minimal` a thin frame and no icon — the three looks of the LaTeX fragment, which used to render as one coloured box whatever the style asked for); `#ts-index` records an entry and `#ts-print-index()` — placed by the `article` and `book` scaffolding when the document has one — prints the index with its sub-entries and page numbers, where it used to be a no-op; `#ts-aside` is a zero-width inline box placed in the margin next to its line, so a note no longer splits its paragraph; every table is set as `booktabs` sets the LaTeX ones (rules above, under the header and below, no vertical rules); the `letter` template lays out the DIN 5008, SN 010130 and NF Z 11-001 window envelopes with the measures of the KOMA-Script class options (`-aformat=din|sn|nf`), where it used to collapse the three to one layout with a grey sender block; and several input documents make one `main.typ`, as they make one `main.tex`.
- **Typst embeds the vector diagrams.** Mermaid and draw.io diagrams, and the snippet previews, reach a Typst document as the same PDF the LaTeX document gets — Typst 0.14 reads PDF images — instead of a PNG raster.

- **A book keeps its own cover, imprint and preamble.** The `book` template reads three new attributes so a project stops having to fork it to change its front matter: `press.titlepage` and `press.imprint` name files whose LaTeX is inlined in place of `\maketitle` and of the imprint page the template builds from `press.imprint.thanks` / `.license` / `.copyright`, and `press.preamble` is LaTeX inserted at the end of the preamble, after the fragments, so it can load a package, redefine a contract macro or override anything above. The two paths are a manifest feature any template can declare, `format = "file"`: the value is a path — relative to the converted document's directory, and to the project directory for a book built from a site's configuration file, where `copy_files` starts too — and the file's text is inlined verbatim, never escaped and never rendered as Markdown. A path that names no file is a `TemplateError`, so a mistyped title page fails instead of silently printing the template's own, and `press.imprint` stays readable as either shape: a path is a page of yours, a mapping is the page the template renders.

### Fixed

- **A reference-style link to another page of a book resolved to nothing.** `texsmith.site.book` handed the resolver only the headings and user counters of the book's other pages, and dropped their plain `[]{#id}` anchors, so `[academic paper][cheese]` on one page stayed the literal brackets CommonMark makes of it even though the book is one LaTeX document and the `\label{cheese}` was in it. Anchors are passed through now and the link is the `\hyperref[cheese]{academic paper}` it should always have been. The text is the author's, so nothing has to be the same on both media; a bare `@key` to a sibling anchor keeps showing the anchor's own text, its span's else its id, which is what `@key` shows for a local anchor too.

- **Two renders sharing the snippet cache could read half a file.** The cache under `~/.cache/texsmith/snippets` is written by whichever render compiles a fence first, and several run side by side — the parity harness renders four at a time, a site build and a `zensical serve` share it. The PDF, the PNG and the Markdown of an entry were copied into place under their final names and the metadata through one temporary name every process used, so a reader could pick up an artefact mid-copy and two writers could interleave in the same file, losing the whole index to a `JSONDecodeError`. Each artefact is now written under a name of its own process and renamed over the entry, which either appears whole or not at all.

- **The `book` header ran off the page.** `fancyhdr` sizes `\headwidth` from the layout memoir has when the package loads, the stock's, and the trimmed page is narrower: on an A5 book the running heads overflowed both edges. The template sets `\headwidth` to the text width once the layout is fixed, and its page styles read memoir's own `\if@twoside` instead of a Jinja flag nothing ever set.
- **Mermaid diagrams rendered with Mermaid's default grey theme.** The default configuration file was looked up at a path that does not exist (`templates/article/template/assets/`), so neither the Playwright nor the CLI backend saw the black-and-white theme the article template ships.
- **Margin notes overprinted each other.** A `\tsaside` on the document's own side is now a `\marginpar` under `marginfix`, which moves a note down past the previous one; a note on the reversed side, or inside a box, stays a `\marginnote` fixed at its line.
- **A moustache in a Typst template attribute rendered as nothing.** `{{callouts.style}}` in a subtitle reached the writer as a `Var` node, which prints empty; the Typst path now resolves the moustaches of the attributes before rendering them, as the LaTeX path does, and a `markdown` attribute of a `[typst.template]` section renders through the Typst writer rather than the LaTeX one.
- **The letter's `back-address` front-matter key was ignored** by the LaTeX template (only `back_address` was read), so KOMA-Script fell back to the full sender line, which overflowed the NF and SN address windows.
- **`examples/colorful`** placed the north-west text in the south-west square (TikZ counts from the bottom), and the Typst poster set its text at 20pt where the LaTeX one uses `\Large`; both quadrants and sizes now agree.
- **The `book` template did not compile in French.** Nine lines were enough — `press: {template: book, language: fr}` and one chapter — to stop at `book.tex:248: Missing number, treated as zero`, and every French book stopped with them, both of the handbook's included. `fixtoc.sty` sizes the table of contents' number columns by measuring `\cftpartpresnum`, which is `\partname`, and babel-french makes that an ordinal built from the part counter (`\csname ordinal\romannumeral\value{part}\endcsname`, "Première partie"); with the counter still at 0 it reached an unrelated `\ordinal` that wanted a number. The measurement now sets the part (and chapter) counter to the number it is measuring and puts it back, and the contents entry does the same through memoir's `\partnumberlinehook` — a local assignment the `\tableofcontents` group undoes, so the document's own numbering is untouched. The entry prints `\thepart` instead of the numeral recorded in the `.toc`, so a language that cancels `\thepart`, as French does, labels the entry the way it labels the heading ("Première partie", not "Première partie I") while English still reads "Part I" and German "Teil I". `examples/book-fr` is the parity entry `book-fr` and one of the five documents `scripts/parity.py pdf` builds and compares.
- **A keystroke whose label is not a control-sequence name aborted the run.** `++shift+←++` reaches the writer as `\tskeys{⇧ Shift,\(\leftarrow\)}`, and `ts_key:n` built `\csname ts@key@<label>\endcsname` out of it: math, a space or a symbol cannot go inside `\csname`, so LaTeX stopped with `Missing \endcsname inserted`. The key-label table is now looked up on the string form of the label, so a label that names no registered key misses the table quietly and is typeset exactly as it was written.
- **A root-relative image path found no file in a book.** A site page writes `/assets/images/figure.png` for a file under `docs_dir` — MkDocs' `validation.absolute_links: relative_to_docs` — but the book builder read the leading slash as the filesystem root, which is how the handbook's two books collected 183 `asset-missing` and lost every figure of one of them. The rule the site's own draw.io export already followed is now one function, `passes.assets.resolve_asset_path`, that every asset the pass resolves goes through (images, the draw.io and SVG diagrams it converts, the `.mmd` sources it reads as fences): a leading slash belongs to the documentation root when the conversion has one, which `texsmith site build` and the MkDocs plugin now pass as `ConversionRequest.root_dir`, and is a filesystem path otherwise, as it is for `texsmith doc.md`.
- **A `--8<--` include went unresolved when the site named no snippet base path.** `pymdownx.snippets` defaults its `base_path` to `['.']`, the directory the build runs from, but TeXSmith read the absence of the option as "no search path" and resolved the include against the page — 32 `include-missing` on the handbook, whose `pymdownx.snippets` sets only `check_paths` and the URL options. A site that enables the extension without naming a `base_path` now searches the project directory, and only a site that does not enable it at all gets none.
- **A lightbox over a draw.io diagram handed the browser the XML.** The web lowering pointed a `.drawio` `<img>` at the SVG `texsmith site assets` exports for it but left the `<a class="glightbox" href="…/diagram.drawio">` glightbox wraps it in, so clicking the figure downloaded a file no browser draws — 122 such links on 40 pages of the handbook, now none. Only an anchor that names the very diagram its own image shows is rewritten, so a link an author wrote to the source file is left alone.

### Changed

- **The site machinery moved to `texsmith.site`**, out of the MkDocs plugin. The site index (the cross-page pre-pass, the label map and the per-page lowering onto `tmark.lower_web`) and a reader for `mkdocs.yml` / `zensical.toml` now live in `texsmith.site.index` and `texsmith.site.config`, with no `mkdocs` import: a page is a `SitePage` (`src_uri`, `abs_src_path`, optional metadata), not an MkDocs `Page`. A site generator without plugin hooks — Zensical — can drive the web lowering through a plain Python-Markdown extension, and the MkDocs plugin is one of its consumers rather than its owner.
- **`examples/markdown` is `examples/tmark`**: the syntax sheet is organised by TMark construct and no longer describes the Python-Markdown extensions that used to implement it. `examples/typst-hello` and `examples/typst-article` are gone — every example builds on both backends — and `counters`, `glossary` and `tables` are built by `make -C examples`.
- **Example builds keep one PDF per variant** (`build/<engine>/<style>/admonition-<style>.pdf`, `build/<engine>/<format>/letter-<format>.pdf`) instead of a copy next to the original, and the letter example has one `build/` directory.
- **The CLI help no longer offers HTML input**, which the reader stopped accepting in 0.7.0.
- **Two parity runs in one checkout no longer corrupt each other.** Every entry of `scripts/parity.py` renders into a directory named after its id, which the run clears first, so a second run deleted the output the first had already written: `baseline --check` reported `no .tex output in …` for three or four entries, a different set every time, which reads exactly like a regression and is not one. A run now holds `build/parity` for as long as it renders, and one that finds it held says which process has it. When a body really is missing the report names what the directory holds and whether the command wrote one at all.
- **The MIT licence names Yves Chevallier** as the copyright holder, in the root `LICENSE.md` and in the MkDocs plugin's; the notice still carried the name of the project TeXSmith's Markdown extensions were forked from, before the TMark migration removed them.

## [0.7.0] - 2026-09-15

### Added

- **The `ts-*` fragments define the contract macros the writers emit, and redefining one of those macros is how you restyle a construct.** Every `provides` entry of `tmark.fragments()` (`specs/migration/fragment-contracts.md` §1–§3) is now a `\NewDocumentCommand` / `\NewDocumentEnvironment` definition in its fragment's `.sty`, with keyval options parsed by `pgfkeys` under `/ts/<name>/` and unknown keys ignored: `ts-typesetting` (`\tslead`, `\tsmark`, `\tsdivider` = `\clearpage`, `\tsrule` for the same divider inside a container, `\tsepigraph[source={…}]{…}`, `\tsaside[side=left]{…}` with the margin-note font and the `\marginparwidth` clamp, `\tsprogress[thin]{0.45}{label}`, `\tsicon{path}`, `\tslogo{XeLaTeX}` through `hologo`, and the `tsdiv` container with its `tsdiv@multicolumn` / `tsdiv@tab` defaults and a transparent fallback), `ts-callouts` (`tscallout` with `kind`, `title`, `id`, `class`, `collapsed` over today's box styles and the `press.callouts.*` colours and icons; a missing title is the kind's word), `ts-code` (`tscode` with `lang`, `title`, `caption`, `linenums`, `hl_lines`, `id`, `stretch`, `engine`, a verbatim body in whichever engine `code.engine` selects; `\tscodeinline[lang=py]{…}`), `ts-keystrokes` (`\tskeys{Ctrl,Alt,Del}`, over the key-label table of `tmark.registries()`), `ts-todolist` (`tstasklist`, `\tsdone`, `\tstodo`, `\tspartial`), `ts-glossary` (`\tsgls`, `\tsacr`), `ts-index` (`\tsindex[registry=r, main]{…}` and one `\makeindex[name=…]` per registry), `ts-bibliography` (`\parencite` / `\textcite` fallbacks for a document with no `.bib`), `ts-fonts` (`\tsscript{slug}{…}`, `\tsemoji{…}`) and the new `ts-critic` (`\tsins`, `\tsdel`, `\tssubst`, `\tscomment`). `texsmith.core.fragments.resolution.activate_from_requires()` maps a body's `Requires` onto the fragments that must be loaded (the `ts_active_fragments` context key), and `ts-extra` loads `Requires.packages` merged with the packages the active rows imply. `src/texsmith/templates/common/texsmith.typ` is the Typst mirror of the same contract (`#ts-callout`, `#ts-code`, `#ts-keys`, `#ts-rule`, …), which is what a Typst template restyles. This replaces the Jinja partial mechanism entirely: there is no `override`, no `partials` key and no `required_partials` any more — you redefine `\tscallout` (or `#ts-callout`) after `\VAR{extra_packages}` in your template, which is what the bundled `book` template already does for `\tscodeinline`. `docs/guide/templates/partials.md` maps every former partial to the macro that replaced it, and `tests/test_fragment_contracts.py` builds a document exercising every macro with tectonic when one can be provisioned.

- **One MkDocs plugin, `texsmith`, renders the site and exports the PDF.** (migration task 3.9, `specs/migration/web-profile.md`.) `on_config` turns on the Markdown extensions the lowering relies on when they are absent (`attr_list`, `md_in_html`, `admonition`, `pymdownx.details`, `pymdownx.superfences`), ships `assets/texsmith/texsmith.css` (asides, the subfigure grid, caption labels, counter spans) through `extra_css` and reads the site-wide declarations under the plugin's `declare.counters`; `on_nav` pre-passes every page with `tmark.parse` + `tmark.resolve(numbering="all")`, `start` chained in navigation order, and builds the site label map; `on_page_markdown` (priority −50, after `macros`) resolves the page against that map minus its own labels — locations relativised as `other.md#id` — splices its constructs with `tmark.lower_web`, keeps the source for the PDF and reports the diagnostics with the page path (`docs/findings.md:12:5: warning ref-unresolved: …`); `on_page_content` collects the `ts-index` tags and `on_post_build` injects them into the lunr index; `on_post_page` rewrites the snippet URLs; `on_post_build` builds every book from the stored **sources** through the same reader path the CLI uses (`Document.from_markdown`, the passes, one `ResolutionChain` seeded where the site's chain stood before the book's first page, `write`, the fragments, the template wrap and the engines), writing each page's exact input under `<build_dir>/<folder>/sources/`; a page with `press.reader: html` in its front matter goes through `Document.from_html(page.content)` instead. `mkdocs.yml` needs no Markdown extension of its own, and `examples/mkdocs` gains a page exercising every row of the per-construct table (`make -C examples/mkdocs` builds the site and the PDF).

- **Diagnostics have one shape, one line and two switches.** Every finding — a missing image, a counter defined twice, a cross-reference nobody publishes, an engine failure — is now a `Diagnostic` record (`code`, `severity`, `span`, `message`, optional `fix` and `related`), the same record the TMark core emits, collected in a `DiagnosticSink` and printed as `file:line:col: severity code: message` with a 1-based line and a 1-based byte column, exactly the line `tmark check` prints for the same finding. `--strict` (or `press.features.strict: true` in the front matter) exits 1 when any warning or error was recorded, after the LaTeX is written and before the engine runs, so the `.tex` is there to inspect; `--diagnostics-json PATH` dumps the list — sorted by file and position, with the printed location — for editors and CI; `-q` hides hints and info lines; a run that recorded anything ends with `N errors, M warnings`. The Python side is `texsmith.diagnostics` (`Diagnostic`, `Severity`, `Span`, `Fix`, `FileTable`, `LineIndex`, `DiagnosticSink`, `format_diagnostic`), and `DiagnosticEmitter` gains `diagnostic(d)`. See `docs/guide/diagnostics.md`.

- **`--numbering {backend,tmark}`, and the document's language reaches the resolver.** `ResolveOptions.lang` is now the language TeXSmith resolved for babel (`--language`, else the front matter, else English) mapped to its BCP 47 primary subtag — `french` → `fr`, `ngerman`/`german` → `de`, `english` → `en`, `italian` → `it`, a tag such as `fr-CH` passing through as `fr` — and the LaTeX and Typst writers are given the same `lang`, so TMark's label words and TeXSmith's babel / `text(lang:)` settings can no longer disagree. `--numbering tmark` makes TMark allocate the numbers of the predeclared series (`fig`, `tbl`, `lst`, `eq`, `sec`, `part`, `chap`, `app`, `thm`, `note`) at resolve time, continuously across a batch, and both writers then print them inside the cross-references (`\hyperref[tbl:one]{Table~1}` / `#link(<tbl:one>)[Table 1]`), identical in the `.tex` and the `.typ`; `backend`, the default, leaves the numbering to each engine as before. Library callers set `ResolutionChain(numbering=…)` or pass `lang` / `numbering` to `resolve_pass`. See `docs/cli/index.md`.

- **`--deprecated {warning,info,off}`, the transition knob for `--strict`.** TMark reports the legacy spellings it still accepts (root `counters:`, `#{prefix:key}`, `[^key]` citations) as `deprecated` and `deprecated-frontmatter-key` warnings, which would fail `--strict` on every document not yet rewritten by `tmark lint --fix`. `--deprecated info` lowers those two codes to `info` (they still print, `-q` hides them, `--strict` passes), `--deprecated off` drops them; `press.diagnostics.deprecated: info|off` in the front matter sets the same level and the CLI option wins. Every other record is untouched. (`press.features` is a boolean map in TMark's front-matter schema, which is why the three-valued switch lives under `press.diagnostics`.)

- **A caption line can follow its float: `Table: …`, `Figure: …` and `Listing: …` after a table, an image or a code block.** TMark has one caption pattern for every float — the paragraph adjacent to the block, spelled `Kind: text {#id}` — and its canonical position is *after* the block, which is where `tmark fmt` prints it; TeXSmith only read the `Table:` line placed *before* a table, so a document normalised by the formatter lost every table caption and its label, and neither `Figure:` nor `Listing:` meant anything. The attribute list is optional and may be a full one (`{#fig:plot .wide lang=fr}`); on a figure the whole list lands on the `<figure>`. Attachment follows the spec: the line attaches to the float *before* it when that float is of the matching kind and has no caption yet, otherwise to the float after it; a kind mismatch (`Figure:` under a table) or a line with no float next to it stays a plain paragraph for a lint to report rather than being guessed at, and a diagram fence is an image, not a listing. A `Figure:` line renders as the old `/// caption` block did — `figure` environment, the image `alt` as the short caption, `\label` after `\caption` — and a `Listing:` line makes the code block a numbered, referenceable listing: the caption takes the title slot of the `code` box, the way `title=` has always captioned a listing, and the id becomes the box's `label=`, which also fixes a `/// caption` on a code block that used to abort the LaTeX writer with `Figure missing <img> element`. Typst emits `#figure(…, caption: […]) <id>` for all three. See `docs/syntax/captions.md`.

- **`--include-path` gives an include somewhere else to look, for the paths a site wrote against its snippet base path.** `{include}(file)` resolves against the file that writes it, which is the rule the syntax reference gives it and which nothing here changes. The deprecated `--8<-- "file"` spelling does not: `pymdownx.snippets` resolves it against the `base_path` the site configured — `!relative $config_dir`, the directory of `mkdocs.yml`, in this repository — so a page that reads correctly on the web exported `[include: … not found]` to the PDF. Every include, the `include=` option of a fence included, now falls back to a search path when its own directory has no such file: `--include-path PATH` first (repeat it to name several), then the document's own `press.include_paths`, a list written relative to it, then the `pymdownx.snippets` base path the MkDocs plugin finds in the site configuration. A file found that way is the one registered and named in diagnostics; one no directory holds keeps its `include-missing` record and its visible literal.

### Changed

- **A bare `@key` citation renders the short, parenthetical form by default, not the narrative one.** TMark's design had made a bare `@key` the in-text ("Einstein [3] showed…") citation and `@[key, locator]` the parenthetical one, calling it Typst's "one-`@`-for-all model" — but Typst's own `#cite(<key>)` renders the *short* form by default, so the two writers disagreed with the model that was supposed to unify them, and the LaTeX writer followed the wrong reading literally (`\textcite` for every bare key). The default is now the short citation on every backend — `\cite{key}` in LaTeX, `#cite(<key>)` in Typst, the web's one author-year form — and the new `citations.narrative` feature (off; `press.features: {citations.narrative: true}`) is what switches a document's bare citations to the narrative form (`\textcite`, `#cite(<key>, form: "prose")`) instead. Either form stays spellable per citation regardless of the document's default: inside brackets a plain item is short and parenthetical, the new per-item flag `@[+key]` forces the narrative form and `@[-key]` forces the year alone (suppressing the author), so `@[+key, p. 3]` reads "Einstein [3, p. 33]" even in a document whose bare keys are short. The deprecated `[^key]` / `^[k1,k2]` citation sugar lowers to the short form as it always printed, so `tmark lint --fix` is meaning-preserving again — it used to silently turn a short "[3]" citation into the narrative "Wadhwani, McManus, and McMahon [3]" (confirmed in a built PDF), because the fix printed the bare `@key` the writers then read as narrative. The fixer also now inserts a space when a legacy `[^key]` or `^[k1,k2]` hugs the word before it (`tutor.[^key]` fixes to `tutor. @key`, not `tutor.@key`). See `docs/syntax/references.md` and `docs/guide/features/bibliography.md`.

- **TeXSmith parses Markdown with TMark and writes its bodies with the TMark writers.** A `.md` input is no longer read by Python-Markdown and no longer passes through HTML on its way to LaTeX: `tmark.parse` produces the IR, TeXSmith's passes do the work that needs a file, a clock, a process or a socket (`include`, `snippet`, `assets`, `highlight`, `doi`, `emoji`, `scripts`, `var`, `title`, `slots`, `headings`, `glossary`), `tmark.resolve` allocates the numbers and resolves every `@` reference through a `Loader` that reads the `.bib` files and the `refs.json` inventories, and `tmark.write` emits the `.tex` and the `.typ`; the HTML a MkDocs page shows comes from the same writers through `tmark.lower_web`. What TeXSmith keeps is everything that was never the parser's business — templates, fragments, fonts, the engines (Tectonic, latexmk, Docker), bibliography output, diagram conversion, the inventory writer, the CLI and the MkDocs companion — and what it hands over is the dialect: the spellings a document may use are the ones the TMark spec defines, and `Requires` from each body is what decides which fragments the preamble loads. Every bundled example is written in canonical TMark as of this release and all of them build (32 / 32 LaTeX, 26 / 26 Typst, `specs/migration/status.md`), as do the 128 pages of `docs/` in both backends and the documentation site with its PDF export. The rendering itself is now gated by a committed record rather than by a cross-reader diff: `scripts/parity.py baseline --check` re-renders the corpus into `tests/parity/baseline/` and fails on any difference, so a change to the parser, a writer or a pass arrives as a diff a reviewer reads.

- **A CommonMark parser reads some of your bytes differently, and `tmark lint --fix` cannot repair it.** These are not deprecations; in each case the *old* reading was the accident, so the fixer leaves them alone and you have to look at the rendered document. A continuation line with no marker joins the block quote or list item above it (CommonMark's lazy continuation) instead of starting a new paragraph — put a blank line where you meant a break. A nested list item must be indented to its parent's *content column*, three spaces after `1. ` and two after `- `, not an arbitrary four: a sub-list indented by four under a `- ` parent becomes an indented code block, and a continuation paragraph inside a list item needs the content column too. Emphasis never opens inside a word, so `snake_case_name` and `a_b_c` keep their underscores. Raw HTML is delimited by CommonMark's seven block kinds, kept as typed and dropped by the paged writers; a `<div>` whose body must be read as Markdown needs the `markdown` attribute, and `::: div` is the canonical spelling anyway. Named and numeric entities (`&nbsp;`, `&#x2014;`) are decoded to the character they name in every backend. An attribute list attaches to the element immediately before it or to the heading it terminates, and a brace group with nothing to attach to is literal text with an `attributes-no-host` warning — wrap running text in an anonymous span (`[this claim]{#claim:one}`) when you want attributes on it. Finally `@` before a word and `#` before `[` or `(` are sigils now: they are guarded (`@` never fires inside an e-mail address, a URL, a word or code) but where you need the literal character, escape it as `\@` or `\#`. Two deviations from GFM stay deliberate and long-standing: `__text__` is small caps, not a second bold, and `---` on its own line is a divider the paged templates render as a page break. `docs/guide/migration.md` has the whole list and a migration session to run against your own corpus.

- **`^^inserted^^` needs the `inline.insert` feature.** PyMdownX's caret insert was on by default in 0.6; in TMark it is a feature of the document (`press.features: {inline.insert: true}`), and without it the text stays as typed with a hint. Critic markup — `{++added++}`, `{--removed--}`, `{~~old~>new~~}`, `{==highlighted==}` and `{>>a comment<<}` — is typeset again, through the `ts-critic` fragment's macros; see the Fixed entry below.


- **A heading is labelled when something refers to it, not on principle.** The 0.6 path emitted `\label{<slug>}` after every heading, whether or not anything pointed at it; the writer now emits one only for an explicit `{#id}` and for an implicit id that a reference in the document actually targets. The implicit slug itself follows GitHub's rule, so `[text](#a-plain-heading)` and `@a-plain-heading` resolve as they read. What this breaks is a hand-written `\ref{a-plain-heading}` or `\hyperref[…]` inside a raw LaTeX block, which has no Markdown reference for the writer to see: give the heading an explicit `{#id}` — which is the spelling that says "this is a target" — and the label comes back.

- **The IR comes from the `tmark` wheel; TeXSmith no longer mirrors it.** `src/texsmith/ir/` (2 195 lines generated from tmark's schema and compared byte for byte in CI) and `scripts/gen_ir_models.py` are deleted: tmark generates and ships `tmark.ir.{model,codec,walk}`, and a node field added there is no longer a change in two repositories. **Breaking for library callers:** `texsmith.ir` → `tmark.ir`. `Span` moved with it and is now defined once, generated from the schema that states its wire form ("Byte span as [file, start, end]"); `texsmith.diagnostics` imports it instead of declaring it and having the generated models import it back. A TeXSmith of this version needs a `tmark` that ships `python/tmark/ir/`.

- **A template slot's body follows a rebuilt tree instead of being remapped onto it.** `SlotBody` held the block *objects* it selected, so the `highlight` pass — which turns every `CodeBlock` into a `Div` with a `RawBlock` child — had to reconcile the bodies with the new tree by Python object identity (`{id(old): new}`). The fallback was silent: a body that lost identity rendered *un-highlighted* rather than raising. A body holds indices now and derives its blocks, so there is nothing to reconcile.

- **`ts-extra` no longer loads what a fragment already loaded.** Two helpers named `implied_packages` computed the same set — the LaTeX packages a `ts-*` contract loads itself — and were used with opposite sign: one subtracted them from the list, the other added them back three lines later. The preamble therefore carried `\usepackage{graphicx}` and `\usepackage{xcolor}` twice in most documents, and `tcolorbox`, `fvextra`, `epigraph`, `marginnote`, `multicol`, `progressbar`, `enumitem`, `amssymb` and `pifont` in the documents that use them. It worked only because the duplicate was the *bare* load and the fragment's came first; the reverse order is an option clash. The rule is now stated once — `ts-extra` loads what the bodies named, less what an active contract provides — and the rendered `.tex` is 707 lines shorter across the corpus with no change to the built PDFs. The `marginnote` styling block that `ts-extra` emitted goes with them: `ts-typesetting` has emitted the same `\marginfont` and `\marginparwidth` clamp since the migration. **Breaking for fragment authors:** `FragmentPiece.slot` is now `FragmentPiece.variable` (and the `fragment.toml` key with it) — a fragment injects into a template *variable*, while a *slot* is a region a document is assigned to, and two checks that both reported on "Fragments" used the word in the two senses with opposite conditions.

- **`--format typst` honours the options it always accepted.** The Typst entry point built a `ConversionRequest` of its own out of four arguments, so every other field of the request reverted to its default: `--hash-assets`, `--convert-assets`, `--no-copy-assets`, `--manifest`, `--http-user-agent` and `--debug-ir` did nothing, and `--include-path` did worse than nothing — the include failed and its text was dropped, where the LaTeX backend resolved it. It now renders the request it is given. **Breaking for library callers:** `render_typst_document(document, request, *, output_dir=…, emitter=…)` takes the request positionally instead of the `template`, `bibliography_files`, `diagrams_backend` and `template_options` keywords.

- **Every finding carries a code, and an emitter is a presenter.** The free-form `texsmith` code is gone: the twenty messages that carried it — the bibliography loader's six, the DOI and entry failures, the Noto coverage scan, the converters' missing dependencies, the slot a template does not declare, an unreadable source, an invalid base level, a malformed `press.declare.glossary`, an unresolved moustache in template text, a template that would not render, and the common tail of the five fatal conversion paths — now report `bibliography-entry-invalid`, `bibliography-entry-incomplete`, `bibliography-write-failed`, `doi-fetch-failed`, `font-scan-failed`, `engine-config-failed`, `transformer-dependency-missing`, `tool-not-on-path`, `slot-undeclared`, `file-unreadable`, `base-level-invalid`, `frontmatter-invalid`, `var-unresolved`, `template-failed` and `conversion-failed`. `--diagnostics-json` and `--strict` can therefore tell them apart, which is what both were for. Two of those findings were not in the diagnostics system at all and went out through `warnings.warn` — a converter found outside `PATH`, and a missing converter dependency — so they were invisible to `--diagnostics-json` and fatal under `PYTHONWARNINGS=error`; the first is now an `info` record, which `--strict` ignores and `-q` hides. **Breaking for library callers:** `texsmith.core.diagnostics` moved to `texsmith.diagnostics` (one import path for the whole system, and the package no longer depends on `texsmith.core`); `DiagnosticEmitter.warning()` and `.error()` are removed, and `emit_diagnostic(emitter, code, message, span=…, exc=…)` replaces them; a custom emitter now subclasses `SinkEmitter` and implements `render(diagnostic, cause)` and `event(name, payload)` — collecting, deduplication and file numbering belong to the `DiagnosticSink` it owns. `raise_conversion_error` moved to `texsmith.core.exceptions`.

- **One file table per run, so a span names the file it belongs to.** A `Diagnostic`'s `span.file` indexes the run's `FileTable`, and that table used to be whatever `getattr(emitter, "files", None)` returned: `NullEmitter`, the default for library callers, had none, so every document of a batch numbered itself 0 and two findings with the same message in two different files deduplicated against each other. Every emitter now owns one (`NullEmitter` collects and shows nothing, rather than discarding), and three consequences follow. A diagnostic raised inside a `snippet` fence used to render as the **host page's** path at the fence's line number — a location that exists and is wrong — because the nested document parsed against a table of its own; the fence now registers as a source of the run, like an include. The MkDocs plugin built three file tables (one per page, plus a second emitter per page to render against it) and now builds one for the site, so its pages are numbered in the order they are met and its long-lived emitter sees the page records it never used to. And a batch numbered under one emitter is numbered identically under any other.

- **Counter and cross-reference defects are diagnostics, not Python warnings.** `Counter 'n:x' is defined more than once`, `Counter reference '@n:x' has no matching item` and the cross-reference inventory messages (missing, unreadable, stale, key not published) used to go through `warnings.warn`; they now go through the active diagnostic emitter under TMark's codes (`label-duplicate`, `ref-unresolved`, `crossref-inventory-missing`, `crossref-inventory-stale`) and print as `doc.md: warning ref-unresolved: …`. The messages are unchanged. Consequently `PYTHONWARNINGS=error` **no longer promotes them to failures**: use `--strict` (or `press.features.strict`) instead, which also covers every other warning TeXSmith records. Library callers that passed no emitter and relied on the warnings reaching stderr should pass a `LoggingEmitter` (or their own) to the conversion request.

- **Messages from `DiagnosticEmitter.warning()` / `error()` print with a code.** The CLI shows `warning texsmith: …` / `error texsmith: …` where it showed `warning: …` / `error: …`, and the `LoggingEmitter` logs the same line; the `-v` exception details follow, indented.

- **The TMark dependency is `tmark-core` on PyPI; the import stays `tmark`.** The wheel TeXSmith depends on had no name of its own there — `tmark` on PyPI is an unrelated project — so it publishes as `tmark-core`, matching the crate's own `[project] name` (`vendor/tmark/crates/tmark-py/pyproject.toml`); nothing in TeXSmith's code changes, since every import is still `import tmark`. `pyproject.toml` names the dependency `tmark-core`, and `[tool.uv.sources]` still builds it editable from `vendor/tmark/crates/tmark-py`, at the crate's first tagged version, `0.1.0`, ahead of its first publish to PyPI.

### Deprecated

- **The spellings TeXSmith 0.6 taught are still accepted, but most of them are deprecated sugar, and one command rewrites them.** `tmark lint FILE` reports each one with its replacement and `tmark lint --fix FILE` rewrites the file in place (`--diff` previews it, `--stdout` writes to a pipe), covering every mechanical case: `#{prefix:key}` → `{counter}(prefix:key)`, `[^key]` / `^[k1,k2]` citations → `@key` / `@[k1; k2]`, `{latex}[…]` → `{raw latex}(…)`, `/// latex … ///` → a ```` ```latex raw ```` fence, `/// caption … ///` → a `Figure:` / `Table:` / `Listing:` line after the float (its id read from the indented `attrs:` line), `{margin}[…]{l|r}` → `{aside side=…}[…]`, `--8<-- "f"` → `{include}(f)` (or `include="f"` on a fence), `{index:r}[…]` → `{index registry=r}[…]`, `{index}[…]{b}` → `{index main=true}[…]`, `[](gls:t)` → `@gls:t`, `[](){#id}` → `[]{#id}`, `{: .x}` → `{.x}`, and the top-level `counters:` / `bibliography:` / `glossary:` / `crossrefs:` / `acronyms:` / `admonitions:` groups → `press.declare.*` / `press.sources.*` / `press.callouts.*`. Those rows have a horizon: they go once `tmark fmt` has been shipping long enough to have rewritten the corpus. The rows whose horizon is *indefinite* are the ones MkDocs Material or Pandoc renders natively and that the dialect therefore promises to keep, deprecation notice or not: `!!! note` / `??? note` callouts, `=== "Tab"` content tabs, `<div markdown>`, a bare ```` ```mermaid ```` fence, a `Table:` line placed *before* its table, `[@key, p. 3]` and `@https://doi.org/…`. Distinct from those, and not deprecated at all, is the sugar that is simply part of the dialect — `~~del~~`, `==mark==`, `^sup^` / `~sub~`, `++Ctrl+C++`, `__smallcaps__`, `:smile:` — which parses without a word of complaint; `tmark fmt` normalises some of it, so a file using it is accepted by `tmark check --strict` without being a fixed point of `tmark fmt --check`. What the fixer will not spell for you, because there is a choice to make: `=== "Tab"` becomes `:::: tabs` / `::: tab {title=…}`, `^^x^^` becomes `{underline}[x]` unless you enable the `inline.insert` feature, a `:::` callout of a non-standard type wants a `press.declare.admonitions.<type>` entry (the `!!! type` sugar accepted anything), and `[](#id)` becomes `@id`. `tmark check --strict FILE` reports what is left. The full table, with a horizon per row, is `docs/guide/migration.md`.

- **The `texsmith.counters` and `texsmith.index` MkDocs plugins do nothing.** Both jobs — numbering every counter site-wide and feeding the index entries to the search index — belong to the single `texsmith` plugin now. The two entry points still load so an existing `mkdocs.yml` keeps building, but each logs a warning naming its replacement and nothing else; they are removed in 0.8. Drop them from `plugins:` and move any `counters:` declared under `texsmith.counters` to `declare.counters` of the `texsmith` plugin. The `texsmith.index` *Markdown extension* is unaffected.

### Removed

- **The Python-Markdown pipeline is gone: TeXSmith parses with TMark and writes with tmark, and nothing else.** What went: the 17 bundled Markdown extensions and the `markdown.extensions` entry points that exposed them (`texsmith.index`, `texsmith.texlogos`, `texsmith.smallcaps`, `texsmith.latex_raw`, `texsmith.latex_text`, `texsmith.missing_footnotes`, `texsmith.multi_citations`, `texsmith.references`, `texsmith.counters`, `texsmith.mermaid`, `texsmith.quotes`) — an `mkdocs.yml` that lists any of them under `markdown_extensions:` must drop the entry, and a site that relied on one for its *own* rendering should reach for the `texsmith` plugin's web lowering instead; the `--reader` option, with `--html` and `--debug-html` (a Markdown input has no intermediate HTML any more — `--debug-ir` writes the parsed IR as `<stem>.ir.json`, which is what the passes and `tmark.write` actually see); and `--list-extensions`, `--enable-extension` / `-x`, `--disable-extension` / `-X` and the `[latex.template] markdown_extensions` key. **`.html` input went with it**, after this entry was first written: the bs4 `HtmlReader`, `Document.from_html`, `InputKind`, `--selector`, `--full-document`, `--parser` and the MkDocs `press.reader: html` branch are all gone (a source is Markdown, and `tmark.parse` reads it). MkDocs Material is migrating to Zensical and the next MkDocs drops plugins and extensions, so Zensical support will be designed against what Zensical emits rather than repaired against what Material emitted. `extensions/tables/schema.py` (the validated table model) and `extensions/texlogos/specs.py` (the logo catalogue) survive as data modules. On the Python side the two writers (`texsmith.writers.latex.LaTeXWriter`, `texsmith.writers.typst.TypstWriter`), the `@writes` registry, the hand-written IR (`texsmith.ir.nodes`, `texsmith.ir.visitor` — `texsmith.ir.model`, generated from TMark's schema, is the tree now), `LaTeXRenderer`, `LaTeXFormatter` and the legacy HTML reader are deleted, and with them `examples/custom-render`, which demonstrated `@reads` / `@writes`. The 45 files of `adapters/latex/partials/` go with them, and so do the four manifest hooks the contract macros replaced, which are no longer read at all: `latex.template.override` (and a template's `overrides/` directory), the template and fragment `required_partials`, a fragment's `partials`, and the template-scoped `readers` / `writer` of 0.4.1 — a package that still declares one converts as if it did not; redefine the construct's `ts*` macro after `\VAR{extra_packages}` instead (`docs/guide/templates/partials.md` maps every former partial to its macro). Numbering and resolution are TMark's, so `texsmith.core.counters` and the reading half of `texsmith.core.crossrefs` (`CrossRefResolver`, `load_inventory`, `parse_front_matter_crossrefs`, `render_reference`) are gone, while the inventory *writer* stays. Dependencies: `markdown`, `pymdown-extensions` and `python-markdown-math` are no longer required.

### Fixed

- **A `.snippet` preview resolves the bibliography its own front matter declares.** `docs/guide/features/bibliography.md` shows a three-line document that names an entry by DOI and cites it; built on its own it emits `\cite{WADHWANI20111713}` and a `texsmith-bibliography.bib`, but the preview of that very source printed `[?WADHWANI20111713]` on page 49 of the shipped manual — the documentation illustrating the feature was the one page where the feature did not work. A fence's YAML is snippet *configuration*, so the compiler splits it off and hands tmark the body alone, forwarding the one key that describes the document rather than the preview — `bibliography` — as a mapping set aside on `Document`. That mapping is the legacy front matter, and the `doi` pass reads the *typed* front matter tmark parsed: it found no `press.sources.bibliography`, fetched nothing, wrote no `inline-doi-<stem>.bib`, and `resolve` was handed a document with no `.bib` at all. (The deprecated inline-bibliography loader did fetch the DOI, which is why a `texsmith-doi-cache.yaml` appeared in the nested build directory beside a citation that had not resolved — the entry reached a collection the IR path no longer consults.) The forwarded keys are written back as a real front-matter block ahead of the body, so tmark parses them and applies the same migration it applies to a standalone document; `press.sources.bibliography` is taken beside the deprecated top-level `bibliography`, which the fence dropped outright. The keys join the preview's digest, so a snippet cached before they travelled is rebuilt rather than served.

- **Critic markup is typeset again.** `{++added++}`, `{--removed--}`, `{~~old~>new~~}`, `{==highlighted==}` and `{>>a comment<<}` went through `pymdownx.critic` and a set of Jinja partials in 0.6; the TMark parser did not lower them, so a reviewer's annotations reached the PDF as literal braces. The five spellings are constructs of the language now (tmark challenge C49): an annotation lowers to the node the compatibility appendix names, wrapped in a span whose single class is `critic` so that a writer can tell a reviewer's mark from an author's `{underline}[…]` or comment, and the `ts-critic` fragment's `\tsins`, `\tsdel`, `\tssubst` and `\tscomment` typeset them — which is what the fragment was written for. Nothing fires inside a code span, a fence, math or a link destination, where PyMdownX did.

- **A Typst document keeps its title, subtitle, authors, date and salutation.** Everything in the Typst scaffolding hangs off `{% if title %}`, and on the IR path `extracted_title` was `None`: `#set document(title: "")`, no title block, no author block, no date, and in the `letter` template no `Dear Maestro Leonardo,` at all. The LaTeX path promotes the leading top-level heading in `prepare_for_conversion` and the legacy Typst path did it again in `_render_templated`, but the IR entry point takes the document straight from `prepare_documents`, before either runs — by which time the `title` pass had already removed the heading from the body. `Document.promoted_title()` now states the decision once (`PROMOTE_METADATA`, not suppressed by `--no-title`, the heading unique at its level — exactly when the `title` pass drops it) and the templated IR branch asks for it; the context also carries the resolved `language`. A standalone document still keeps the heading in its body. This was the single largest defect the parity gate found: 78 of the 84 differing Typst entries.

- **A glossary declared in the front matter reaches the document again.** `press.declare.glossary` is a *flat* `term → definition` mapping to TMark, so TeXSmith's structured section turned `style`, `groups` and `entries` into three glossary terms (`\newacronym{style}{style}{long}`) and declared none of the acronyms underneath, while the writer's occurrence substitution reads `Document.abbreviations` and `declare.acronyms` only and therefore saw nothing to replace — a `REST API` written in prose stayed a plain word and six of the seven entries of `examples/glossary` vanished from the printed list. A `glossary` pass now appends one `AbbrDef` per entry (the IR twin of the synthetic `*[KEY]: …` lines the 0.6 path wrote) and leaves `declare.glossary` holding only the flat terms it did not consume, skipping a term that a cased variant already declares — TMark case-folds `Resolved.glossary` while `\tsacr` keeps the acronym's spelling, so an acronym both declared and used was otherwise printed twice. The canonical `press.declare.glossary` spelling is read where the deprecated top-level `glossary:` was, the `glossary_style` alias and the groups included.

- **Inline markup survives in a table header cell, and a link in one is not destroyed.** A header cell is a cell, but the pipe-table lowering kept only its plain text, so a header row holding an inline code span, a bold run and a link produced `\textbf{Key tlmgr name} & \textbf{Bold head} & \textbf{Link}` — the code span flattened, the emphasis flattened and the hyperlink destroyed, with no diagnostic to say so. A column now carries a parsed `title` alongside its plain `name`, set only when the header holds markup a string cannot hold, so the IR of an ordinary table is unchanged and `name` stays what named-row mode keys on and what a diagnostic calls the column; the writers and `tmark fmt` render `title` when it is there. The IR walk descends into those titles too, so a pass that rewrites inlines sees them. Seen on this project's own release notes, `docs/syntax/supported` and `docs/guide/fonts`.

- **The images of a `::: figure` are lettered subfigures and stop consuming figure numbers.** The specification promises `Figure 1` with `(a)` and `(b)`, and `@fig:crash` reading *figure 1b*, but never said that a subfigure takes no number of the `fig` series — so under whole-site numbering a page holding a plain figure and a `::: figure` of two labelled images numbered them 1, 2, 3 and 4 instead of 1 and 2a, 2b, and the resolution's `next_start` inflated a site's figure count by one per image. The collector now maps a container's images before walking it and marks them as subfigures of the container's label, the allocator skips them and the formatted reference composes the container's number with the letter, so one container is one figure everywhere. A lone image *is* the figure and shares its number with no letter; a container that is not a grid of image paragraphs stays a plain float; an unlabelled container numbers nothing. LaTeX always emits the subfigure `\caption` so `subcaption` prints the marker and `\ref` reads `2a`, and the bundled Typst prelude gains `ts-subfigure` and `ts-subnumber` so the subfigures leave the Typst figure counter alone.

- **Every document of a batch keeps the fragments it asked for.** `apply_requires` replaced `DocumentState.required_fragments` — and the required packages, and the index registries — with the current document's, so in a batch (the CLI in input order, a MkDocs book in navigation order: one state threaded through every document and one template wrap at the end) a contract the *first* page named was gone by the time the template was wrapped, and a `\tslead` on page one compiled against a preamble that never loaded `ts-typesetting`. The record is a union now, and an acronym an earlier document wrote is no longer dropped when a later one defines it without using it. The template wrapper had the mirror-image fault: it took the fragment set from the caller and never looked at what the bodies required, which is invisible while the caller passes nothing (the manifest lists every contract fragment and each gates itself) and fatal the moment one passes an explicit list — the snippet compiler always does, so a nested preview lost every contract its own body needed and `docs/syntax/progressbar` emitted `\tsprogress{0.25}{Research}` with no `\usepackage{ts-typesetting}`. The set is the caller's list unioned with what the bodies named.

- **The cross-reference inventory publishes its anchors again.** `publish_inventory` took them from the Python counter registry, which the IR path never filled, so every `<document>.refs.json` written since the reader flip was empty and every sister document citing into it reported a key the inventory does not publish. The anchors now come from the resolution — `anchors_from_resolved` reads the `counter_item` labels TMark allocated, with their formatted numbers — and the conversion hands the resolution back to the document the service holds, so a batch publishes the anchors of all of its documents, not just the last one.

- **LuaTeX finds a writable font cache, and `ts-fonts` closes its conditionals.** Two faults the bundled Tectonic never reached and a system `lualatex` always did. `build_tex_env` pointed `TEXMFCACHE` at a directory outside the distribution's trees, where `luaotfload`'s writable-path lookup comes up empty and LuaTeX dies before loading a single font; `TEXMFVAR` already puts the cache under the same root, so the override is dropped. And in `ts-fonts` the line before a whitespace-stripping `\endif` ended with a comment character, which swallowed the three `\fi` that close the engine branches.

- **`\tsacr` typesets the short form, always.** The macro was defined as `glossaries`' `\gls`, which expands an acronym on its first use, so a document acquired `Nuclear Magnetic Resonance (NMR)` in a sentence the author had written as `NMR`. The author never writes the call — the writer substitutes every strict, case-sensitive match of a declared key — so a first-use expansion rewrites prose nobody typed and makes the printed document say something different from the web profile, where the key stays inside `<abbr>`; the Typst contract already rendered the short form, so the two backends disagreed as well. `ts-glossary` now defines `\tsacr` as `\acrshort` (decision O5, `specs/migration/parity-triage.md` §5). `\tsgls` keeps `\gls`: a glossary *term* reference is written by the author, and there the `glossaries` convention applies.

- **A `---` inside a container separates instead of tearing the container in two.** `---` had one contract in every position — `\tsdivider` = `\clearpage`, `#ts-divider()` = `#pagebreak(weak: true)` — which inside a block quote or a callout is a page break inside a box; Typst refuses it outright (*pagebreaks are not allowed inside of containers*), so `examples/markdown/features.md`, which has a `---` in a block quote, could not be built as a Typst document at all. The writers now choose by their own nesting: `\tsdivider` at the top level, and `\tsrule[width, thickness, above, below]` / `#ts-rule()` — a full-width rule with a skip on each side, its keys under the `/ts/rule/` family like its neighbours — anywhere inside a container.

- **A snippet preview builds instead of falling back to its source.** Three faults in a row, each of which made a `.snippet` fence print the fence's text as a code block rather than the rendered figure it promises. A nested build called `Document.from_markdown` without naming a reader while that default was still the legacy one, so a source written in canonical TMark came back as literal text and the book example's `latex raw` fences killed the nested build on a runaway argument; then the reader parameter was removed with the legacy path and the call raised `TypeError: from_markdown() got an unexpected keyword argument 'reader'`; and the fragment set the preview was wrapped with came from its host rather than from its own body. All three are fixed, and the committed baseline of `docs/syntax/progressbar` matches byte for byte in both backends.

- **The Typst bibliography carries the entries the DOI pass fetched, and the Typst IR path runs the passes' values.** The `.bib` the Typst scaffolding cites is now built the way the LaTeX path builds it: the CLI and front-matter entries plus every file the `doi` pass wrote (`inline-doi-<stem>.bib`), written label-safe as `<stem>-refs.bib` — so a `@doi:` citation whose key the pass rewrote to the fetched entry no longer fails `typst compile` with *citation key … is not present*. The same path now applies the pass values (script usage, the fallback summary, the emoji mode) to the `DocumentState` and the template context, and threads `--diagrams-backend` into the `assets` pass, which it had never reached.

- **Typst display equations are numbered again.** The scaffolding gates `#set math.equation(numbering: "(1)")` on `uses_eqnref`, which the IR path set to a literal `False`, so `examples/math` produced a document whose equations had no numbers and whose references to them pointed at nothing. The Typst writer already says it — it names the `ts-equations` fragment when it emits an equation label or a reference to one — so the flag is now that fragment appearing in the union of the bodies' `Requires`.

- **A themed image reaches the Typst output.** `_build_image_map` resolved `assets/ts-light.svg#only-light` as a file name, found nothing and mapped it to the empty string, which the writer reads as *drop this image* — so a light/dark pair lost both halves and the documentation's own logo was missing from the PDF. The Typst map strips the theme fragment before resolving, keyed by the original `src`, as the LaTeX path has always done.

- **The bundled Typst prelude and templates pin `mitex` 0.2.7.** 0.2.6 rejects a `\imath` and an `aligned` block that the `math` and `markdown` examples carry; 0.2.7 compiles both. The pin lives in three places — the body prelude and the two bundled Typst templates — and all three moved together.

- **A bold lead-in is a paragraph that is one bold span, and nothing else.** The `paragraph.lead` sugar fired on any `Strong` that merely *opened* a paragraph or a list item and skipped a paragraph that *is* a `Strong` — the exact opposite of what the contract typesets. `\tslead` is `\par\noindent…\par\nobreak\smallskip`, so firing it on `**Leading bold:** followed by text` moved the rest of the sentence into a paragraph of its own, while the standalone bold label the macro was written for stayed a plain `\textbf`. The role and the sugar are now two rules: `{lead}[…]` at the start of a paragraph is a lead-in whatever follows, and the sugar promotes a paragraph whose whole content is one strong span under 80 characters, outside a list item. Eleven or more corpus entries, in both backends.

- **`[](){#id}` is an anchor, not an empty link.** The MkDocs/autorefs anchor idiom lowered to a link with an empty destination followed by a homeless attribute list — `\url{}\{\#id\}` in LaTeX, `#link("")[\#id]` in Typst — with no `\label` emitted and every `\hyperref[id]` to it dangling. An empty link is no link: the pair now lowers to the same zero-width span `[]{#id}` produces (`\phantomsection\label{id}` / `#metadata(none) <id>`) and reports a `deprecated` record carrying `[]{#id}` as its fix, so `tmark lint --fix` rewrites it.

- **Smart symbols and straight quotes are typeset.** `(c)`, `(tm)`, `(r)`, `-->` and `1/2` reached the output as typed and a straight double-quoted phrase never became `\enquote{…}`. Both are read in the scan of a decoded text run that already expands emoji shortcodes, so a code span, a raw span, a link destination and an attribute value are untouched and a backslash declines the spelling; the symbol table is `pymdownx.smartsymbols`' with its own boundaries (an arrow is not part of a longer dash run, a fraction not part of a longer number, `c/o` a whole word). Deliberately not applied: ordinal numbers, single quotes (an apostrophe is not a quote), and `--` and `...`, which both backends typeset as written. A quote pair straddling inline markup stays literal.

- **A `---8<---` include is expanded, and its `;` escape is honoured.** `pymdownx.snippets` writes its marker with two *or more* dashes on each side, the two sides free to differ, but only the exact `--8<--` spelling was recognised — and every occurrence in this project's corpus uses three, so nineteen include lines reached the document as literal text instead of including anything. The `;` prefix that disables a marker is understood too, at both ends: the printer escapes a literal marker with a backslash in a paragraph and with the `;` in a fence body, where no backslash escape exists, and both stay fixed points of `tmark fmt`.

- **A cross-reference names its counter in the document's language.** The writers printed `Table~1`, `Section 2` and `Figure 3` in English wherever they rendered a counter's reference template, however the document or the caller had set `lang`. The word now comes from the registry for the effective language — the writer option, else the resolution's, else the front matter's, else English — and reaches the LaTeX `\hyperref`, the Typst `#link` / `#ref`, sibling and book labels, the web lowering's link text and the HTML caption labels. LaTeX's own `\caption` numbering stays babel's business, which is why a French reference (`Table 1`) agrees with the caption babel prints. A `name` declared under `declare.counters` survives, on a predeclared prefix too.

- **A counter marker at the head of a table cell no longer pushes its text down a line.** The LaTeX rendering of `#(ns:key)` emitted `\phantomsection\label{…}` before the counter text; at the start of a `p{}` cell TeX is still in vertical mode, and hyperref's raised link then opened an empty paragraph, so the row's first cell (`D-01`) sat one line below its neighbours. It now starts with `\leavevmode`, a no-op inside a paragraph and the right thing at the head of a cell.

- **A superscript typed as a Unicode character is a superscript, not a script run.** The `scripts` pass treats a Unicode block that is a writing system as needing a font switch; it was also treating *Superscripts and Subscripts* as one, so `s⁻¹` came out as `s\tsscript{superscriptsandsubscripts}{\textsuperscript{-}}\textsuperscript{1}` — the wrong macro, a fallback entry naming the document's own serif face, and the run split between the sign and the digit. The block joins `latin`, `common`, `punctuation` and `other` among the groups the pass skips.

- **`tscode` with `engine=pygments` boxes the payload the pass produced.** Under `code.engine=pygments` the `highlight` pass pre-renders the block, so the body of `\begin{tscode}[…, engine=pygments]` is already a `Verbatim` environment of `\PY` macros with its line numbers and highlighted lines; the environment is a plain `tcolorbox` around ordinary LaTeX in that case (title, caption, id and class as box options, `stretch` through `\baselinestretch`), and the `VerbatimOut` capture stays for a raw body, launched past the `\fi` so `\futurelet` peeks the real token.

- **A Typst comment, heading or list marker no longer eats prose it should not, and `~` prints a space.** TMark's Typst writer escaped only the characters that are special *anywhere* (`` \ # $ * _ ` < > @ [ ] ``); it never escaped `//` or `/*`, which open a line or block comment and silently swallow the rest of a `Str` node's text, nor `=`, `+`, `-` and `/` at the start of a line, which read as a heading marker or a list item inside anything the writer emits as fresh markup — a footnote, a link's visible text, the start of a paragraph — the same way `= x` does at a document's own top level. `~` is always a non-breaking space in Typst markup and was passed through literally. All four are now escaped: the first slash of a comment opener, `=` unconditionally at a line start (a heading marker is a run, so escaping one already breaks it), `+`/`-`/`/` at a line start only when followed by a space (so a leading `-5` or `a--b` stay untouched), and `~` unconditionally, like LaTeX's `\textasciitilde{}`.

- **`++Ctrl+C++` no longer swallows the prose between two unrelated `++` runs.** The keystroke sugar matched any two `++` delimiters with something in between, so "`C++03` was superseded by `C++`" — two independent uses of `++`, not a keystroke — typeset everything between the first and the last `++` as one keystroke body. A keystroke body must now be non-whitespace throughout; a run that contains a space between its would-be delimiters is prose on both sides of an ordinary `++`, not a keystroke.

- **A closing smart quote before an em dash no longer pairs with the wrong quote.** Only ASCII punctuation was recognised as valid context after a closing quote, so `"quotation"—and` treated the dash as disqualifying and kept scanning for a partner, closing the pair at the *next* `"` in the document instead of the one right there — turning a short quotation into everything up to and including an unrelated one further down. An em or en dash is punctuation like any other for this rule now, and the pair closes where it visibly does.

- **A heading id built from non-Latin or symbol text no longer produces a broken Typst label.** Typst reads a label as a run of `XID_Continue` characters plus `_`, `-`, `:` and `.`; every other character silently became invalid label syntax, so an id containing kanji, Cyrillic, or a character such as `/` or `+` could fail to compile, or — worse — collide with an unrelated id that lost the same characters (`日本語 見出し` and `日本語 本文` both losing their space). Such a character is now replaced with `-`, and a lossy replacement appends a short hash of the id's original bytes as a suffix, so two ids that only differ in the characters Typst cannot host never collide; an accented or non-Latin id with nothing to replace is used as written.

- **A reference to an anchor with no number reports `ref-unnumbered` instead of printing `?`.** `[]{#id}` and similar zero-width anchors carry no counter value, so a `@id` pointing at one has nothing to format; previously the writers rendered a bare `?` with no explanation. Such a reference is now a diagnostic (`ref-unnumbered`) naming the anchor, and the writers fall back to the anchor's title when it has one, its bare id otherwise — visible and traceable instead of a silent placeholder in the printed document.

- **Twelve `warnings.warn` calls that never reached `--strict` or `--diagnostics-json` now do.** A font family that could not be downloaded, a CTAN package fetch that failed, a fragment's `should_render()` predicate raising, two acronyms declared with two different definitions — all printed through Python's warning system, invisible to both diagnostics switches and fatal outright under `PYTHONWARNINGS=error` rather than a printed line. Every `warnings.warn` call site in the codebase (24 of them) was read and decided on its own terms: the twelve whose call site a run's emitter can actually reach now call `emit_diagnostic` under a new code — `font-fallback` for the font pipeline's eight sites plus the CTAN download `FontsFragment` wraps, `fragment-manifest` for a `should_render()` that raised (the fragment renders anyway, fail-open, with the exception attached to the finding), `metadata-invalid` for `DocumentState.remember_abbreviation` catching an inconsistent acronym definition. Eleven more, built before any `Document` or emitter exists — front-matter metadata normalisation, the date and `git describe` helpers behind it, three warnings raised while the fragment registry singleton is still loading its entry points — move to their own module's `logging.getLogger(__name__).warning(...)`, which at least survives `PYTHONWARNINGS=error`; one, a template-package author re-registering an attribute normaliser without `override=True`, is an import-time notice for library extenders rather than a document finding, and keeps its plain `UserWarning`.

- **A diagnostic's path prints the same way on every OS.** `TexsmithLoader.join`/`join_dir` build an OS-native string on purpose — forcing it to posix previously broke every on-disk lookup keyed by a real `str(Path(...))` on Windows — so the diagnostic that later displayed that same string verbatim showed backslashes on Windows and forward slashes everywhere else, and the MkDocs plugin's own page table, keyed by the OS-native `src_path` rather than MkDocs's already-posix `src_uri`, disagreed with the links MkDocs itself renders. `FileTable.add` now takes a `PurePath`, so a caller doing display work can register a `PurePosixPath` once the real file has already been found on disk; the MkDocs plugin's site pre-pass does exactly that with `src_uri`, and the loader itself is untouched — `join`/`join_dir` stay OS-native, which is what a real file-system lookup needs. A diagnostic's `file:line:col` is posix-spelled on Linux, macOS and Windows alike.

## [0.6.0] - 2026-09-02

### Added

- **A draw.io diagram can be exported at its page size, through `crop=false` on the image.** The Playwright exporter — the default backend — always shrink-wrapped the SVG to the cells it found, so everything the author had laid out *around* the drawing was thrown away: the sheet's margins, a frame, a title block, the relative placement of several drawings on one page. What reached the document was the bounding box of the ink, not the canvas, and no option existed to say otherwise. `![Site plan](plan.drawio){crop=false}` now exports the page(s) the drawing spans instead, at the `pageWidth` / `pageHeight` declared in the file — draw.io's own *Size: Page Size* — by asking export3 for an `exportType` of `page` and cropping `getSvg` to the background page bounds rather than to the graph bounds. The flag is document-agnostic: the local CLI and the Docker backends read the same option (they map it onto `--crop`), so the three backends finally agree on what an export contains, where until now the CLI ones silently kept the page and Playwright silently dropped it. Cropping stays the default — a figure embedded in prose wants the drawing, not the whitespace — and `press.drawio_crop: false` in the front matter (or `-a press.drawio_crop=false`) flips it for a whole document, an image attribute still winning over it. The same diagram may appear both ways in one document: the render options take part in the asset key, so the cropped and the full-page exports are stored as two distinct assets rather than the first one silently serving both. See `docs/syntax/images.md`.

- **Inline code can wrap again, through a `code.inline` front-matter section.** A fenced block has always folded inside its box — every engine is configured with `breaklines`, and `fvextra` with `breakanywhere` on top — but an inline span sits in a justified paragraph where TeX will not break it on its own. The only break opportunity TeXSmith inserted was after a hyphen, a vestige of the days when inline code was plain `\texttt`, so a long dotted identifier such as `texsmith.core.conversion_options` ran straight past the right margin, and the Pygments highlighting introduced since then had removed even that: a highlighted span is a chain of `\PY{token}{payload}` macros with no discretionary anywhere. `code.inline.breaks` now declares the characters after which an `\allowbreak` is inserted — `"_./"` for the usual identifier separators, `all` for the full punctuation set `-_./\:;,|@+=&#%`, `none` to opt out, and the historical `-` when nothing is declared, so existing documents are untouched. Letters and digits are ignored: breaking mid-word costs more legibility than the overflow it saves. Highlighted spans get the same treatment without losing their colours — the insertion runs *between* the Pygments macros, the token names being isolated from their payload, and it matches the escaped form of each character (`\PYZus{}` for an underscore) rather than the raw one. `code.inline.plain` complements it with the "simple mono" mode: inline spans are typeset as plain `\texttt{…}` whatever the engine, blocks keeping their highlighting. That is the only way to break an inline span under `minted`, whose `\mintinline` is verbatim and cannot host an `\allowbreak`, and a document whose only code is inline then stops requesting the shell escape that `\mintinline` would have forced. Both keys are available as CLI overrides (`-a code.inline.plain=true -a code.inline.breaks=_./`). See `docs/guide/features/listings.md`.
- **Cross-document references, so a number allocated in one document can be cited in another.** A counter value only exists inside the conversion that allocated it: a sister document citing `FW-10` had no way to know what `FW-10` was, and no way to notice when a renumbering turned it into `FW-12` — the hard-coded number simply became wrong, silently, which is precisely the maintenance burden counters remove *inside* a document. Every conversion now publishes a `<document>.refs.json` **inventory** next to its output, the way DocBook's target database and Sphinx's `objects.inv` do, and a citing document declares what it depends on under `crossrefs:`. The inventory is written in two passes because the two halves of a reference become known at different times: keys and formatted labels while converting, page numbers only once LaTeX has run — harvested from the `.aux`, the same source the `xr` package reads. A document may declare a free `id` (a contract or report number such as `RHE-423`; `document-id` is accepted as an alias); a citation then concatenates it with the item's label, so `@fwrev:fw:pas-de-temps` renders as `RHE-423-FW-10 p. 14`, falling back to naming the document by its title when no id is declared, and to the bare label when it has neither. Resolution is explicit — an alias never falls back to a local counter and a local counter is never shadowed by an external one — and an external citation renders as **text** rather than a `\hyperref` that would point into a different PDF and resolve to nothing. What makes the feature worth its weight is the diagnostics: a key the inventory does not publish, a missing inventory, and an inventory whose source has changed since it was written all raise a visible warning, and an unresolved citation renders as `[?fwrev:fw:disparu]` rather than disappearing — a silently dropped reference is how a contractual document ships a hole. Set `PYTHONWARNINGS=error` to turn any of them into a build failure. Two documents citing each other need two passes, exactly like LaTeX's own `.aux`: a missing inventory warns rather than fails, so the first build publishes the inventories and the second resolves the citations. See `docs/syntax/crossrefs.md`.
- **Custom counters for document-specific numbered series.** Technical documents number things LaTeX knows nothing about — findings, requirements, bugs, risks, test cases — and until now the only way to get `FW-23` into a PDF was to type it and maintain it by hand, with a `\label` bolted on through raw LaTeX. A `counters:` section in the YAML front matter now declares such a series (`name`, a Python `format` string such as `"FW-{n:02d}"`, an optional `start`); the body defines an item with `#{fw:watchdog}`, which prints the formatted number and becomes the anchor, or silently with an ordinary `{#fw:watchdog}` attribute list on a heading or a figure; and the existing `@fw:watchdog` cross-reference shorthand resolves to the same number as a hyperlink. Numbers are allocated by TeXSmith in document order rather than by the backend, so the LaTeX and the Typst builds print identical values, and the documents of a multi-file build continue one series instead of restarting. A companion MkDocs plugin (`plugins: - texsmith.counters:`) brings the same numbers to a documentation site, where TeXSmith's front-matter parsing never runs: it enables the counter and cross-reference extensions on its own, accepts site-wide declarations in `mkdocs.yml` as well as per-page ones in the front matter, shares every declaration across every page, and numbers the whole site in navigation order through a pre-pass — so a reference on the first page resolves to an item defined on the last one, and a cross-page reference is rewritten to point at the page that defines it. LaTeX emits `\phantomsection\label{fw:watchdog}FW-01` at the definition — the `\phantomsection` is what keeps the `hyperref` anchor on the item rather than on the enclosing section, and it makes `\pageref` work — and `\hyperref[fw:watchdog]{FW-01}` at the reference; Typst emits `FW-01<fw:watchdog>` and `#link(<fw:watchdog>)[FW-01]`. A marker whose prefix is not declared is left strictly alone, so a Ruby interpolation such as `#{user.name}` in prose survives untouched and the syntax is inert in any document without a `counters:` section; `\#{…}` forces a literal, and code spans and fenced blocks are never touched. Duplicate keys and dangling references are reported as warnings — through `warnings.warn`, so they are visible by default and can be promoted to failures with `PYTHONWARNINGS=error` — rather than silently producing a wrong or empty number. Two caveats are worth stating plainly: the numbering is positional, so inserting an item renumbers every item after it — which breaks traceability when the identifiers have been quoted outside the document — and the first iteration deliberately ships without auto-generated listings, per-item attributes, back-references, hierarchical numbering or per-chapter resets. See `docs/syntax/counters.md`.

### Fixed

- **Capital Greek vanished inside math alphabets: `\mathrm{k\Omega}` printed `k` and no ohm.** fontspec keeps the legacy OT1 math layout alive in a `legacymaths` symbol font (Computer Modern), where capital Greek sits in slots "00–"0A — a bare `$\Omega$` works because that is where it comes from. But fontspec declares those symbols `\mathalpha` (class 7), and a math alphabet — `\mathrm{k\Omega}`, `\mathbf{\Delta}` — refetches class-7 symbols from the *current* alphabet font: the Unicode text font, whose slot "0A holds the LINE FEED. The glyph silently disappeared (`Missing character … U+000A` in the log), which is exactly the input a pdfLaTeX user writes for units. The `ts-fonts` fragment now redeclares the eleven capital Greek symbols `\mathord`, taken from `legacymaths` under every alphabet — upright, which is what pdfLaTeX prints for `\mathrm{k\Omega}`. The trade: `\mathbf{\Omega}` renders regular instead of bold, where it previously rendered *nothing*. Registered at begin-document so it lands after fontspec's own deferred math setup, and skipped when fontspec was loaded `no-math`.
- **Markdown in an image's alt text reached the caption as literal punctuation.** `![anti-*windup* by *back-calculation*](fig.png){#fig:x}` rendered `\caption[…anti-*windup*…]{…}`: Python-Markdown copies the image description verbatim into the `alt` attribute without processing its inline syntax, and TeXSmith read that attribute as plain text — a single string node — so the emphasis the author wrote shipped as asterisks, in the caption and in the list-of-figures short caption alike. The reader now re-parses the alt as inline Markdown (only when it contains characters that can start inline syntax; a plain alt keeps its fast path) and both writers render it like a figcaption, so `*windup*` becomes `\emph{windup}` in LaTeX and `_windup_` in Typst. This applies wherever the alt is used: the caption of a bare image, and the short caption of a `/// caption` figure.
- **`-o <dir> --build` could ignore the requested directory and drop the PDF in the current one.** The decision to render into a temporary directory was keyed on Typer's parameter source for `--output`, which is `None` whenever the command runs without a click context — and `None` was treated as "the user did not pass `-o`". An explicit `-o dir` then rendered to a temporary directory, left the requested one empty, and wrote the PDF to `Path.cwd()`, littering the current directory with a file nobody asked for there. The branch is now keyed on the absence of `-o` itself.
- **The reference inventory was never delivered when building a PDF, so `{page}` was unreachable.** `<document>.refs.json` is written next to the intermediate `.tex` and enriched with the page numbers harvested from the `.aux`; with `-o report.pdf --build` that directory is temporary, so the inventory — pages and all — was deleted along with it and only the PDF came out. It is now delivered next to the artifact that was asked for, and its `document.source`, which is stored relative to the inventory's own location and is what the staleness check reads, is recomputed when the file moves. Copying the inventory by hand had the same effect as losing it: the path stopped resolving and the staleness check went quietly inoperative, so an inventory whose recorded source cannot be found now warns instead of silently skipping the check.
- **Cross-reference and counter warnings pointed at TeXSmith's own source.** They are diagnostics for whoever writes the document, but `warnings.warn` attributed them to the frame that raised them and Python printed that irrelevant line of TeXSmith underneath. They are now attributed to the citing document.
- **A double-quoted attribute value made the whole attribute list vanish.** `![Trace](a.png){#fig:trace width="50%"}` rendered as an image with no attributes followed by the literal text `{#fig:trace width="50%"}`, taking the `id` — and therefore every reference to that figure — down with it. The cause is ordering: TeXSmith's `quotes` extension is an inline pattern (priority 65) and turns `"50%"` into a `<q>` element long before the `attr_list` treeprocessor (priority 8) gets to look at the brace group, which by then is no longer a single text node and no longer matches. Single-quoted and unquoted values were unaffected, as was vanilla Python-Markdown, which is what made this look like a colon-in-the-id problem rather than a quoting one. The quote pattern now declines any match that sits inside a brace group shaped like an attribute list — one holding an `#id`, a `.class` or a `key=value` token — so `{#fig:x width="50%"}` and `{#sec:x title="Mon titre"}` keep their attributes. Quotes in running prose are untouched, including inside a brace group that carries no attribute token.
- **An `attr_list` id on an image produced no `\label`, so every reference to that figure was dangling.** `![Trace](trace.png){#fig:trace}` puts the id on the `<img>` element itself, and the HTML reader dropped it: `ir.Image` had no field to carry it, so the LaTeX writer had nothing to pass and hardcoded `label=None`. The figure partials had emitted the `\label` in the right place — after the `\caption`, where it captures the figure number rather than the enclosing section's — for as long as they had existed; the value simply never arrived. `\ref{fig:trace}` therefore resolved to nothing, `\pageref` to `??`, and neither LaTeX nor TeXSmith said a word, which is why this repository writes its figure labels by hand inside the captions. The id now reaches `ir.Image` and both writers, so `{#fig:…}` works on an image the way it already worked on a heading, in LaTeX and in Typst alike. The `<figure id="…">` form that `pymdownx.blocks.caption` produces was never affected and keeps precedence when both ids are present. This also makes an image a valid silent-definition target for a custom counter.
- **A figure's short caption was dropped in exactly the case it exists for.** The image `alt` text is the short caption — the entry that goes to the list of figures while the figure itself carries the explanatory `/// caption`. The guard deciding whether to emit `\caption[short]{long}` compared the two the wrong way round: it discarded the short caption as soon as the full caption was *longer* than the alt, which is the only situation where a short caption earns its place, and kept it when the alt was the more verbose of the two, so the list of figures collected the longer text of the pair. The comparison is reversed: the alt is emitted as the optional argument of `\caption` unless it is longer than the caption it stands for, and a figure whose alt *is* its caption still renders `\caption[X]{X}` as before. Documents whose alt differs from their caption will see their list of figures change — that is the point, but it is a visible change to an existing rendering.
- **Affiliation footnote marks disappeared from the title page under XeLaTeX.** Since 2020 the LaTeX kernel builds footnote symbols from *text* symbols rather than math ones: `\@fnsymbol` starts with `\textasteriskcentered`, which is U+2217 in `TU` encoding. When the document also triggered the font-fallback machinery, the `ucharclasses` transitions installed for a Unicode block took the mark with them: a single `−` (U+2212) anywhere in the body was enough to hand the whole *Mathematical Operators* block (U+2200–U+22FF) to a fallback font chosen for that minus sign, and that font — Noto Serif in practice — has no U+2217, so the mark was silently dropped (`Missing character` in the log) while the affiliation footnote at the bottom of the page kept its now-invisible reference. The `ts-fonts` fragment restores the pre-2020 math symbols wherever it installs transitions; taken from the math font, they are out of reach of the block rules. The glyphs are unchanged — the mark sequence is still `*`, `†`, `‡`, `§`, `¶`, … — and documents without fallback transitions keep the kernel definition untouched. The underlying weakness is not addressed here: a block transition is installed even when the main font covers the characters that triggered it, and the fallback font is only ever validated against the characters the scan saw in the source, never against the rest of the block.

## [0.5.4] - 2026-08-25

### Fixed

- **Fixed column widths overflowed the text block.** A declared `width: 25%` was emitted verbatim as `p{0.25\linewidth}`, but `p{}` sizes the *content* box and LaTeX adds `\tabcolsep` of padding on **both** sides of **every** column on top of it. A table whose percentages summed to 100 % therefore measured `\linewidth + 2n\tabcolsep` — 48 pt too wide at four columns, 60 pt at five — and its booktabs rules ran into both margins, the more so as the column count grew. Applies to `tabular`, `longtable` and the fixed columns of a `tabularx` alike, and to absolute lengths (`width: 3cm`) as well as percentages. Tables that reach the declared width through `X` / `auto` columns were never affected, LaTeX sizing those against the total.

## [0.5.3] - 2026-08-24

### Fixed

- **`longtable` was wrapped in a `table` float.** The float incremented the table counter a second time, so a document alternating floating tables and longtables skipped numbers, and it prevented the table from breaking across pages — the whole point of `longtable`. The environment is now emitted directly with its caption inside, plus `\endfirsthead`/`\endhead` so the header repeats on every page. `longtable` also hard-codes `: ` as its caption separator while babel-french patches `\@makecaption` to honour `\CaptionSeparator`; `\LT@makecaption` is redefined on the same separator when one is installed.
- **Glossary acronyms corrupted inline math.** Inline `$...$` spans used to travel through the pipeline as raw text, protected only by the LaTeX escaper's math heuristic. Since Markdown 3.5 the `abbr` extension (which backs the front-matter glossary) is a tree processor that rewrites every non-atomic text node, so an acronym occurring inside a formula — `$V_{bus}/(4 L f_{PWM})$` with a `PWM` glossary entry — was wrapped in an `<abbr>` element, splitting the formula and downgrading it to escaped literal text (`\$\textbackslash{}Delta...`) in the output. `mdx_math` now runs with `enable_dollar_delimiter` so `$...$` becomes a math element at inline-pattern time, with its payload stored as `AtomicString`, out of reach of tree-level text rewriting. Side benefit: a literal `*` inside inline math (`$i_q^*$`) no longer pairs with emphasis markers elsewhere in the paragraph.
- **Only the first YAML configuration input was honoured; the following ones were converted as documents.** `split_inputs` captured a single metadata-style YAML file as shared configuration, so every subsequent `.yaml`/`.yml` input fell through to the document list and was rendered as Markdown — surfacing as confusing errors such as a `press.language` conflict between the configuration and the template defaults. All body-less YAML mapping inputs are now recognised as configuration and deep-merged in argument order (later files override earlier ones), so a build can pass `texsmith config.yaml data.yml tasks.yaml doc.md` directly instead of concatenating the files beforehand. The merged configuration counts as a single press-metadata source, `--makefile-deps` records every configuration file as a dependency, and when *only* YAML inputs are given the last one is treated as the document (data-driven templates) with the earlier ones acting as configuration. API note: `SplitInputsResult.front_matter_path` and `ConversionRequest.front_matter_path` (both `Path | None`) are replaced by `front_matter_paths` sequences.

## [0.5.0] - 2026-07-15

### Added

- **`@[label]` cross-reference shorthand.** The reference syntax documented in `docs/syntax/references.md` is now implemented by a bundled Markdown extension (`texsmith.extensions.references:SmartReferenceExtension`, enabled by default). `@[sec:intro]` renders as an internal reference (`\ref{sec:intro}` in LaTeX, `#ref(<sec:intro>, supplement: none)` in Typst), and the brackets can be omitted when the label is a single word (`@sec:intro`, `@tbl:data`); trailing sentence punctuation stays out of the label. E-mail addresses, `@` inside words/URLs and code spans are not affected, and `\@` escapes a literal `@`.
- **Typst cross-reference targets.** The Typst writer now emits heading labels from `{#…}` identifiers (`= Title <sec:intro>`), attaches figure identifiers as labels (`#figure(…) <fig:melt>`), wraps labelled tables in a referenceable `#figure(…) <tbl:data>`, and renders fragment links (`[text](#label)`) as `#link(<label>)[text]` instead of a dead URL link. Note that Typst resolves references at compile time: a reference to a label that does not exist is a hard compile error (LaTeX degrades to `??`).

### Fixed

- **Table labels referenced the enclosing section.** The LaTeX table partials emitted `\label{…}` *before* `\caption{…}`, so `@[tbl:…]`/`\ref` resolved to the current section number instead of the table number. The label is now attached after the caption.

## [0.4.1] - 2026-06-27

### Added

- **Template-scoped render extensions.** A template's `[latex.template]` manifest section can now declare `readers` (a list of importable modules whose `@reads` HTML→IR lowerings are layered on top of the bundled registry) and `writer` (a `"module:Class"` reference to a `LaTeXWriter` subclass adding or overriding `@writes` emitters). They are resolved when the template is selected and applied to the `LaTeXRenderer` **for that template only**, so a template package (exam, thesis, poster…) can own custom constructs without affecting other templates' conversions. This restores third-party custom rendering after the 0.4.0 IR migration removed the global `@renders` / `texsmith.renderers` mechanism; the new hook is deliberately template-scoped (no global reader/writer registration). New public helper `texsmith.readers.html.build_reader_registry(extra_modules=…)`; resolution lives in `texsmith.core.templates.extensions`. Documented in `docs/api/handlers.md`.

## [0.4.0] - 2026-06-27

### Added

- **Typed intermediate representation (IR).** Conversion now flows through an explicit three-stage pipeline — `readers/html` → `texsmith.ir` (a typed, backend-agnostic `Block`/`Inline` document model) → `writers/{latex,typst}` — instead of mutating a BeautifulSoup tree in place into LaTeX strings. The IR is semantic, not LaTeX-shaped (a table carries the validated `texsmith.extensions.tables` model with one-letter semantic alignment, never a `"lrX"` preamble; the backend writer computes the preamble), which is what makes a second output backend possible without duplicating the conversion logic. New public surface: `texsmith.ir` (nodes, enums, `NodeVisitor`), `texsmith.readers.html.HtmlReader`, and `texsmith.writers.latex.LaTeXWriter` / `texsmith.writers.typst.TypstWriter`.
- **Typst output backend (experimental).** A new `--format {latex,typst}` flag (default `latex`) selects the output engine, so a single Markdown/HTML source can be built with a LaTeX engine (Tectonic, TeX Live, lualatex…) **or** with [Typst](https://typst.app/). The `article` and `book` templates are Typst-compatible: title, authors (with affiliations), subtitle, date/version, abstract, table of contents, section/heading numbering, native `#bibliography`, and book chapters. Templates declare a `[typst.template]` manifest section (parallel to `[latex.template]`) with a `template.typ` scaffolding; the Typst path routes through the template system, with a standalone fallback for the no-template case. The covered node subset is broad (text/formatting, headers, lists, code, math via `mitex`, links, images, tables, citations, footnotes, admonitions, definition lists). The backend is **experimental**: math goes through the third-party `mitex` package (which can lag the bundled compiler and fail on some constructs), a few constructs are approximated (`MarginNote` renders as a footnote, the `<abbr>` index marker is dropped, remote/unresolved images are dropped to keep the document compilable), and any node still without a Typst emitter raises an explicit, localised `TypstWriteError` rather than degrading silently. The LaTeX backend remains the default and the supported path. See `docs/guide/plumbing/backends.md` for the full covered/uncovered scope.
- **Pip-installable Typst compiler.** A new `texsmith[typst]` optional extra bundles the Typst compiler (the PyPI `typst` package), so `pip install "texsmith[typst]"` / `uv tool install "texsmith[typst]"` enables `--build` for Typst with no system toolchain — analogous to the live Tectonic download. A system `typst` binary on `PATH` is used as a fallback when present. `.typ` emission never depends on a compiler being installed. (Note: the bundled PyPI compiler can lag recent Typst releases; for documents using recent `mitex` math, prefer a system `typst` binary.)
- New documentation page `docs/guide/plumbing/backends.md` describing the IR pipeline, the `--format` flag, Typst installation paths, and the covered/uncovered Typst scope.
- `examples/typst-hello` and `examples/typst-article` demonstrating the Typst backend end to end.
- **Full Typst coverage of every bundled example.** Every `examples/*` document now also builds with `--format typst`, and each example `Makefile` builds **both** backends (a `latex` / `typst` target each, plus a `make typst` aggregate at the examples root), mirroring `examples/paper`. Closing the remaining gaps required several backend additions: the Typst path now renders **Draw.io / Mermaid diagrams** to PNGs (reusing the shared converter strategies) and rewrites the IR image nodes accordingly; **equation cross-references** (`\eqref` / `\ref` / `\label`) are handled natively (mitex labels do not propagate, so a pure-reference math span becomes a Typst `#ref` and an embedded `\label` is re-attached to the now-numbered equation); the templated path gained a **generic named-slot engine** (any declared slot is filled from the matching section, not just `abstract`), a raw `front_matter` context plus `te` (typst-escape) / `longdate` Jinja filters for **data-driven templates**, and an `asset()` helper that copies a source-relative file (e.g. a signature image) next to the `.typ`. A new `bcp47_language` attribute normaliser maps babel language names (`english`) to ISO codes (`en`).
- **Typst sections for the `colorful-grid`, `recipe`, and `formal-letter` templates.** The poster grid, the data-driven recipe card, and the business letter (the LaTeX-only holdouts) now declare `[typst.template]` blocks with native `template.typ` scaffolding, so `colorful`, `recipe`, and `letter` build with Typst too.
- **Closer Typst/LaTeX article parity.** The Typst article (and book) backend now: renders a bare block image as a centred `#figure` captioned by its alt/title (was a left-aligned inline image); renders the document date through the shared, language-aware `format_date` resolver (`November 16, 2025`); emits an unnumbered **Acronyms** backmatter list of the `<abbr>` definitions used (mirroring the LaTeX glossary fragment); gives section headings more vertical space; and shows the page number only when the document spans more than one page (single-page articles stay unnumbered, like the LaTeX `LastPage>1` guard). The author block no longer renders stray `[…]` brackets (Typst markup treats `[…]` literally).
- **Styled Typst callouts + mustache substitution on the Typst path.** The Typst backend now honours `callouts.style` (`fancy` / `classic` / `minimal`) and the per-kind callout palette — border/title colours and icons from the built-in definitions plus any custom callouts declared in front matter — instead of a single hard-coded block, matching the LaTeX `ts-callouts` fragment. The `admonition` example builds all three styles for Typst as it does for LaTeX. The Typst path also now runs the shared mustache substitution (front matter + HTML), which `prepare_documents` skips, so placeholders like `{{callouts.style}}` resolve in Typst output.

- **Rendering architecture rewritten.** Element handling moved from a multi-pass DOM-mutation engine to the reader/writer model above. Extension authors who registered render rules with `@renders` / `RenderPhase` must migrate to `@reads` (lower an HTML element to an IR node) and `@writes(NodeType)` (emit a node for a given backend). `LaTeXRenderer` is now a thin `read → write` orchestrator that reuses the existing Jinja LaTeX partials, so the LaTeX output is preserved — the bundled examples render byte-identically to the previous engine. The font-fallback scan now runs over IR text nodes instead of the final LaTeX, making it backend-agnostic. Net effect on the source tree: ~12 fewer files and ~4k fewer lines.
- `escape_latex_chars` now lives in `texsmith.writers.latex.escaper` (escaping is a backend concern); `texsmith.adapters.latex.utils` re-exports it.
- Pinned Tectonic version for the live download bumped `0.15.0` → `0.16.9` (release asset naming verified unchanged; the `--version` cache probe relies on a flag that was dropped in 0.16.0 and restored in 0.16.9).
- Typst PDF compilation now **prefers the system `typst` binary** over the embedded PyPI compiler, falling back to the package when no binary is on `PATH`. The bundled package floats to the latest Typst (`>=0.15`), which drops symbols `mitex` still emits (e.g. `diff` for `\partial`); the user-installed binary tracks `mitex`'s supported versions, so preferring it keeps recent math compiling.

The `_coerce_string` / `_format_authors` helpers copied across the article/book/letter templates are now a single `TemplateContextHelpers` mixin in `texsmith.templates.common`.
- Merged `texsmith.core.html_utils` (`strip_html_comments`) into `texsmith.adapters.html_utils` and deleted the dead `texsmith.core.templates.text` module (the live `_squash_blank_lines` lives on in `wrapper`); `_discover_template_variables` is now defined once in `context_usage` and imported by `wrapper`. Front-matter glossary parsing moved from `texsmith.core.conversion.glossary` to `texsmith.core.glossary` (it has no conversion-layer dependency and sits beside the other front-matter resolvers).
- Extracted the babel / BCP-47 language tables and mappers out of the 1039-line `texsmith.core.templates.manifest` into a focused `texsmith.core.templates.languages` module (manifest down to ~930 lines); `runtime` now imports the alias table from there instead of reaching into `manifest`.
- Moved the two heading-analysis `HTMLParser` subclasses out of `texsmith.core.documents` (637 → ~547 lines) into `texsmith.core.heading_analysis` (`HeadingLevelScanner`, `HeadingInspector`), and dropped the unused `Document._HEADING_TAGS` class variable.
- Split the LaTeX-log Rich renderer (`LatexLogRenderer`) out of the 720-line `texsmith.adapters.latex.engines.latex.log` into a sibling `log_render` module (log down to ~500 lines), separating log *parsing* from its *presentation*; the streaming entry point imports the renderer lazily to avoid an import cycle.
- Removed the module-level `DoiBibliographyFetcher` cache-and-test-seam in `texsmith.core.conversion.templates` (the last "exported for test monkeypatching" shim). DOI fetching now goes through a single `_resolve_bibliography_fetcher()` factory that lazily imports the real fetcher; `_ensure_doi_support()` only resolves the error type and DOI normaliser. Tests substitute the fetcher by patching the factory rather than a dual-purpose module global.
- Moved the font-provisioning machinery out of the `ts-fonts` fragment into `texsmith.fonts.provisioning`. The fragment package (`texsmith.fragments.fonts`) carried ~780 lines of font tooling — CTAN `.sty` acquisition / stub generation, Plex and emoji font downloads, and the family / glyph-fallback / monospace context builder — leaving the actual fragment only ~70 lines. That tooling now lives under `texsmith.fonts` (where the rest of the font subsystem already is), and the fragment is a thin ~100-line glue module that imports it. Pure relocation, no behaviour change; the LaTeX-oriented output is unchanged.

The command previously re-implemented binary selection (Tectonic/biber/makeglossaries), command/env construction and the engine run inline — duplicating the (until now unused) `build_pdf` service method. `render` now delegates to it and keeps only presentation, the PDF copy and dependency-file emission (1225 → ~1150 lines). `build_pdf` gains an injectable `run_engine` parameter so the engine run stays a clean test seam instead of relying on monkeypatched module globals.

## [0.3.1] - 2026-06-12

### Added

- Template packages can now supply their own attribute `normaliser` without reaching into TeXSmith internals. The manifest `normaliser` field, in addition to the built-in names (`paper_option`, `orientation`, `babel_language`, `callout_style`, `margin_style`, `code_options`), now accepts a fully-qualified callable reference of the form `"package.module:callable"` (the dotted `"package.module.callable"` form is also tolerated). The referenced object is imported and cached (`functools.cache`) the first time it is needed, and validated when the manifest is loaded so misconfiguration fails early with the template name, attribute name, and offending value in the `TemplateError` message (module not found / attribute not found / not callable). A public `texsmith.core.templates.register_attribute_normaliser(name, func, *, override=False)` helper is also exposed for authors who prefer registering a short name at import time; registering over a built-in name raises a `TemplateError` unless `override=True`. The callable contract is unchanged — `(value, spec, fallback) -> value` — and every existing manifest using a built-in name behaves exactly as before.
- Templates can now declare their own default Markdown extensions through a new `markdown_extensions` manifest field (`TemplateInfo.markdown_extensions`). The `render` command resolves the selected template's manifest and layers its extensions on top of the built-in defaults but below the CLI-requested ones (`--extension`), so a template can opt into extra Markdown behaviour by default while authors can still override per document and switch any of them off with `--disable-extension`. `resolve_markdown_extensions` gains a keyword-only `template=` parameter carrying the template-declared list; template-resolution failures are deferred to the main pipeline rather than surfacing twice. New `examples/hello_world_api.py` shows the minimal Python-API path (`ConversionRequest` → `ConversionService.execute` → `build_pdf`) for rendering a "Hello World" article to PDF with Tectonic.
- `bibliography_show_urls` front-matter flag (default `false`) for the `ts-bibliography` fragment. When `false` (the new default), the `biblatex` preamble suppresses raw `url`/`urldate` field output and turns the entry's title into a `\href{<url>}{…}` hyperlink, preserving the underlying style's italic (`\mkbibemph`) or quoted (`\mkbibquote`) formatting. Long URLs no longer leak into justified two-column bibliographies as `\url{…}` chunks that produce streams of `Underfull/Overfull \hbox` warnings; the title stays clickable in the PDF. Set `bibliography_show_urls: true` in the document front matter to restore the previous behaviour and print the full URL inline (with the same hyphenation caveats as before).
- Structured `version:` front-matter schema (validated by Pydantic) that supersedes the previous string-only contract. Five shapes are accepted: free-form text (`version: "Draft 3"`), a list of integers (`version: [2, 3, 0]` → `"2.3.0"`), an explicit semver mapping (`version: {major: 2, minor: 3, patch: 0, pre: "rc1", build: "abc"}` → `"2.3.0-rc1+abc"`), a git derivation (`version: {git: true}` → `git describe --tags --dirty`), and a git-with-suffix variant (`version: {git: true, suffix: "(draft)"}` → `"v0.5.1 (draft)"`). The literal `version: git` shorthand is preserved as a backwards-compatible alias for `{git: true}`. Resolution lives in a new `texsmith.core.document_version` module (`format_version`, `FreeFormVersion`, `SemverListVersion`, `SemverDictVersion`, `GitVersion`, `DocumentVersionError`); the article template feeds the resolved canonical text through `escape_latex_chars` before injection, so structured shapes survive the metadata pipeline untouched (`type = "any"` on the manifest attribute) and validation errors surface as `DocumentVersionError` with the originating Pydantic message.
- Structured `date:` front-matter schema with three magic keywords on top of free-form ISO and string values: `date: today` renders today's system date in long form, `date: commit` renders the date of the last `HEAD` commit (via the new `git_commit_date()` helper in `texsmith.core.git_version`), and `date: none` (the new default when `date` is omitted) emits a bare `\date{}` so `\maketitle` drops the date line. ISO strings (`"2026-03-05"`) and YAML-parsed `date` objects render as long form localised by the document `language` (`"5 mars 2026"` for `language: french`, `"March 5, 2026"` for English; first of the month becomes `"1er"` in French). Resolution lives in a new `texsmith.core.document_date` module (`format_date`); the article template's manifest attribute is `type = "any"` so structured shapes pass through, and `core.metadata` now skips string coercion for structured `date` values during press-metadata flattening.
- `texsmith.core.git_version.git_commit_date()` returns the committer date of `HEAD` (using `git log -1 --format=%cs`) for the repository containing the supplied path, with a per-repo cache and the same warn-on-missing semantics as `git_describe()`. Used by the `date: commit` keyword.
- `article` template `version` front-matter field that surfaces in `\maketitle` underneath the date in a `\small` style. The value is free-form (`version: "Consolidation du draft de janvier 2026"`) or the literal sentinel `version: git`, in which case the template runs `git describe --tags --dirty` against the document's repository (with a 7-character commit-hash fallback, suffixed `-dirty` when the worktree has uncommitted changes) and emits a warning if no git metadata is reachable. The resolver lives in a new `texsmith.core.git_version` module — `git_describe()`, `git_commit_date()`, `resolve_git_root()`, `reset_cache()` — so other templates can opt in. Tag names containing LaTeX-special characters (`_`, `&`, `%`, `#`, …) are escaped by the article template before being injected, so a tag like `v1.0_alpha` renders correctly.
- New `invisible_chars` Markdown extension (registered by default) that replaces stray zero-width characters — ZWSP (`U+200B`), ZWNJ (`U+200C`), ZWJ (`U+200D`), and BOM (`U+FEFF`) — with a non-breaking space (`U+00A0`) in text nodes. Code, `pre`, `kbd`, `script`, and `style` elements are left untouched, so deliberate zero-width sequences inside fenced code blocks still survive. Defends against pasted content silently smuggling glyphs that small-caps fonts (e.g. `lmromancaps10-regular`) cannot render.
- `yaml table` columns can now omit the `name` field. When every column omits it, the rendered output drops the `<thead>` (and the corresponding LaTeX `\midrule` after the header) so the body sits directly under `\toprule` — handy for two-column key/value summaries. Mixed cases (some named, some not) keep the header row and emit blank `<th>` cells for the unnamed columns. Per-column `align`, `width`, and `width-group` keep their usual meaning. The `examples/tables/tables.md` tutorial gains a "Headerless tables" section showcasing the feature.
- Plain Markdown tables now support inline horizontal separators: any body row whose every cell is just three or more dashes (`| --- | ----- | --- |`, surrounding whitespace allowed) is rewritten as a separator row tagged with `data-ts-role="separator"` (a single `<td colspan="N">`) and rendered as a bare `\midrule` in LaTeX. A new `_MarkdownTableSeparatorTreeprocessor` performs the rewrite on `<tbody>` / `<tfoot>` rows and reuses the same separator markup that `yaml table` emits, so both the legacy `render_tables` handler and `render_yaml_table` (when bound via `yaml table-config`) handle the rule uniformly. Cells with fewer than three dashes, or rows where any cell carries non-dash content, are left as regular data rows.

### Changed

- The `"module:attribute"` import-reference parsing now lives in a single helper (`texsmith.core.templates.manifest._import_object`) shared by the attribute-normaliser resolver and fragment-entrypoint loading, replacing two near-duplicate copies. As a side effect, a malformed or unresolvable fragment `entrypoint` now raises a `TemplateError` whose message names the reference and the missing module/attribute (the same actionable wording used for normalisers), instead of leaking a bare `ImportError`/`AttributeError` or the older terse "Fragment entrypoint must be in the form 'module:attribute'." text. Also removed a dead, shadowed duplicate definition of `_render_attribute_markdown` in the manifest module (the second definition always won; the first was unreachable).
- Standalone short-bold paragraphs are now promoted to a `\tslead{…}` lead-in instead of rendering as bare `\textbf{…}`. A `<p>` whose only meaningful child is a single `<strong>` element with under 80 characters of plain text triggers the rule; bold inside running prose, bold over the threshold, and bold labels synthesised by other extensions (e.g. `tabbed-set` labels nested in a `<div>`) keep the original `\textbf{…}` rendering. The macro — `\providecommand{\tslead}[1]{\par\noindent\textbf{#1}\par\nobreak\smallskip}` — is emitted idempotently next to every use (same pattern as `\texsmithHighlight`), so it can be overridden in a custom preamble snippet without touching the converter. Motivation: under `babel-french` (and any class with a non-zero `\parindent`), a bold pseudo-heading wedged between two block environments (`\end{center}` … `\textbf{Méthodologie}` … `\begin{center}`) renders flush left while the same construct after running prose is indented; `\tslead` forces a stable `\noindent` paragraph break + `\smallskip` so both cases align without authors having to sprinkle manual `\noindent`s. Implemented as a new PRE-phase `<p>` handler (`render_lone_bold_paragraph`) and a new `lead.tex` partial; documented under "Standalone bold paragraphs" in `docs/syntax/formatting.md`.
- The article template now emits `\date{}` (no date line) when no `date` is configured, replacing the previous `\date{\today}` fallback. Documents that want today's date must opt in explicitly with `date: today`. Same applies when `date: none` is set explicitly.
- The article template's title block emits a `\date{{\small <version>}}` block when only a version is set (no date), instead of suppressing the version entirely. Combined date+version blocks are unchanged.
- `texsmith.core.git_version.format_version` is now a thin shim that forwards to `texsmith.core.document_version.format_version`. The shim is preserved for backwards compatibility; new code should import from the new module.
- `ts-extra` margin-note safety buffer (`\tsmarginparbuf`, subtracted from the available outer margin when clamping `\marginparwidth`) bumped from `6pt` (~2 mm) to `6mm`, so margin notes typeset via the `{margin}[…]` extension keep a visibly safe gap to the page edge instead of sitting 2-3 mm away. Documents that need the previous, tighter clamp can override it in a custom preamble snippet (`\setlength{\tsmarginparbuf}{6pt}`).

### Fixed

- `letter` template Swiss standard (`sn-right`) now passes the correct `scrletter` LCO option `SN` instead of the non-existent `SNright`, which `KOMA-Script` silently ignored, so right-aligned Swiss letters (SN 010130) now lay out as intended. The bare `sn` and `swiss` aliases now resolve to `sn-right` (the published SN 010130 reference layout) rather than `sn-left`; documents that relied on the old left-aligned default must set `sn-left` explicitly.
- The `footnote` LaTeX partial no longer emits a trailing `%` after the closing brace. Inline footnotes followed by text on the same source line (e.g. `…enseignants[^note] ; suite`) used to render as `\footnote{…}% ; suite`, where the stray `%` silently commented out the rest of the rendered paragraph; the closing brace is now bare so subsequent inline content is preserved.
- Inline `<code>` inside a footnote definition now reaches the LaTeX formatter and is rendered as `\texttt{…}` (with `_`/`#`/`%` escaped) instead of being flattened to raw text. The footnote handler now runs the same rich-text preparation that lists and definition lists already use before extracting the body, so a footnote like ``[^note]: La source `EPFL_REORIENT` documente …`` produces `\texttt{EPFL\_REORIENT}` and no longer trips XeLaTeX with `Missing $ inserted` on the unescaped underscore.
- `article` template now loads `morewrites` first thing after `\documentclass`, virtualising `\newwrite` so XeLaTeX's hard 16-register limit no longer truncates documents that combine many glossary groups (each group costs one `\write`) with biblatex, hyperref's outline, the toc, and `listoftables` / `listoffigures`. Before this change a typical front matter with 5+ glossary groups and `listoftables: true` failed at runtime with `! No room for a new \write` at `\listoftables`, and `tectonic` produced a silently truncated PDF that stopped before the back matter (LOT, glossaries, bibliography). `morewrites` is loaded ahead of `xcolor` so subsequent allocations route through its virtual stream pool. Added to `tlmgr_packages` so non-tectonic builds resolve it automatically.
- `ts-fonts` now activates `U+200B` and maps it to `\hskip\z@`, mirroring the existing `U+2135` (Aleph) precedent. `biblatex`'s `blx-unicode.def` workaround for [biblatex#979](https://github.com/plk/biblatex/issues/979) appends a literal ZWSP inside `\textnohyphenation`, which `babel-french` invokes from its redefinition of `\mkbibnamefamily`; rendered through the active small-caps font that lacks a glyph for `U+200B`, this used to spam `Missing character: There is no ​ (U+200B) in font [lmromancaps10-regular.otf]` warnings on every French-language bibliography. `ts-fonts` is loaded before `biblatex` in every bundled template, so `blx-unicode.def` reads the literal ZWSP under the new active catcode and the resulting macro expands to a zero-width breakable skip — preserving the line-break-opportunity semantics the workaround was after, without ever hitting the font.

## [0.3.0] - 2026-04-26

### Added

- Structured `glossary:` front-matter section, validated with pydantic, that complements the existing `*[KEY]: …` body syntax. Each entry carries an explicit `description` and an optional `group`; groups are declared at the top with their displayed title (`groups: {tech: Acronymes techniques, …}`), and entries with no group fall back to the standard acronym table. TeXSmith emits one localised `\printglossary[type=<group>, title=<title>]` per group in declaration order, plus `\printglossary[type=\acronymtype]` for ungrouped entries; the default acronym title now uses `\acronymname` so `babel` localises it (e.g. *Acronymes* under `language: french`). Front-matter entries that never appear in the body are still defined in the glossary; entries that do appear are auto-substituted with `\acrshort{KEY}` whenever the strict, case-sensitive form occurs in the text — `\Gls`/`\GLS` casing helpers are not synthesised (a documented limitation). The `article` template now loads `babel` before `extra_packages` so the `glossaries` package picks up the active language. New `examples/glossary/` tutorial.
- `article` template now supports `listoffigures: true` and `listoftables: true` front-matter flags (mirroring the `book` template), plus a `lists_position: toc | backmatter` knob to choose whether the lists are inserted right after the table of contents (default) or just before the backmatter and references. Each list is wrapped in `\ifnum\value{figure|table}>0` so empty documents don't emit blank pages.
- New `yaml table` Markdown fence describing complex tables in YAML and compiling to `tabular` / `tabularx` / `longtable` on demand. Supports multi-row and multi-column cells (in headers and body), nested grouped headers, width-groups, separators with optional labels, footers, captions via the standard `Table: …` syntax, and explicit width control. Validation errors surface as inline error admonitions with a clear, localised message. New `examples/tables/` tutorial pairs each YAML source with its rendered output and ships a Makefile to build the demo PDF.
- `ts-extra` now auto-loads the `multirow` package when `\multirow` is detected in the rendered LaTeX.
- `Table: <caption> {#label}` now also works on plain Markdown tables: a tree processor pairs the caption paragraph with the following `<table>` and injects a `<caption>` child carrying the caption text (and optional `id` from the `{#label}` part). Both the yaml-table renderer and the legacy table renderer consume `<caption>` directly, so the LaTeX output gets a proper `\caption{…}` with its `\label{…}`.
- 0.5 em of vertical breathing room is inserted between the caption and the table body for both yaml-tables and plain Markdown tables when a caption is present.
- New `yaml table-config` fence applied right below a plain Markdown table sends per-column attributes (`align`, `width`, `width-group`) and table-level settings to the yaml-table renderer. Marks the table with `data-ts-*` attributes so it goes through the same `tabular` / `tabularx` / `longtable` selection as full yaml-tables, including caption handling. A `BlockProcessor` parses the fence into a real ElementTree marker so a sibling tree processor can bind the config to the preceding `<table>`.
- New explicit `width: X` value (case-insensitive, alias for `tabularx`'s `X` column) marks a single column as flexible without needing a `width-group` shim. When any column carries `width: X`, only that column expands; the others keep their natural width.
- `align` accepts long forms (`left`, `right`, `center`, `centre`, `justify`, `justified`) in addition to the short single-letter forms; both are normalised to the short form internally.
- New `{margin}[note]{side?}` inline shorthand for margin notes, joining the unified `{keyword}[content]` family (alongside `{index}[term]` and `{latex}[payload]`). The optional single-letter suffix picks a side — `l` / `i` force the left margin (scoped `\reversemarginpar`), `r` / `o` the right; without a suffix the note follows the document's default (right in `oneside`, outer in `twoside`). Inline markdown inside the note is preserved (bold, italic, code, links). Compiles to `\marginnote{…}` from the LaTeX `marginnote` package, which `ts-extra` now auto-loads on detection. Three defensive layers keep notes within the page on any geometry: (1) `\marginfont` is configured with `\footnotesize`, `\sloppy`, `\emergencystretch=1em` and lowered hyphenation penalties so long words break (or inter-word spacing stretches) rather than overflow; (2) an `\AtBeginDocument` hook clamps `\marginparwidth` to the horizontal space the document's geometry actually reserves on each side (recto and, in twoside, verso), minus `\marginparsep` and a 6 pt safety buffer; (3) a custom `geometry: {left: 3cm, right: 4cm}` yields notes that still fit on both pages with no manual `marginparwidth=…` tweak. New `examples/marginnote/` tutorial with a Makefile; extension documented in `docs/syntax/notes.md`.

### Fixed

- Two long-standing test assertions that had drifted away from the templates they exercise: `test_render_template_applies_markdown_metadata` expected the title/subtitle pair `\\\large` (pre-spacing format) but the article template now emits `\\[0.5em]\large` (commit `c9aff0f`); `test_article_template_supports_columns_option` expected the `twocolumn` documentclass option, but the article template intentionally omits it and uses `\twocolumn[…]` after `\maketitle` so `\@thanks` stays populated and affiliation footnotes survive (`\tsreplayfn` flushes them). Both assertions updated to match the current — correct — template behaviour.
- Python 3.10 compatibility regression: `enum.StrEnum` is 3.11+, but `requires-python = ">=3.10"` and the CI matrix exercises 3.10. The `tables` extension imported `StrEnum` unconditionally, breaking 50 test files at collection time on 3.10 (every test that transitively touches the markdown processor). Added a tiny version-guarded shim that subclasses `str, Enum` on 3.10 and re-exports the stdlib class on 3.11+. Aligned `ruff target-version` with `requires-python` so the version guard isn't flagged as `UP036 outdated version block`.
- Page-number prefix (`n1` / `n2`) leaking into grouped acronym tables produced by the `glossaries` package. Two-part fix: (1) bumped the `pyxindy` dependency to **0.0.7**, which routes every `markup-locref` slot (`:open` / `:close` / `:sep` / `:prefix`) through the existing `_normalize_markup_string` helper so the xindy `~n` newline escape no longer leaks into the rendered output (`_update_locfmt` previously copied the raw strings verbatim); (2) extended TeXSmith's defensive post-processor (`adapters/latex/engines/__init__.py`) to glob `*-gls` in addition to `*.gls` so files emitted by `\newglossary*{<type>}` (e.g. `glossary.technical-gls`) go through `sanitize_glossary_output` for users still on pyxindy <0.0.7.
- Glossary page numbers were not clickable: the `glossaries` package only wraps numbers in `\hyperpage` when `hyperref` is loaded *before* it. Both the `article` and `book` templates now load `babel` and `hyperref` before `\VAR{extra_packages}` (which carries `glossaries` via `ts-glossary`), enabling both babel-localised acronym titles and hyperref-backed clickable backreferences. Same constraint that applies to babel localisation, made explicit in the preamble comments.
- HTML comments (`<!-- ... -->`) are now stripped before rendering and no longer appear verbatim in the LaTeX output. A shared `core.html_utils.strip_html_comments` helper runs in `extract_slot_fragments` (before node serialisation, where `str(comment_node)` would otherwise silently drop the `<!--`/`-->` delimiters and expose the raw comment text) and from the `discard_unwanted` PRE-phase handler.
- `tabularx` column specifications now use `>{\raggedright\arraybackslash}X`, `>{\raggedleft\arraybackslash}X`, and `>{\centering\arraybackslash}X` for all columns (including the first), replacing the previous `l`/`X` split. This prevents text overflow in two-column (`twocolumn`) document layouts and improves line-breaking throughout.
- Inline formatting (bold, italic, etc.) inside quoted text (`"**bold**"`) is now correctly rendered — `AtomicString` was preventing further inline processing inside `<q>` elements.
- Silent exception swallowing in post-render rule/asset collection now emits a diagnostic warning instead of discarding the error.
- Nested list environments (`\begin{itemize}`) no longer appear glued to the parent item text on the same line; a newline is now inserted between the item content and any nested `\begin{itemize|enumerate|description}`.
- Table caption numbering no longer skips numbers (e.g. 1, 2, 4, …). `ts-extra` previously auto-loaded `ltablex` under single-column layouts, which silently transformed every `tabularx` into a `longtable` internally and bumped the `table` counter twice per use. Replaced by a plain `tabularx` load; explicit `longtable` is still detected on demand.

### Changed

- Removed dead code after the early `return` in `_allow_hyphenation` (unreachable lines).
- Dropped the unused `fragments` field from `ExecutionContext`; fragment resolution was already propagated through `template_overrides`.
- Deduplicated `runtime_common.get("code")` lookups in `_render_slot_fragments` into a single local variable.
- Reverted an uncommitted injection of `template_overrides` into the Jinja render context (`runtime_common`) — it had no consumer and exposed internal state unnecessarily.
- **Tables extension refactor (SSOT).** Introduced `texsmith.extensions.tables.constants` housing `TableAttr` (StrEnum for every `data-ts-*` attribute), `PERCENT_RE`, `ALIGN_ALIASES` / `ALIGN_WRAPPERS`, and a `Priority` class that documents each pipeline position. Removed the duplicate `_PERCENT_RE` in `layout.py`. Collapsed the three identical align/width/width-group validator triplets (`LeafColumn`, `ColumnGroup`, `ColumnConfig`) into a shared `_ColumnAttrs` base. Extracted a single `_consume_fence` helper used by both preprocessors and the block processor; the two preprocessors now fail identically (admonition surfaced on parse error) instead of diverging between silent fall-through and block-level error emission. Caption handling no longer wraps the table in a throwaway `<figure>` / `<figcaption>` to be unwrapped by `render_figures`; the `<caption>` is injected directly into the `<table>`. `render_figures` keeps its figure-with-table path (still reached by `pymdownx.blocks.caption`) and routes via a new `is_texsmith_table()` helper instead of literal attribute comparison. The `build_error_element` helper in `tables.html` lets the preprocessor and the block processor share admonition construction.
- **`slot_options` plumbing simplified.** The per-slot render flags (`SlotOptions`) now live only on `Document` and are read directly by the consumer (`extract_slot_fragments`) instead of being copied through `ExecutionContext` and `BinderContext`. The `parse_slot_mapping_with_options` and `extract_front_matter_slots_with_options` wrappers were removed; `parse_slot_mapping` and `extract_front_matter_slots` now always return a `(selectors, options)` tuple.
- **Fragment resolution extracted.** New `core.fragments.resolution` module with a typed `FragmentModifiers(append, prepend, disable)` dataclass, `parse_modifiers(raw)` for front-matter shapes, and a pure `merge_fragments(defaults, override, *, cli_enable, cli_disable)` function. `_resolve_fragments_list` is now a 15-line orchestrator instead of a 65-line dispatcher with three nested helpers.
- **Silent `except Exception` handlers documented or warned.** Font-fallback scans in `conversion/renderer.py` now emit a warning via the diagnostic emitter on failure; user-supplied `should_render` callbacks in `core/fragments` warn with the fragment name instead of silently swallowing the failure; the third-party template-distribution discovery in `templates/loader.py` keeps its broad catch but carries an explicit comment and `# noqa: BLE001` explaining why it is intentional.

### Removed

- **`ExecutionContext` and `BinderContext` merged into `ConversionContext`.** Both classes carried an almost identical set of fields resolved at two successive stages (pre- and post-template-binding); they were collapsed into a single `core.conversion_contexts.ConversionContext` with optional `config` / `template_binding` fields that become populated when `bind_template` runs. Dead fields dropped: `BinderContext.documents: list[Document]` (only ever appended, never read meaningfully), `BinderContext.bound_segments` (written in `_render_document`, never read). The file `core/execution.py` has been deleted.

- **Function renames tracking the new context class:**
  - `resolve_execution_context` → `resolve_conversion_context` (returns the partially-populated `ConversionContext`).
  - `build_binder_context` → `bind_template` (mutates the context in place to populate `config`, `template_binding`, and the template-refined `slot_requests`; same object returned for chaining). Its keyword parameter `execution=` is renamed to `context=`.
  - `ConversionResult.binder_context` field renamed to `ConversionResult.context`.
