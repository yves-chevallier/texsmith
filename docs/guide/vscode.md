# VS Code extension

TeXSmith ships a Visual Studio Code extension that highlights TMark, the
Markdown dialect described in `specs/tmark.md`. It lives under
`packages/vscode-tmark` and is not published on the marketplace yet: build it
from the repository and install the resulting `.vsix`.

## Installation

```sh
cd packages/vscode-tmark
npm install
npm run package                                   # writes vscode-tmark-<version>.vsix
code --install-extension vscode-tmark-0.1.0.vsix
```

Reload the window afterwards (*Developer: Reload Window*). In a WSL or SSH
window, run the last command from the remote side: the extension is a
grammar-only extension and works wherever it is installed. Opening
`packages/vscode-tmark` in VS Code and pressing ++f5++ starts an Extension
Development Host with a sample document instead, which is the quickest way to
try a change to the grammar.

## What it does

The extension contributes a TextMate grammar in two ways:

- **Injected into Markdown.** Every `.md` file keeps VS Code's own `markdown`
  language (preview, outline, link navigation, the other Markdown extensions)
  and gains the TMark scopes on top of it.
- **A `tmark` language** for `.tmark` and `.tmd` files, with the same grammar.
  A workspace can force it on Markdown files with
  `"files.associations": {"*.md": "tmark"}`.

The grammar follows the recognisers of the *Lexical grammar* section of the
specification, one rule per construct:

| Family | Highlighted |
| ------ | ----------- |
| Attributes | `{#id .class key=value}` after headings, images, captions, fences, and Pandoc spans `[text]{attrs}` |
| Roles | the name, the positional argument and the `key=value` arguments of `{aside}[…]`, `{index}[…][…]`, `{raw latex}(…)`, `{include}(…)`, `{counter}(…)`, `{code py}[…]`, … |
| References | `@key`, `@[key, locator; key2]`, `@doi:…`, Pandoc's `[@key]` |
| Definitions | `#[term][sub]` index entries, `#(prefix:key)` counter items |
| Captions | `Table:`, `Figure:`, `Listing:` lines |
| Containers | `::: name {attrs}` … `:::`, `!!! type "Title"`, `??? type`, `/// name` |
| Data directives | the node word and the options of ```` ```yaml table ````, ```` ```python image include="…" ````, ```` ```latex raw ````, and fence options such as `title=` or `hl_lines=` |
| Inline sugar | `__small caps__`, `==mark==`, `~sub~`, `^sup^`, `++keys++`, `[^1]`, `^[note]`, `{{ moustache }}`, critic markup |

Deprecated spellings listed in the specification's deprecation schedule
(`#{prefix:key}`, `{latex}[…]`, `{margin}[…]`, `{index:registry}[…]`,
`/// … ///`, `--8<--`, `::: margin`) carry the `invalid.deprecated.tmark` scope
and are struck through, so a document can be cleaned up by eye before
`tmark fmt` exists.

Nothing fires inside code spans, fenced blocks, the YAML front matter, math or
HTML comments.

## Colours

The scopes reuse the conventional TextMate names (`entity.name.function` for a
role name, `support.type` for a reference key, `keyword.control` for a
directive marker, …), so every theme colours them. Constructs without a
conventional scope (small caps, highlight, subscript, superscript) receive a
default colour through the extension's `configurationDefaults`; override any
of them with `editor.tokenColorCustomizations`:

```json
"editor.tokenColorCustomizations": {
  "textMateRules": [
    { "scope": "support.type.reference.tmark", "settings": { "foreground": "#c586c0" } }
  ]
}
```

*Developer: Inspect Editor Tokens and Scopes* shows the scopes under the
cursor; every TMark scope ends in `.tmark`.

## Maintaining the grammar

The JSON grammars under `syntaxes/` are generated by
`scripts/build_grammar.py`, where each rule is a Python raw string next to a
comment naming the construct it covers. After a change:

```sh
npm run build:grammar   # regenerate syntaxes/*.json
npm test                # tokenise test/sample.md with vscode-textmate and check the scopes
node test/tokens.mjs some-file.md   # dump the tokens of any file
```

The tests load the Markdown and Markdown Math grammars vendored under
`test/grammars/` from VS Code itself, so what they see is what the editor
shows. Two behaviours of `vscode-textmate` shaped the grammar and are worth
knowing before editing it: a rule that includes a grammar the registry cannot
load is dropped silently, and only a `begin` match moves the `\G` anchor that
Markdown's paragraph rule needs, which is why the line markers (`Table:`,
`:   `, `[^1]:`, `- [x]`) are `begin`/`end` rules that run to the end of the
line.
