\section{Fallbacks}
Font fallback is... complicated---almost \emph{passionately} so. In a browser, the mechanism is straightforward: if a glyph is missing in the first font, the engine walks the font stack and tries the next one, and the next one, until it eventually finds something that contains the character. For obscure Unicode blocks or emoji, Chrome and other modern browsers ultimately fall back to Google's Noto super-family, which covers most of the Unicode universe.

\LaTeX{}, on the other hand, does \textbf{not} provide automatic font fallback in the same way. With classic \tslogo{pdfLaTeX} there is no real fallback mechanism at all; if a glyph isn't in the selected font, you simply get a missing-glyph warning or a tofu box.

\tslogo{LuaLaTeX} changes the game: thanks to the \tscodeinline{luaotfload} package, it \emph{can} perform font fallback, but you must explicitly define fallback fonts in your document or template.

However, for this to work, those fallback fonts need to actually \emph{exist} on your \TeX{} system. And this is where it gets tricky: installing Noto fonts via \TeX{} Live (\tscodeinline{tlmgr}) or via system packages like \tscodeinline{apt install fonts-\allowbreak{}noto} is often incomplete, because distributions usually ship only a subset of the full Noto collection. For full Unicode coverage (emoji, rare historical scripts, CJK extensions, etc.), you often need to manually download and install the complete font set from Google's official Noto Fonts repository.
