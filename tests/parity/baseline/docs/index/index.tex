\section{Why would I use TeXSmith?}\label{why-would-i-use-texsmith}

TeXSmith bridges the gap between lightweight Markdown authoring
and the typographic power of \LaTeX{}. It is ideal for:

\begin{itemize}
\item{} Writing scientific articles.
\item{} Writing product documentation.
\item{} Writing books.
\item{} Writing letters.
\item{} Writing technical reports.
\item{} Writing cooking recipes and more.

\end{itemize}
The combination with MkDocs provides a single source of truth for both web and PDF output, which improves collaboration because all documentation lives in Markdown in a Git repository. Versioning with MkDocs stays simple and natural.

\section{Why teams choose TeXSmith}\label{why-teams-choose-texsmith}

\begin{description}
\item[{ Pipeline parity }] The CLI and Python API share the same conversion engine,
  so automation scripts and ad-hoc conversions stay in sync.
\item[{ Template-friendly }] Wrap multiple documents into a single LaTeX project,
  map fragments into template slots, and customise the runtime with Jinja2.
\item[{ Diagnostics you can trust }] Structured emitter APIs and CLI verbosity
  flags surface the context you need when something goes wrong.

\end{description}
\section{How is it different from Pandoc?}\label{how-is-it-different-from-pandoc}

\href{https://pandoc.org/}{Pandoc} is a powerhouse, but reproducing an extended Markdown syntax other than
\href{https://commonmark.org/}{CommonMark} or \href{https://github.github.com/gfm/}{GitHub-flavored Markdown} document in
Pandoc requires custom filters and ongoing maintenance. TeXSmith focuses on MkDocs Markdown
with Pymdown extensions, delivering parity out of the box:

\begin{itemize}
\item{} Handles Material-only components such as tabbed content, callouts, and
  keyboard keys.
\item{} Ships with diagram converters (Mermaid, Draw.io) that plug directly
  into the LaTeX build step.
\item{} Exposes the same primitives via the CLI and Python API, so automation scripts
  match what authors do locally.

\end{itemize}
Use both tools together when it makes sense; reach for TeXSmith when MkDocs \(\rightarrow\) \LaTeX{}
compatibility is the priority.
