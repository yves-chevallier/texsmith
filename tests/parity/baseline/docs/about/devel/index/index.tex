\section{Unified Fences Syntax}
Markdown format has evolves like a living spece and multiple syntaxes coexists for different purposes. While MyST chose to only use backticks for any blocks (code, admonition), it seems more natural to use different fence styles for different purposes:
\begin{itemize}
\item \tscodeinline{```} for code blocks and special blocks (Mermaid, \LaTeX{}, custom tables, etc.) that require processing
\begin{itemize}
\item \tscodeinline{<language>} Language highlighting for code blocks
\item \tscodeinline{mermaid} for Mermaid diagrams
\item \tscodeinline{svgbob} for SVGBob diagrams
\item \tscodeinline{tikz} for TikZ diagrams
\item \tscodeinline{table} for custom tables
\item \tscodeinline{python figure} for Python-generated figures
\end{itemize}
\item \tscodeinline{!!!} and \tscodeinline{???} for admonitions and promoted text (notes, warnings, tips, etc.)
\item \tscodeinline{:::} or \tscodeinline{///} for custom containers environments (center, right, language, font size, \LaTeX{} only, HTML only, raw \LaTeX{}, etc.)
\begin{itemize}
\item \tscodeinline{align center} for centered text
\item \tscodeinline{align right} for right-aligned text
\item \tscodeinline{language <lang>} for language-specific content
\item \tscodeinline{font large} for font size adjustments
\item \tscodeinline{font small} for font size adjustments
\end{itemize}
\end{itemize}
which can add captions to figures or tables, but discrimination of target (figure or table) is
not done automatically you must specify \tscodeinline{figure-\allowbreak{}caption} or \tscodeinline{table-\allowbreak{}caption}

MyST Directives support adding options/arguments using this syntax:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
```\PYZob{}directive\PYZcb{}
:option: value
```

\PYZob{}rolename\PYZcb{}`text`
\end{Verbatim}
\end{tscode}
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
:::\PYZob{}note\PYZcb{}
Admonition
:::
\end{Verbatim}
\end{tscode}
The subfigures with the \tscodeinline{| \^{}1} syntax work, but this is not optimal for \LaTeX{} rendering, and the reference ID generated with \tscodeinline{attrs: \{id: static-\allowbreak{}id\}} can be misleading.

TeXSmith offers a more convenient way of adding figures using the admonition style
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
/// figure \PYZob{} \PY{n+ni}{\PYZsh{}reference} \PYZcb{}

   ![\PY{n+nt}{alt}](\PY{n+na}{image.png})

   Caption...
\end{Verbatim}
\end{tscode}
You can automatically use subfigures with the following. The layout attribute will dictate how the figures are arranged in the output (\tscodeinline{2:1} two figures horizontally, \tscodeinline{2:2} four figures in two columns with two rows).
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
/// figure \PYZob{} \PY{n+ni}{\PYZsh{}reference} layout=\PYZdq{}2:1\PYZdq{} \PYZcb{}

   ![\PY{n+nt}{a}](\PY{n+na}{image.png})
   ![\PY{n+nt}{b}](\PY{n+na}{image.png})

   We see in (a) a figure and in (b) another one.
\end{Verbatim}
\end{tscode}
To refer to figures, use the \tscodeinline{[](reference)} which will be replaced by the element number.
\begin{tscode}[lang=markdown, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
We see in Figure [](duck) that the animal has two legs.
\end{Verbatim}
\end{tscode}
\section{Tectonic log}
We want to mute false warnings and not display them:
\begin{tscode}[lang=perl, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{l+s+sr}{/\PYZca{}warning:\PYZbs{}s*.*?:\PYZbs{}d+:\PYZbs{}s*Requested font.*?at.*\PYZdl{}/}
\PY{l+s+sr}{/\PYZca{}warning:\PYZbs{}s*.*?:\PYZbs{}d+:\PYZbs{}s*Unknown feature.*?in font.*\PYZdl{}/}
\end{Verbatim}
\end{tscode}
Recent matrix runs with \TeX{} Gyre (bonum/pagella/termes/schola/heros/adventor/cursor) trigger
many Tectonic warnings like \tscodeinline{Unknown feature '} or repeated \tscodeinline{Requested font} lines; output is
otherwise correct. Keep these noted as benign until we wire the log filter above or document a
flag to silence them.

Mais nous avions configuré un style Mermaid global a TeXSmith pour avoir des diagrammes b\&w dans le PDF final. Il n'est probablement plus activé ou pris en compte. La gestion du cache des assets est aussi à vérifier et la rendre dépendante de la configuration mermaid (si on change le style, il faut regénérer les diagrammes), ou alors si l'exécutable ou la version de l'image docker utilisée change.

\subsection{MkDocs Linking Issues}
MkDocs currently fails to resolve links to other pages. For example, \tscodeinline{[High-\allowbreak{}Level Workflows](api/high-\allowbreak{}level.md)} becomes \tscodeinline{\textbackslash{}ref\{snippet:...} but the referenced snippet is never defined. Replacing the syntax with \tscodeinline{\textbackslash{}ref} builds successfully but still fails at runtime. Investigate and fix the resolver so links work throughout the site.

Also note that the scientific paper ``cheese'' example prematurely closes code blocks after a snippet. Identify why the snippet terminates early and correct it.

\subsection{Fences the gros bordel}
\subsubsection{Code}
We only use \tscodeinline{```} fences for code blocks or other special blocks like Mermaid, \LaTeX{}, custom tables, etc. No other uses should be allowed.
\subsubsection{Admonitions}
We prefer the MkDocs admonition syntax as it is more flexible and better supported.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]

    This is the content of the note.

??? info \PYZdq{}Foldable Info Title\PYZdq{}

    This is the content of the info.
\end{Verbatim}
\end{tscode}
\subsubsection{Fenced custom}

We use the syntax \tscodeinline{verb} + \tscodeinline{option} after the opening \tscodeinline{:::} to specify the type of container and any relevant options.
\begin{tscode}[lang=text, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
::: latex only
This LaTeX\PYZhy{}only content will be included in the LaTeX output but ignored in HTML.
:::

::: html only
This HTML\PYZhy{}only content will be included in the HTML output but ignored in LaTeX.
:::
\end{Verbatim}
\end{tscode}
We can use raw \LaTeX{} blocks for more complex \LaTeX{} content that doesn't fit well in Markdown:
\begin{tscode}[lang=text, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
::: latex raw
\PYZbs{}clearpage
:::
\end{Verbatim}
\end{tscode}
With SuperFences we support extra HTML attributes for custom containers:
\begin{tscode}[lang=text, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
::: language arabic \PYZob{}\PYZsh{}custom\PYZhy{}id .custom\PYZhy{}class data\PYZhy{}attr=\PYZdq{}value\PYZdq{}\PYZcb{}
This is Arabic content with custom HTML attributes.
:::
\end{Verbatim}
\end{tscode}
Each \tscodeinline{:::} container is converted into a \tscodeinline{<div>} with the specified attributes in HTML, while \LaTeX{} processes the content according to the container type.
\subsubsection{GFM Support for admonitions}
We want TeXSmith to support GitHub Flavored Markdown (GFM) admonitions as well. This includes the ability to create notes, warnings, tips, and other types of admonitions using the GFM syntax.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{k}{\PYZgt{} }\PY{g+ge}{[!NOTE]}
\PY{k}{\PYZgt{} }\PY{g+ge}{This is a note admonition.}
\end{Verbatim}
\end{tscode}
This is converted to the exact same output as the MkDocs admonition syntax. It is equivalent to:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
!!! note
    This is a note admonition.
\end{Verbatim}
\end{tscode}
\subsection{Figure References}
Printed references depend on the document language. In English we would write, ``The elephant shown in Figure 1 is large.'' The \LaTeX{} equivalent is \tscodeinline{The elephant shown in Figure\textasciitilde{}\textbackslash{}ref\{fig:elephant\} is large.} Pymdown lets us write:
\begin{tscode}[lang=markdown, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
The elephant shown in figure [\PYZsh{}fig:elephant] is large.
\end{Verbatim}
\end{tscode}
\begin{tscode}[lang=latex, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{k}{\PYZbs{}hyperref}\PY{n+na}{[fig:elephant]}\PY{n+nb}{\PYZob{}}Figure\PYZti{}\PY{k}{\PYZbs{}ref}\PY{k}{*}\PY{n+nb}{\PYZob{}}fig:elephant\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZcb{}}

\PY{k}{\PYZbs{}usepackage}\PY{n+na}{[nameinlink]}\PY{n+nb}{\PYZob{}}cleveref\PY{n+nb}{\PYZcb{}}
The elephant shown in \PY{k}{\PYZbs{}Cref}\PY{n+nb}{\PYZob{}}fig:elephant\PY{n+nb}{\PYZcb{}} is large.
The same sentence in French typography would translate to “The elephant shown in \PY{k}{\PYZbs{}cref}\PY{n+nb}{\PYZob{}}fig:elephant\PY{n+nb}{\PYZcb{}} is large,” keeping “figure” lowercase.
\end{Verbatim}
\end{tscode}
In scientific English we capitalize ``Figure'', while French typography keeps ``figure'' lowercase.
