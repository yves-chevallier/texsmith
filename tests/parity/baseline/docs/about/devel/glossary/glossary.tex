The MkDocs \href{https://realtimeprojects.github.io/mkdocs-ezglossary}{ezglossary} plugin exists, but the syntax is unintuitive (for example, the semicolon separator) and does not handle spaced or formatted entries well. Ideally, readers should be able to access the glossary as a popup, tooltip, or link.

\LaTeX{} glossaries usually rely on the \tscodeinline{glossaries} package and definitions declared in the preamble via \tscodeinline{\textbackslash{}newglossaryentry}:
\begin{tscode}[lang=latex, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{k}{\PYZbs{}newglossaryentry}\PY{n+nb}{\PYZob{}}key\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}
  name=\PY{n+nb}{\PYZob{}}singular form\PY{n+nb}{\PYZcb{}},
  plural=\PY{n+nb}{\PYZob{}}plural form\PY{n+nb}{\PYZcb{}},
  description=\PY{n+nb}{\PYZob{}}descriptive text\PY{n+nb}{\PYZcb{}},
  first=\PY{n+nb}{\PYZob{}}special form for first use\PY{n+nb}{\PYZcb{}},
  text=\PY{n+nb}{\PYZob{}}normal form (if you want to force it)\PY{n+nb}{\PYZcb{}},
\PY{n+nb}{\PYZcb{}}
\end{Verbatim}
\end{tscode}
\tscodeinline{\textbackslash{}gls} uses the standard form, \tscodeinline{\textbackslash{}Gls} capitalizes the first letter, \tscodeinline{\textbackslash{}glspl} gives the plural, and \tscodeinline{\textbackslash{}Glspl} capitalizes the plural. The first use of the term falls back to the \tscodeinline{first} form when present, otherwise \tscodeinline{name}. Markdown alone cannot express all of that. \textbf{What shipped} is the front-matter
declaration, under \tscodeinline{press.declare.glossary} (the top-level \tscodeinline{glossary:} key is
read as deprecated sugar):
\begin{tscode}[lang=yml, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
press:
  declare:
    glossary:
      entries:
        HTML: HyperText Markup Language
\end{Verbatim}
\end{tscode}
Every occurrence of a declared key in the prose becomes \tscodeinline{\textbackslash{}tsacr\{HTML\}}, which
\tscodeinline{ts-\allowbreak{}glossary} defines as \tscodeinline{\textbackslash{}acrshort} --- always the short form, deliberately: the
author never writes the call, so a first-use expansion would rewrite prose
nobody typed and make the printed document say something different from the web
profile, where the key stays inside \tscodeinline{<abbr>}. A glossary \emph{term} reference is
written by the author as \tscodeinline{@gls:term} and becomes \tscodeinline{\textbackslash{}tsgls}, which is \tscodeinline{\textbackslash{}gls} and
therefore follows the \tscodeinline{glossaries} conventions.

What is \textbf{still open} is the rest of a \tscodeinline{\textbackslash{}newglossaryentry}: \tscodeinline{plural}, \tscodeinline{first}
and a forced \tscodeinline{text} have no spelling yet, and neither does the popup/tooltip
presentation on the web side.
