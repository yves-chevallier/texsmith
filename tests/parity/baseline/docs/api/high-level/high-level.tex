\section{High-Level Workflows}\label{high-level-workflows}

TeXSmith exposes a thin, expressive façade over the lower-level conversion primitives. Mix and match Markdown, HTML, and template-aware documents without touching the CLI or re-implementing glue code.

This page showcases the building blocks you are most likely to use in scripts, services, or notebooks. All examples assume \texttt{pip install texsmith} (or \texttt{uv tool install texsmith}) plus any template packages you rely on.

\begin{callout}[callout tip]{Run the snippets}
Save the examples into a file and execute them with \texttt{uv run python example.py}. The snippets rely only on fixtures you create alongside the script.
\end{callout}

\subsection{Drive the pipeline with \texttt{ConversionService}}\label{drive-the-pipeline-with-texttt-conversionservice}

If you need the exact orchestration used by the CLI, rely on \texttt{ConversionService}. It exposes two steps:

\begin{enumerate}
\item \texttt{prepare\_documents(request)} splits inputs, normalises Markdown/HTML, applies slot assignments, and returns a \texttt{ConversionPrepared} payload.
\item \texttt{execute(request, prepared=...)} renders the documents, optionally through a template, and produces a \texttt{ConversionResponse} with the bundle plus emitted diagnostics.

\end{enumerate}
\begin{code}{python}{}{}
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]

The CLI passes a \texttt{CliEmitter} via \texttt{ConversionRequest.emitter} so warnings surface nicely. Library callers can supply their own emitter or accept the default \texttt{NullEmitter}.
