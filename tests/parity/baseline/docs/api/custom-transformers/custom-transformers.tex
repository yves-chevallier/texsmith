\maketitle
Transformers convert non-PDF assets (Mermaid, Draw.io, bitmap images) into files
\LaTeX{} can include. They are driven by the \href{handlers.md\#ir-passes}{\tscodeinline{assets} pass},
which rewrites each image node to point at the converted file before
\tscodeinline{tmark.write} emits the figure. When the built-in strategies do not cover your
workflow, register custom converters via
\tscodeinline{texsmith.adapters.transformers.register\_converter}.

The base class adds caching, stable file naming, and retry/backoff hooks. Supply
your own \tscodeinline{suffix} when the converter emits something other than \tscodeinline{.pdf}.
\section{Wiring the converter}
\begin{enumerate}
\item Import the module before converting documents (e.g., in \tscodeinline{docs/hooks/mkdocs\_hooks.py}
or a standalone script).
\item Reach it from an \href{handlers.md\#ir-passes}{IR pass}: register a \tscodeinline{pre} pass that
walks the tree for the nodes it owns --- a \tscodeinline{CodeBlock} with \tscodeinline{lang="plantuml"},
say --- and calls \tscodeinline{registry.convert("plantuml", …)}, replacing the node with an
\tscodeinline{Image} that points at the result. Declare it on your template
(\tscodeinline{[latex.template] passes = […]}) so it applies only while that template
renders.
\item Ship optional dependencies (CLI tools, Docker images) alongside the template
README so users know how to enable the converter.
\end{enumerate}
\section{Handling fallbacks}
When TeXSmith cannot find a converter, the \tscodeinline{assets} pass leaves a visible
literal in the output and emits a diagnostic at the node's span rather than
failing the render --- a pass never raises. Use
\tscodeinline{texsmith.adapters.transformers.has\_converter("mermaid")} to check whether a
converter is registered before assuming the dependency exists, and
\tscodeinline{-\allowbreak{}-\allowbreak{}diagrams-\allowbreak{}backend playwright|local|docker} to pin which backend is tried
instead of letting the automatic fallback pick.
