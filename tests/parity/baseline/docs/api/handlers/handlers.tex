\title{IR passes and fragment contracts}
\author{}\date{}

\maketitle
TeXSmith no longer reads HTML and no longer emits \LaTeX{} from
Python. The parser, the intermediate representation, the resolver and the
writers are tmark's; what remains on the Python side is the part that needs the
filesystem, the network and a process --- and the part that decides what a
construct \emph{looks like}.
\begin{tscode}[lang=text, stretch=0.5, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
tmark.parse ─▶ IR ─▶ TeXSmith passes ─▶ tmark.resolve ─▶ tmark.write ─▶ Body \PYZob{} text, map, requires \PYZcb{}
\end{Verbatim}
\end{tscode}
There are therefore two extension points, and the \tscodeinline{@reads} / \tscodeinline{@writes}
decorators of 0.6 map onto them:
\begin{center}
\begin{tabularx}{\linewidth}{>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X}
\toprule
\textbf{0.6 hook} & \textbf{0.7 replacement} \\
\midrule
\tscodeinline{@reads} lowering (HTML \tsscript{symbols}{\(\rightarrow\) }IR) & a TMark \textbf{container} (\tscodeinline{::: name}) plus, when it computes something, an \textbf{IR pass} \\
\tscodeinline{@writes} emitter (IR \tsscript{symbols}{\(\rightarrow\) }\LaTeX{}) & a \textbf{contract macro} provided by a fragment, redefined by the template \\
\tscodeinline{[latex.template] readers} & \tscodeinline{[latex.template] passes = ["pkg.module:pass"]} \\
\tscodeinline{[latex.template] writer} & redefine the contract macro in the template's \tscodeinline{.tex} \\
fragment \tscodeinline{partials}, \tscodeinline{required\_partials} & the fragment's \tscodeinline{provides} list \\
\bottomrule
\end{tabularx}
\end{center}
All five --- \tscodeinline{readers}, \tscodeinline{writer}, \tscodeinline{latex.template.override}, fragment
\tscodeinline{partials} and \tscodeinline{required\_partials} --- were deprecated in 0.7.0 and are gone in
0.8.0: neither the template manifest nor \tscodeinline{fragment.toml} reads them any more, so
a package that still declares one converts as if it did not.
\section{IR passes}
A pass is a pure function \tscodeinline{(Document, PassContext) -\allowbreak{}> Document} over the
generated IR models. It never mutates its input, returns the same object when it
has nothing to do, and otherwise rebuilds the tree with \tscodeinline{document.evolve(...)}.
Failures never raise: a node is replaced by a visible literal and a diagnostic
is emitted at its span. An exception escaping a pass is a bug.

Two stages surround the one Rust step in the middle:
\begin{description}
\item[{\tscodeinline{pre}}] before \tscodeinline{tmark.resolve}. A \tscodeinline{pre} pass may add, remove or rewrite blocks --- this
is where includes are spliced, diagrams converted, DOIs fetched, moustaches
expanded.
\item[{\tscodeinline{post}}] after \tscodeinline{tmark.resolve}. A \tscodeinline{post} pass only slices the block list or computes
per-body options, so that the \tscodeinline{Resolved} of the whole document stays valid.
\end{description}
\begin{tscode}[lang=python, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]

Order is declared, never implicit: a \tscodeinline{PassSpec} names the passes it must run
\tscodeinline{after}, and \tscodeinline{build\_pipeline} performs a stable topological sort that raises
\tscodeinline{PassOrderError} on a cycle. Declare a template's passes in its manifest:
\begin{tscode}[lang=toml, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{k}{[}\PY{k}{latex}\PY{k}{.}\PY{k}{template}\PY{k}{]}

\PY{n}{version}\PY{+w}{ }\PY{o}{=}\PY{+w}{ }\PY{l+s+s2}{\PYZdq{}}\PY{l+s+s2}{1.0.0}\PY{l+s+s2}{\PYZdq{}}
\PY{n}{entrypoint}\PY{+w}{ }\PY{o}{=}\PY{+w}{ }\PY{l+s+s2}{\PYZdq{}}\PY{l+s+s2}{template/template.tex}\PY{l+s+s2}{\PYZdq{}}
\PY{n}{engine}\PY{+w}{ }\PY{o}{=}\PY{+w}{ }\PY{l+s+s2}{\PYZdq{}}\PY{l+s+s2}{lualatex}\PY{l+s+s2}{\PYZdq{}}

\PY{n}{passes}\PY{+w}{ }\PY{o}{=}\PY{+w}{ }\PY{p}{[}\PY{l+s+s2}{\PYZdq{}}\PY{l+s+s2}{my\PYZus{}exam\PYZus{}pkg.questions:run}\PY{l+s+s2}{\PYZdq{}}\PY{p}{]}
\end{Verbatim}
\end{tscode}
They are resolved with the same import machinery as attribute normalisers and
fragment entrypoints, so a typo fails early with an actionable \tscodeinline{TemplateError},
and they apply \textbf{only while the declaring template renders} --- exam-style rules
would corrupt unrelated documents, so there is no global entry point.

Keep passes semantic and backend-neutral: a pass rewrites IR nodes and their
attributes, never \LaTeX{} strings. The one exception is deliberate and narrow ---
the bundled \tscodeinline{highlight} pass turns code blocks into \tscodeinline{RawBlock\{format=latex\}}
holding a Pygments payload, because that work is Python-only and reuses the
\tscodeinline{latex raw} path rather than making the writer Pygments-aware.
\section{Custom constructs}
The container names TMark knows are a \textbf{closed} registry: the callout types
(built-in and declared), \tscodeinline{aside}, \tscodeinline{figure}, \tscodeinline{tabs}, \tscodeinline{tab}, \tscodeinline{multicolumn} and
\tscodeinline{div}. A new \emph{kind} of thing is a declaration under
\tscodeinline{press.declare.admonitions}, not a new container name; a wrapper the template
styles is \tscodeinline{::: div} with a class.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
::: div \PYZob{}\PYZsh{}s1 .sidebar\PYZcb{}
Content.
:::
\end{Verbatim}
\end{tscode}
On the paged backends every layout container is rendered by one contract,
\tscodeinline{\textbackslash{}begin\{tsdiv\}\{name\}[attrs]} (\tscodeinline{\#ts-\allowbreak{}div("name", ..)} in Typst), dispatched on the
name with the attributes forwarded as keys: \tscodeinline{\#id} becomes \tscodeinline{id}, classes become
\tscodeinline{class=\{a,b\}}, \tscodeinline{key=val} is forwarded as is (\tscodeinline{lang} and \tscodeinline{media} never are). A
template styles a class through the \tscodeinline{pgfkeys} family, or redefines the
environment for a name it knows:
\begin{tscode}[lang=latex, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{k}{\PYZbs{}tcbset}\PY{n+nb}{\PYZob{}}/ts/div/class/sidebar/.style=\PY{n+nb}{\PYZob{}}grow to left by=2cm\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZcb{}}
\PY{k}{\PYZbs{}RenewDocumentEnvironment}\PY{n+nb}{\PYZob{}}tsdiv@multicolumn\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}O\PY{n+nb}{\PYZob{}}\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}\PY{k}{\PYZbs{}begin}\PY{n+nb}{\PYZob{}}multicols\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}3\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}\PY{k}{\PYZbs{}end}\PY{n+nb}{\PYZob{}}multicols\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZcb{}}
\end{Verbatim}
\end{tscode}
A container name the registry does not know raises \tscodeinline{container-\allowbreak{}unknown} and
renders its content transparently.
\section{Contract macros}
The writers emit a fixed macro or environment per construct, and a fragment must
define every macro the writer can name. Naming is regular: macros are
\tscodeinline{\textbackslash{}ts<name>}, environments \tscodeinline{ts<name>}, lowercase, one word per construct. At most
one optional keyval group comes first, then the mandatory arguments, content
last.
\begin{tscode}[lang=latex, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{k}{\PYZbs{}tslead}\PY{n+nb}{\PYZob{}}…\PY{n+nb}{\PYZcb{}}
\PY{k}{\PYZbs{}tsaside}\PY{n+na}{[side=left]}\PY{n+nb}{\PYZob{}}…\PY{n+nb}{\PYZcb{}}
\PY{k}{\PYZbs{}tsprogress}\PY{n+na}{[thin]}\PY{n+nb}{\PYZob{}}0.45\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}Launch\PY{n+nb}{\PYZcb{}}
\PY{k}{\PYZbs{}tskeys}\PY{n+nb}{\PYZob{}}Ctrl,Alt,Del\PY{n+nb}{\PYZcb{}}
\PY{k}{\PYZbs{}tsindex}\PY{n+na}{[registry=physics, main]}\PY{n+nb}{\PYZob{}}sort@formatted!sub\PY{n+nb}{\PYZcb{}}
\PY{k}{\PYZbs{}begin}\PY{n+nb}{\PYZob{}}tscallout\PY{n+nb}{\PYZcb{}}[kind=warning, title=\PY{n+nb}{\PYZob{}}…\PY{n+nb}{\PYZcb{}}, id=w1, collapsed] … \PY{k}{\PYZbs{}end}\PY{n+nb}{\PYZob{}}tscallout\PY{n+nb}{\PYZcb{}}
\PY{k}{\PYZbs{}begin}\PY{n+nb}{\PYZob{}}tscode\PY{n+nb}{\PYZcb{}}[lang=py, title=\PY{n+nb}{\PYZob{}}bubble\PY{k}{\PYZbs{}\PYZus{}sort}.py\PY{n+nb}{\PYZcb{}}, linenums=1, hl\PY{n+nb}{\PYZus{}}lines=\PY{n+nb}{\PYZob{}}2\PYZhy{}3\PY{n+nb}{\PYZcb{}}] … \PY{k}{\PYZbs{}end}\PY{n+nb}{\PYZob{}}tscode\PY{n+nb}{\PYZcb{}}
\PY{k}{\PYZbs{}tscodeinline}\PY{n+na}{[lang=py]}\PY{n+nb}{\PYZob{}}xs.sort()\PY{n+nb}{\PYZcb{}}
\end{Verbatim}
\end{tscode}
Options are \tscodeinline{pgfkeys} keyvals under \tscodeinline{/ts/<name>/}, and every family ignores
unknown keys, so an older fragment survives a newer writer. Only keys with a
value are serialised; booleans are bare, text is escaped and braced, lists are
braced with commas. Typst mirrors each contract with one hyphenated function
(\tscodeinline{\#ts-\allowbreak{}callout}, \tscodeinline{\#ts-\allowbreak{}keys}) whose named arguments match the keys.

Which fragment provides which macro is the writer's \tscodeinline{Requires.fragments}: a body
that emits \tscodeinline{\textbackslash{}tscallout} activates \tscodeinline{ts-\allowbreak{}callouts}, one that emits \tscodeinline{\textbackslash{}tsindex}
activates \tscodeinline{ts-\allowbreak{}index}. Activation is by construction, not by sniffing the
rendered \LaTeX{}.
\section{Overriding a construct}
Three levels, in increasing order of violence. All of them go in the template's
\tscodeinline{.tex}, after \tscodeinline{\textbackslash{}VAR\{extra\_packages\}} (that is where fragments are
\tscodeinline{\textbackslash{}usepackage}d).
\begin{tscode}[lang=latex, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{k}{\PYZbs{}VAR}\PY{n+nb}{\PYZob{}}extra\PY{n+nb}{\PYZus{}}packages\PY{n+nb}{\PYZcb{}}
\PY{c}{\PYZpc{} (a) restyle through the pgfkeys family}
\PY{k}{\PYZbs{}tcbset}\PY{n+nb}{\PYZob{}}/ts/code/.append style=\PY{n+nb}{\PYZob{}}frame hidden, boxrule=0pt\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZcb{}}

\PY{c}{\PYZpc{} (b) redefine the macro, same signature}
\PY{k}{\PYZbs{}RenewDocumentCommand}\PY{n+nb}{\PYZob{}}\PY{k}{\PYZbs{}tscodeinline}\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}O\PY{n+nb}{\PYZob{}}\PY{n+nb}{\PYZcb{}}m\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}\PY{k}{\PYZbs{}texttt}\PY{n+nb}{\PYZob{}}\PYZsh{}2\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZcb{}}
\PY{k}{\PYZbs{}RenewDocumentEnvironment}\PY{n+nb}{\PYZob{}}tsdiv@multicolumn\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}O\PY{n+nb}{\PYZob{}}\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}\PY{k}{\PYZbs{}begin}\PY{n+nb}{\PYZob{}}multicols\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}3\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}\PY{k}{\PYZbs{}end}\PY{n+nb}{\PYZob{}}multicols\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZcb{}}
\end{Verbatim}
\end{tscode}
\begin{tscode}[lang=yaml, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{c+c1}{\PYZsh{} (c) replace the fragment outright}
\PY{n+nt}{press}\PY{p}{:}
\PY{+w}{  }\PY{n+nt}{fragments}\PY{p}{:}
\PY{+w}{    }\PY{n+nt}{disable}\PY{p}{:}\PY{+w}{ }\PY{p+pIndicator}{[}\PY{n+nv}{ts\PYZhy{}code}\PY{p+pIndicator}{]}
\PY{+w}{    }\PY{n+nt}{append}\PY{p}{:}\PY{+w}{ }\PY{p+pIndicator}{[}\PY{n+nv}{./my\PYZhy{}code.sty}\PY{p+pIndicator}{]}
\end{Verbatim}
\end{tscode}
A replacement fragment must define every entry of the fragment's \tscodeinline{provides}
list; the check runs at load time against \tscodeinline{tmark.fragments()}. See
Contract macros for the full table mapping
each construct to its macro.
