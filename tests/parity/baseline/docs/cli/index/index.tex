\title{TeXSmith Command-Line Interface}
\author{}\date{}
\begin{document}
\maketitle
TeXSmith ships with a feature-rich CLI that lets you convert Markdown or HTML into \LaTeX{}, compile PDFs, and inspect bibliography files directly from a terminal. The CLI now exposes a single command: \tscodeinline{texsmith}. Every flag hangs off that root entry point.
\begin{tscode}[lang=text, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PYZdl{} texsmith \PYZhy{}\PYZhy{}help
\PYZhy{}\PYZhy{}8\PYZlt{}\PYZhy{}\PYZhy{}\PYZhy{} \PYZdq{}docs/assets/cli\PYZhy{}help\PYZdq{}
\end{Verbatim}
\end{tscode}
\section{Options}
\subsection{General Options}
\begin{description}
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}version}}] Print the installed TeXSmith version and exit. The same value is available in Python as \tscodeinline{texsmith.get\_version()}.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}diagrams-\allowbreak{}backend}}] When TeXSmith discovers diagrams in your Markdown (e.g., Mermaid or Draw.io), it needs to convert them into image files that \LaTeX{} can include. This option forces a specific backend for that conversion, overriding the automatic selection logic. Supported backends include \tscodeinline{playwright} (headless browser), \tscodeinline{local} (locally installed CLI tools), and \tscodeinline{docker} (containerized tools).
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}embed}}] By default, TeXSmith renders converted documents as separate \LaTeX{} files and links them into the main document using \tscodeinline{\textbackslash{}input\{\}}. This option inlines the converted \LaTeX{} documents directly into the main document body instead. This can be useful for simpler projects where a single \tscodeinline{.tex} file is preferred.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}classic-\allowbreak{}output}}] When building PDFs, TeXSmith normally parses and structures the output from \tscodeinline{latexmk} to provide cleaner logs and richer diagnostics. This option disables that behavior and streams the raw \tscodeinline{latexmk} output directly to your terminal. You can disable structured logs temporarily with this option.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}build}}] After rendering the \LaTeX{} document from your Markdown sources, invoke the default engine (\tscodeinline{tectonic}) or the engine specified via \tscodeinline{-\allowbreak{}-\allowbreak{}engine} to compile the \LaTeX{} into a PDF.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}legacy-\allowbreak{}latex-\allowbreak{}accents}}] By default, TeXSmith emits Unicode characters for accented letters and ligatures (e.g., é, ñ, æ) when generating \LaTeX{} output. This option switches to using legacy \LaTeX{} macros (e.g., \tscodeinline{\textbackslash{}'\{e\}}, \tscodeinline{\textbackslash{}\textasciitilde{}\{n\}}, \tscodeinline{\textbackslash{}ae\{\}}) instead, which may be necessary for compatibility with older \LaTeX{} engines or templates.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}template-\allowbreak{}scaffold DEST}}] Copy the template selected with \tscodeinline{-\allowbreak{}-\allowbreak{}template} into \tscodeinline{DEST} and exit, so you can edit a copy of a built-in instead of starting from a blank directory. See \href{templates.md\#scaffolding-custom-templates}{Templates}.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}install-\allowbreak{}completion}, \tscodeinline{-\allowbreak{}-\allowbreak{}show-\allowbreak{}completion}}] Install or display shell completion scripts for the TeXSmith CLI. This enhances your terminal experience by providing auto-completion for commands and options.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}help}}] Show contextual help for the TeXSmith CLI, including available commands and options.
\end{description}
\subsection{Diagnostics Options}
\begin{description}
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}list-\allowbreak{}templates}}] List all discoverable templates, along with their origins and paths.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}list-\allowbreak{}bibliography}}] Display a summary of all bibliography entries found in the provided \tscodeinline{.bib} files, front matter, or DOI links. This is useful for validating bibliography sources without performing a full document render.
\item[{\tscodeinline{-\allowbreak{}v}, \tscodeinline{-\allowbreak{}-\allowbreak{}verbose}}] Increase CLI verbosity; repeat it (\tscodeinline{-\allowbreak{}vv}) for more. At \tscodeinline{-\allowbreak{}v} a diagnostic also prints its suggested fix and related locations, indented under its line.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}debug}}] Enable detailed debugging output for the CLI. This includes full Python tracebacks when unexpected exceptions occur, which can help diagnose issues during conversion or rendering. It also turns \tscodeinline{-\allowbreak{}-\allowbreak{}debug-\allowbreak{}ir} on unless that flag is given explicitly.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}debug-\allowbreak{}ir}}] Save the parsed IR of each document as \tscodeinline{<stem>.ir.json} next to the output. This is what the passes see and what \tscodeinline{tmark.write} turns into a body, so it is the first place to look when a construct does not render as expected.
\item[{\tscodeinline{-\allowbreak{}q}, \tscodeinline{-\allowbreak{}-\allowbreak{}quiet}}] Hide \tscodeinline{hint} and \tscodeinline{info} diagnostics. Warnings and errors are always shown.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}strict}}] Exit with status 1 when any warning or error was recorded, after the \LaTeX{} is written and before the engine runs. \tscodeinline{press.features.strict: true} in the front matter has the same effect. See Diagnostics.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}deprecated LEVEL}}] The transition knob of the parser. TMark reports the legacy spellings it still accepts --- root \tscodeinline{counters:} instead of \tscodeinline{press.declare.counters}, \tscodeinline{\#\{prefix:key\}} instead of \tscodeinline{\#(prefix:key)}, \tscodeinline{[\^{}key]} citations --- as \tscodeinline{deprecated} and \tscodeinline{deprecated-\allowbreak{}frontmatter-\allowbreak{}key} warnings, which would fail \tscodeinline{-\allowbreak{}-\allowbreak{}strict} on a document that has not been rewritten yet (\tscodeinline{tmark lint -\allowbreak{}-\allowbreak{}fix} does the rewrite). \tscodeinline{warning} (the default) keeps them as they are; \tscodeinline{info} lowers them to \tscodeinline{info} records, so they still print but do not fail \tscodeinline{-\allowbreak{}-\allowbreak{}strict} (and \tscodeinline{-\allowbreak{}q} hides them); \tscodeinline{off} drops them entirely. Applied before the strict check and the \tscodeinline{-\allowbreak{}-\allowbreak{}diagnostics-\allowbreak{}json} dump. \tscodeinline{press.diagnostics.deprecated: info} (or \tscodeinline{off}) in the front matter sets the same level; the CLI option wins. Every other warning is untouched.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}diagnostics-\allowbreak{}json PATH}}] Write every recorded diagnostic to \tscodeinline{PATH} as a JSON list, sorted by file and position, for editors and CI.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}open-\allowbreak{}log}}] If \LaTeX{} compilation fails during the build step, automatically open the \tscodeinline{latexmk} log file using the system's default viewer. This makes it easier to inspect compilation errors.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}dump-\allowbreak{}snippets DIR}}] Copy the sources of every \tscodeinline{.snippet} fence render (the generated \tscodeinline{.tex} and its auxiliary files) into \tscodeinline{DIR}, so a preview that comes out wrong can be compiled by hand.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}template-\allowbreak{}info}}] Show manifest metadata for the template selected via \tscodeinline{-\allowbreak{}-\allowbreak{}template}, including its attributes, assets, and slots.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}fonts-\allowbreak{}info}}] After rendering, display a summary of the fonts used in the generated \LaTeX{} document, including any fallback fonts that were selected based on the document's language and content.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}print-\allowbreak{}context}}] Print the resolved template context, including all emitters and consumers, then exit. This is useful for debugging template rendering issues.
\end{description}
\subsection{Output Options}
\begin{description}
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}output}, \tscodeinline{-\allowbreak{}-\allowbreak{}output-\allowbreak{}dir}}] Specify the output file or directory for the rendered \LaTeX{} or compiled PDF. If no output path is provided, TeXSmith defaults to writing to \tscodeinline{stdout} unless a template is used.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}makefile-\allowbreak{}deps}}] When building PDFs, generate a Makefile-compatible \tscodeinline{.d} dependency file alongside the output. This can be useful for integrating TeXSmith into larger build systems.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}format}}] Choose the output backend: \tscodeinline{latex} (default) or \tscodeinline{typst}. Both backends consume the same intermediate representation; \tscodeinline{typst} emits a \tscodeinline{.typ} source (add \tscodeinline{-\allowbreak{}-\allowbreak{}build} to compile it to PDF). The Typst path does not support \tscodeinline{-\allowbreak{}-\allowbreak{}template-\allowbreak{}info} or \tscodeinline{-\allowbreak{}-\allowbreak{}template-\allowbreak{}scaffold}. See Output backends for installation and scope.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}engine}}] Specify the \LaTeX{} engine to use when compiling the rendered document into a PDF (\LaTeX{} backend only). Supported engines include \tscodeinline{tectonic}, \tscodeinline{lualatex}, and \tscodeinline{xelatex}. The default is \tscodeinline{tectonic}.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}system}}] Use the system-installed Tectonic binary instead of the bundled version provided by TeXSmith. This can be useful if you have a specific version of Tectonic installed or want to leverage system-wide configurations.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}isolate}}] By default, TeXSmith uses a shared cache located at \tscodeinline{\textasciitilde{}/.cache/texsmith} to store compiled \LaTeX{} artifacts. This option creates a per-render cache inside the output directory, isolating the build environment for each project.
\end{description}
\subsection{Input Handling Options}
\begin{description}
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}include-\allowbreak{}path PATH}}] A directory an include falls back to when its path does not resolve against the file that writes it. Repeat the option to name several; they are searched in the order given. The including file's own directory always comes first, so \tscodeinline{\{include\}(file)} keeps the meaning the syntax reference gives it --- the search path only rescues a path written against somewhere else, which is what the deprecated \tscodeinline{-\allowbreak{}-\allowbreak{}8<-\allowbreak{}-\allowbreak{} "file"} spelling does: MkDocs resolves those against the \tscodeinline{base\_path} of \tscodeinline{pymdownx.snippets}, usually the directory of \tscodeinline{mkdocs.yml}. A document can carry the same list itself as \tscodeinline{press.include\_paths} in its front matter, written relative to the document; \tscodeinline{-\allowbreak{}-\allowbreak{}include-\allowbreak{}path} is searched before it, and the MkDocs plugin's own \tscodeinline{base\_path} after it.
\end{description}
\subsection{Structure Options}
\begin{description}
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}base-\allowbreak{}level}}] Set the base heading level for the document relative to the template. For example, if your template starts at level 1 (e.g., \tscodeinline{\textbackslash{}section\{\}}), you can adjust the base level accordingly. The default is \tscodeinline{0}. We use the convention where \tscodeinline{-\allowbreak{}1} is \tscodeinline{\textbackslash{}part\{\}}, \tscodeinline{0} is \tscodeinline{\textbackslash{}chapter\{\}}, \tscodeinline{1} is \tscodeinline{\textbackslash{}section\{\}}, and so on.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}strip-\allowbreak{}heading}}] Remove the first heading from the rendered content. This is useful when the first heading is redundant with the document title or when you want to avoid duplicate titles or keep the first heading as information only.
\end{description}
\subsection{Template Options}
\begin{description}
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}no-\allowbreak{}promote-\allowbreak{}title}}] By default, TeXSmith promotes the first heading in the document to be the title of the \LaTeX{} document. This option disables that behavior, keeping the first heading as part of the main content. If no title is found in metadata or front matter, no title will be generated.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}no-\allowbreak{}title}}] Disable title generation entirely, even if metadata or front matter provides a title. This is useful when you want to suppress the title page in the rendered document.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}template}, \tscodeinline{-\allowbreak{}t}}] Select a \LaTeX{} template to use during conversion. You can provide a local path, an entry point, or a built-in slug such as \tscodeinline{article}, \tscodeinline{book}, or \tscodeinline{letter}.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}enable-\allowbreak{}fragment}, \tscodeinline{-\allowbreak{}f} / \tscodeinline{-\allowbreak{}-\allowbreak{}disable-\allowbreak{}fragment}, \tscodeinline{-\allowbreak{}F}}] Add or remove one fragment for this render, on top of what the template defaults and \tscodeinline{press.fragments} decided. Repeat either to name several. A contract fragment the writer requires cannot be dropped this way --- a body that emits \tscodeinline{\textbackslash{}tscallout} still activates \tscodeinline{ts-\allowbreak{}callouts}.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}attribute}, \tscodeinline{-\allowbreak{}a}}] Override template attributes by providing key=value pairs. This allows you to customize template behavior without modifying the template files directly. You can repeat this option multiple times to set multiple attributes.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}slot}, \tscodeinline{-\allowbreak{}s}}] Inject specific document sections into designated template slots using the syntax \tscodeinline{slot:Section}. You can repeat this option multiple times to map multiple sections to different slots in the template.
\end{description}
\subsection{Rendering Options}
\begin{description}
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}no-\allowbreak{}copy-\allowbreak{}assets}, \tscodeinline{-\allowbreak{}C}}] Control whether remote assets (e.g., images, diagrams) are copied to the output directory during rendering. By default, assets are copied to ensure they are available for \LaTeX{} compilation. You can disable this behavior.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}convert-\allowbreak{}assets}}] Convert bitmap assets (e.g., PNG, JPEG) to PDF format even when \LaTeX{} supports the original format. This can improve compatibility and rendering quality in some cases.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}hash-\allowbreak{}assets}}] Hash the filenames of stored assets instead of preserving their original names. This helps avoid filename collisions when multiple assets with the same name are used in different documents.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}http-\allowbreak{}user-\allowbreak{}agent}}] Override the User-Agent header used when fetching remote assets (images, emoji). You can also set \tscodeinline{TEXSMITH\_HTTP\_USER\_AGENT} in the environment.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}manifest}, \tscodeinline{-\allowbreak{}m}}] Generate a \tscodeinline{manifest.json} file alongside the \LaTeX{} output, containing metadata about the rendered document, including input sources, template details, and rendering options.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}language}, \tscodeinline{-\allowbreak{}l}}] Specify the language code to pass to the \LaTeX{} \tscodeinline{babel} package. This affects hyphenation and language-specific typographic rules. If not provided, TeXSmith uses the language specified in the document metadata or defaults to English. On the \tscodeinline{tmark} reader the same resolved language, as a BCP 47 primary subtag (\tscodeinline{french} \tsscript{symbols}{\(\rightarrow\) }\tscodeinline{fr}, \tscodeinline{ngerman} \tsscript{symbols}{\(\rightarrow\) }\tscodeinline{de}, \tscodeinline{english} \tsscript{symbols}{\(\rightarrow\) }\tscodeinline{en}), is also handed to TMark's resolver and writers (\tscodeinline{lang}), which pick the label words of the predeclared series from it.
\item[{\tscodeinline{-\allowbreak{}-\allowbreak{}numbering MODE}}] Who allocates the numbers of the predeclared series --- figures, tables, listings, equations, sections and the theorem kinds. \tscodeinline{backend} (the default) leaves them to \LaTeX{} and Typst, each numbering its own floats as it always did, so a \tscodeinline{Figure 3.2} in the PDF may be a \tscodeinline{Figure 12} in the Typst output. \tscodeinline{tmark} makes TMark allocate them once, at resolve time, in document order and continuously across the documents of a batch (\tscodeinline{ResolveOptions.numbering: all}), and both writers print those numbers in the cross-references: \tscodeinline{\textbackslash{}hyperref[tbl:one]\{Table\textasciitilde{}1\}} in the \tscodeinline{.tex}, \tscodeinline{\#link(<tbl:one>)[Table 1]} in the \tscodeinline{.typ}, identical on both backends. Only labelled items (a caption with \tscodeinline{\{\#fig:x\}}) take a number; the float's own caption is still numbered by the backend, so use \tscodeinline{tmark} numbering where the two must agree (the web profile, a site built page by page) and keep \tscodeinline{backend} for a print-only document with chapter-scoped numbers. User counters declared under \tscodeinline{press.declare.counters} are always TMark-numbered, whatever the mode.
\end{description}
\section{Quick Start}
\begin{tscode}[lang=bash, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{c+c1}{\PYZsh{} Generate LaTeX fragments from Markdown}
texsmith\PY{+w}{ }intro.md\PY{+w}{ }\PYZhy{}\PYZhy{}output\PY{+w}{ }build/

\PY{c+c1}{\PYZsh{} Render with a template and compile to PDF (default = Tectonic)}
texsmith\PY{+w}{ }intro.md\PY{+w}{ }\PYZhy{}\PYZhy{}template\PY{+w}{ }article\PY{+w}{ }\PYZhy{}\PYZhy{}output\PYZhy{}dir\PY{+w}{ }build/pdf\PY{+w}{ }\PYZhy{}\PYZhy{}build

\PY{c+c1}{\PYZsh{} Inspect bibliography sources}
texsmith\PY{+w}{ }references.bib\PY{+w}{ }\PYZhy{}\PYZhy{}list\PYZhy{}bibliography
\end{Verbatim}
\end{tscode}
Refer to \tscodeinline{texsmith COMMAND -\allowbreak{}-\allowbreak{}help} whenever you need the most up-to-date option list, defaults, and environment-specific notes.
\section{Diagnostics}
Every CLI invocation routes warnings, errors, and structured events through the \tscodeinline{DiagnosticEmitter} interface. The Typer app instantiates a \tscodeinline{CliEmitter}, so verbosity flags (\tscodeinline{-\allowbreak{}v}) control how much detail reaches your terminal. Library consumers can provide their own emitter to capture the same diagnostics programmatically when embedding TeXSmith.
