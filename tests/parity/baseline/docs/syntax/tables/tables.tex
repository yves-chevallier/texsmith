\title{Tables}
\author{}\date{}
\begin{document}
\maketitle
Markdown pipe tables are cute until they meet real reports. The minute you
need grouped headers, wrapped text, row spans, totals, or a table that behaves
properly in \LaTeX{}, plain Markdown turns into duct tape. TeXSmith keeps the
simple syntax for simple tables and adds a declarative \tscodeinline{yaml table} fence for
the serious stuff.

Use the right level of power:
\begin{itemize}
\item Plain Markdown table: quick two-dimensional data, no layout drama.
\item Plain Markdown table + \tscodeinline{yaml table-\allowbreak{}config}: keep the pipe table, add \LaTeX{}
layout metadata.
\item \tscodeinline{yaml table}: describe the whole table as structured data when spans,
grouped headers, footers, or validation matter.
\end{itemize}
\section{Captions and Labels}
Put the standard TeXSmith caption line directly after the table:
\begin{tscode}[lang=markdown, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{l+s+sb}{```}\PY{l+s+sb}{yaml}\PY{+w}{ }table
\PY{n+nt}{columns}\PY{p}{:}\PY{+w}{ }\PY{p+pIndicator}{[}\PY{n+nv}{Fruit}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{Geneva}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{Zurich}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{Basel}\PY{p+pIndicator}{]}
\PY{n+nt}{rows}\PY{p}{:}
\PY{+w}{  }\PY{p+pIndicator}{\PYZhy{}}\PY{+w}{ }\PY{p+pIndicator}{[}\PY{n+nv}{Apples}\PY{p+pIndicator}{,}\PY{+w}{   }\PY{n+nv}{120}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{180}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{90}\PY{p+pIndicator}{]}
\PY{+w}{  }\PY{p+pIndicator}{\PYZhy{}}\PY{+w}{ }\PY{p+pIndicator}{[}\PY{n+nv}{Pears}\PY{p+pIndicator}{,}\PY{+w}{    }\PY{n+nv}{45}\PY{p+pIndicator}{,}\PY{+w}{  }\PY{n+nv}{\PYZti{}}\PY{p+pIndicator}{,}\PY{+w}{   }\PY{n+nv}{110}\PY{p+pIndicator}{]}

\end{Verbatim}

The \tscodeinline{\{\#tbl:stock\}} part becomes the \LaTeX{} \tscodeinline{\textbackslash{}label\{tbl:stock\}}, and \tscodeinline{@tbl:stock}
refers to it. The caption line works the same on a plain Markdown table. Its
canonical position is \textbf{after} the block --- after the \tscodeinline{table-\allowbreak{}config} fence when
there is one --- and a \tscodeinline{Table:} line before the table stays accepted for Pandoc
compatibility (see \href{captions.md\#caption-lines-in-detail}{captions} for the
attachment rule).

\begin{center}
\begin{tabularx}{\linewidth}{>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X}
\toprule
\textbf{Key} & \textbf{Purpose} \\
\midrule
\tscodeinline{table} & Optional table-level settings: width, placement, long-table mode. \\
\tscodeinline{columns} & Required column tree. Needs at least two leaf columns. \\

The first column is the row-label column. In positional rows, the first item
becomes that label and the remaining items fill the data columns.

\tscodeinline{\textasciitilde{}} is YAML null. In normal cells it renders as empty. In span rectangles it
is also the explicit ``this slot is absorbed'' marker, so the validator knows
you meant it.

\end{Verbatim}

Width rules:
\begin{itemize}
\item \tscodeinline{table.width: auto} means natural table width.
\item \tscodeinline{table.width: 100\%} means \tscodeinline{\textbackslash{}linewidth}; other percentages scale from it.
\item \tscodeinline{width: X} marks a column as the flexible \tscodeinline{tabularx} column.
\item \tscodeinline{width: auto} on a column is also treated as a flexible \tscodeinline{X} column.
\item \tscodeinline{width-\allowbreak{}group: quarter} makes all matching columns equal-width \tscodeinline{X} columns
when no explicit width is supplied.
\item Raw strings such as \tscodeinline{2.5cm} are passed through as \LaTeX{} lengths.
\end{itemize}

\begin{tscode}[lang=yaml, engine=pygments]

\section{Validation Errors}
The YAML table parser validates the table before the \LaTeX{} renderer sees it.
When something is wrong, TeXSmith emits an inline error block and keeps the
document buildable.

Common failures:
\begin{itemize}
\item Unknown top-level keys.
\item Missing \tscodeinline{columns}.
\item Rows with too many or too few cells.
\item Unknown column names in named-row mode.
\item Span rectangles whose absorbed slots are not \tscodeinline{\textasciitilde{}}.
\item Invalid alignment values.
\item Invalid percentage widths.
\end{itemize}
Example:
