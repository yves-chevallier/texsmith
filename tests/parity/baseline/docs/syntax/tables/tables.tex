\thispagestyle{plain}
Markdown pipe tables are cute until they meet real reports. The minute you
need grouped headers, wrapped text, row spans, totals, or a table that behaves
properly in \LaTeX{}, plain Markdown turns into duct tape. TeXSmith keeps the
simple syntax for simple tables and adds a declarative \texttt{yaml table} fence for
the serious stuff.

Use the right level of power:

\begin{itemize}
\item{} Plain Markdown table: quick two-dimensional data, no layout drama.
\item{} Plain Markdown table + \texttt{yaml table-\allowbreak{}config}: keep the pipe table, add LaTeX
  layout metadata.
\item{} \texttt{yaml table}: describe the whole table as structured data when spans,
  grouped headers, footers, or validation matter.

\end{itemize}
\section{Captions and Labels}\label{captions-and-labels}

Put the standard TeXSmith caption line directly after the table:

\begin{code}{markdown}{}{}
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{l+s+sb}{```}\PY{l+s+sb}{yaml}\PY{+w}{ }table
\PY{n+nt}{columns}\PY{p}{:}\PY{+w}{ }\PY{p+pIndicator}{[}\PY{n+nv}{Fruit}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{Geneva}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{Zurich}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{Basel}\PY{p+pIndicator}{]}
\PY{n+nt}{rows}\PY{p}{:}
\PY{+w}{  }\PY{p+pIndicator}{\PYZhy{}}\PY{+w}{ }\PY{p+pIndicator}{[}\PY{n+nv}{Apples}\PY{p+pIndicator}{,}\PY{+w}{   }\PY{n+nv}{120}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{180}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{90}\PY{p+pIndicator}{]}
\PY{+w}{  }\PY{p+pIndicator}{\PYZhy{}}\PY{+w}{ }\PY{p+pIndicator}{[}\PY{n+nv}{Pears}\PY{p+pIndicator}{,}\PY{+w}{    }\PY{n+nv}{45}\PY{p+pIndicator}{,}\PY{+w}{  }\PY{n+nv}{\PYZti{}}\PY{p+pIndicator}{,}\PY{+w}{   }\PY{n+nv}{110}\PY{p+pIndicator}{]}
\PY{l+s+sb}{```}

Table: Fruit stock by warehouse \PYZob{}\PYZsh{}tbl:stock\PYZcb{}
\end{Verbatim}
\end{code}
The \texttt{\{\#tbl:stock\}} part becomes the \LaTeX{} \texttt{\textbackslash{}label\{tbl:stock\}} and can be
referenced like any other table. The caption line also works with plain
Markdown tables, and the line placed \emph{before} the table is accepted as well
(see \hyperref[caption-lines]{captions} for the attachment rule).

Top-level keys:

\begin{center}
\begin{tabularx}{\linewidth}{>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X}
\toprule

\midrule
\texttt{table} & Optional table-level settings: width, placement, long-table mode. \\

The first column is the row-label column. In positional rows, the first item
becomes that label and the remaining items fill the data columns.

\texttt{\textasciitilde{}} is YAML null. In normal cells it renders as empty. In span rectangles it
is also the explicit ``this slot is absorbed'' marker, so the validator knows
you meant it.

\section{Columns}\label{columns}

The short form is just a list of names:

\begin{code}{yaml}{}{}
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{n+nt}{columns}\PY{p}{:}\PY{+w}{ }\PY{p+pIndicator}{[}\PY{n+nv}{Article}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{Editor}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{Status}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{Pages}\PY{p+pIndicator}{]}
\end{Verbatim}
\end{code}
For metadata, use mappings:

\begin{code}{yaml}{}{}

\PY{+w}{  }\PY{p+pIndicator}{\PYZhy{}}\PY{+w}{ }\PY{n+nt}{name}\PY{p}{:}\PY{+w}{ }\PY{l+lScalar+lScalarPlain}{Description}

\end{Verbatim}
\end{code}
Column attributes:

\begin{center}
\begin{tabularx}{\linewidth}{>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X}
\toprule
\textbf{Attribute} & \textbf{Values} \\

\midrule
\texttt{align} & \texttt{l}, \texttt{c}, \texttt{r}, \texttt{j}, or long forms: \texttt{left}, \texttt{center}, \texttt{centre}, \texttt{right}, \texttt{justify}, \texttt{justified}. \\

\bottomrule
\end{tabularx}
\end{center}

Grouped columns are recursive:

\begin{code}{yaml}{}{}

\PY{+w}{    }\PY{n+nt}{width\PYZhy{}group}\PY{p}{:}\PY{+w}{ }\PY{l+lScalar+lScalarPlain}{quarter}
\PY{+w}{  }\PY{p+pIndicator}{\PYZhy{}}\PY{+w}{ }\PY{n+nt}{name}\PY{p}{:}\PY{+w}{ }\PY{l+lScalar+lScalarPlain}{FY24}
\PY{+w}{    }\PY{n+nt}{columns}\PY{p}{:}\PY{+w}{ }\PY{p+pIndicator}{[}\PY{n+nv}{Q1}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{Q2}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{Q3}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{Q4}\PY{p+pIndicator}{]}

Groups can carry \texttt{align}, \texttt{width}, and \texttt{width-\allowbreak{}group}; those attributes
propagate to their leaf columns unless a child overrides them. Nested groups
produce multiple header rows and \texttt{\textbackslash{}cmidrule} strokes in \LaTeX{}.

\end{Verbatim}

Width rules:

\begin{itemize}
\item{} \texttt{table.width: auto} means natural table width.
\item{} \texttt{table.width: 100\%} means \texttt{\textbackslash{}linewidth}; other percentages scale from it.
\item{} \texttt{width: X} marks a column as the flexible \texttt{tabularx} column.
\item{} \texttt{width: auto} on a column is also treated as a flexible \texttt{X} column.
\item{} \texttt{width-\allowbreak{}group: quarter} makes all matching columns equal-width \texttt{X} columns
  when no explicit width is supplied.
\item{} Raw strings such as \texttt{2.5cm} are passed through as LaTeX lengths.

\end{itemize}

\begin{code}{yaml}{}{}
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]

\end{Verbatim}
\end{code}

\section{Validation Errors}\label{validation-errors}

The YAML table parser validates the table before the \LaTeX{} renderer sees it.
When something is wrong, TeXSmith emits an inline error block and keeps the
document buildable.

Common failures:

\begin{itemize}
\item{} Unknown top-level keys.
\item{} Missing \texttt{columns}.
\item{} Rows with too many or too few cells.
\item{} Unknown column names in named-row mode.
\item{} Span rectangles whose absorbed slots are not \texttt{\textasciitilde{}}.
\item{} Invalid alignment values.
\item{} Invalid percentage widths.

\end{itemize}
Example:

\begin{code}{markdown}{}{}
