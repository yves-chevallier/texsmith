\maketitle
If Markdown is new to you, start with the \href{https://www.markdownguide.org/basic-syntax/}{canonical guide}.

The original spec is spartan---tables, diagrams, and other niceties didn't exist.

Over time new \emph{flavours} sprouted to fill the gaps. For printed documentation,
especially for scientific or technical reports, more is required still:
\begin{itemize}
\item Citations and bibliographies
\item Cross-references
\item Diagrams (Mermaid, draw.io, Vega)
\item Mathematical formulas (\LaTeX{} math)
\item Index
\item Glossary and acronyms
\item Rich tables (spans, multi-line cells, grouped headers)
\item Raw passthrough to one backend without polluting the others
\end{itemize}
\textbf{TMark} (TeXSmith Markdown) is the dialect TeXSmith reads: CommonMark, plus
the extension set every MkDocs site already loads, plus exactly four syntactic
families for everything print needs. It has a
\href{https://github.com/yves-chevallier/tmark}{specification}, a parser, a printer
and a linter, and one canonical spelling per construct.
\section{Markdown is a mess}
So many flavours, so many extensions, so many incompatible syntaxes---it's a jungle. CommonMark tried to herd the cats and mostly succeeded, but fragmentation remains. MyST brought Sphinx-style goodies to Markdown, yet it isn't MkDocs-compatible, so TeXSmith had to chart its own course.
\begin{figure}[H]
\centering
\href{https://imgs.xkcd.com/comics/standards.png}{\includegraphics[width=0.6\linewidth]{standards.pdf}}
\caption{How Standards Proliferate}
\end{figure}
Source: xkcd\footnote{\href{https://xkcd.com/927/}{xkcd:927}}.

TMark's answer is not another pile of extensions: it is a closed set of rules,
so that a construct you have never seen can still be read.
\section{Four syntactic families}
Beyond core CommonMark (headings, paragraphs, lists, quotes, emphasis, links,
images, fenced code), TMark adds exactly four families. Every construct on the
following pages is an instance of one of them.

\textbf{Attributes} decorate the element before them.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{g+gu}{\PYZsh{}\PYZsh{} Boot sequence \PYZob{}\PYZsh{}sec:boot\PYZcb{}}

![\PY{n+nt}{Trace}](\PY{n+na}{trace.png})\PYZob{}width=60\PYZpc{}\PYZcb{}
\end{Verbatim}
\end{tscode}
A brace group holds \tscodeinline{\#id}, \tscodeinline{.class} and \tscodeinline{key=value} items, separated by spaces;
values with spaces are double-quoted. There are no bare-word attributes: write
\tscodeinline{\{collapsed=true\}}, not \tscodeinline{\{collapsed\}}. Attributes need a host; where you want
them on a piece of running text, wrap it in a span: \tscodeinline{[this claim]\{\#claim:one\}}.

\textbf{Roles} create semantic inline nodes; the name comes before the content.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PYZob{}index\PYZcb{}[endianness] \PYZob{}aside\PYZcb{}[see Prandtl 1921] \PYZob{}raw latex\PYZcb{}(\PYZbs{}clearpage)

\PYZob{}include\PYZcb{}(chapter.md)
\end{Verbatim}
\end{tscode}
Brackets and parentheses follow the rule Markdown links already apply in
\tscodeinline{[content](argument)}: brackets hold \textbf{content}, parsed as Markdown and read by
the reader; parentheses hold a verbatim \textbf{argument} the processor consumes.
\tscodeinline{\{aside\}[see **Prandtl**]} is content; \tscodeinline{\{raw latex\}(\textbackslash{}textbf\{x\})} and
\tscodeinline{\{include\}(chapter.md)} are arguments, and nothing inside them is ever
Markdown.

\textbf{Container directives} hold Markdown.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
::: figure \PYZob{}cols=2\PYZcb{}
![\PY{n+nt}{Boot}](\PY{n+na}{boot.png})
![\PY{n+nt}{Crash}](\PY{n+na}{crash.png})

Figure: Watchdog traces. \PYZob{}\PYZsh{}fig:traces\PYZcb{}
:::
\end{Verbatim}
\end{tscode}
Nesting is by fence length (\tscodeinline{::::} outside \tscodeinline{:::}), as in Pandoc. The container
names TMark knows are a \textbf{closed registry} --- the callout types, \tscodeinline{aside},
\tscodeinline{figure}, \tscodeinline{tabs}, \tscodeinline{tab}, \tscodeinline{multicolumn \{cols=\}} and \tscodeinline{div} --- so an unknown name
raises \tscodeinline{container-\allowbreak{}unknown} and renders its content transparently, and a
template that needs a new look uses \tscodeinline{::: div \{.class\}} rather than a new name.
A \textbf{dotted} \tscodeinline{::: pkg.module} line is not a container at all but a foreign
directive, kept verbatim and dropped in print.

\textbf{Data directives} hold non-Markdown content in a fenced code block whose info
string is \tscodeinline{<lang> <node>}. The second word names the node the fence produces and
defaults to \tscodeinline{code}, so an ordinary code block is the degenerate case.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{l+s+sb}{```}\PY{l+s+sb}{python}\PY{+w}{ }image
\PY{k+kn}{import}\PY{+w}{ }\PY{n+nn}{matplotlib}\PY{n+nn}{.}\PY{n+nn}{pyplot}\PY{+w}{ }\PY{k}{as}\PY{+w}{ }\PY{n+nn}{plt}
\PY{n}{plt}\PY{o}{.}\PY{n}{plot}\PY{p}{(}\PY{p}{[}\PY{l+m+mi}{1}\PY{p}{,} \PY{l+m+mi}{2}\PY{p}{,} \PY{l+m+mi}{4}\PY{p}{,} \PY{l+m+mi}{8}\PY{p}{]}\PY{p}{)}
\PY{n}{plt}\PY{o}{.}\PY{n}{savefig}\PY{p}{(}\PY{l+s+s2}{\PYZdq{}}\PY{l+s+s2}{out.pdf}\PY{l+s+s2}{\PYZdq{}}\PY{p}{)}
\PY{l+s+sb}{```}

\PY{l+s+sb}{```}\PY{l+s+sb}{yaml}\PY{+w}{ }table
\PY{n+nt}{columns}\PY{p}{:}\PY{+w}{ }\PY{p+pIndicator}{[}\PY{n+nv}{A}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{B}\PY{p+pIndicator}{]}
\PY{n+nt}{rows}\PY{p}{:}\PY{+w}{ }\PY{p+pIndicator}{[}\PY{p+pIndicator}{[}\PY{n+nv}{1}\PY{p+pIndicator}{,}\PY{+w}{ }\PY{n+nv}{2}\PY{p+pIndicator}{]}\PY{p+pIndicator}{]}
\PY{l+s+sb}{```}
\end{Verbatim}
\end{tscode}
The node words are \tscodeinline{code}, \tscodeinline{table}, \tscodeinline{table-\allowbreak{}config}, \tscodeinline{image} and \tscodeinline{raw}.
\section{Two sigils}
TMark reserves two inline sigils, each with one meaning.
\begin{center}
\begin{tabularx}{\linewidth}{>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X}
\toprule
\textbf{Sigil} & \textbf{Meaning} & \textbf{In braces (attribute)} & \textbf{Before brackets (node)} \\
\midrule
\tscodeinline{\#} & define & \tscodeinline{\{\#id\}} names an existing host element & \tscodeinline{\#[term]} an index entry (content), \tscodeinline{\#(fw:key)} a counter item (argument) \\
\tscodeinline{@} & refer & (none) & \tscodeinline{@key} bare, \tscodeinline{@[key …]} bracketed \\
\bottomrule
\end{tabularx}
\end{center}
\textbf{\tscodeinline{\#} defines, \tscodeinline{@} refers} is the mnemonic the whole reference system hangs on.
\tscodeinline{@} resolves against named registries: a declared counter prefix, \tscodeinline{gls:} for the
glossary, \tscodeinline{doi:} for a DOI, and otherwise the bibliography. Both sigils are
guarded --- \tscodeinline{@} never fires inside a word, an e-mail address or a URL, and \tscodeinline{\#[}
or \tscodeinline{\#(} followed by a non-space does not occur in prose --- and both escape with
a backslash: \tscodeinline{\textbackslash{}@}, \tscodeinline{\textbackslash{}\#}.
\section{Degradation classes}
Every construct says what a renderer \emph{other} than TeXSmith shows for the same
bytes.
\begin{description}
\item[{C, compatible}] Renders identically in CommonMark and GFM.
\item[{E, extension-compatible}] Not CommonMark, but identical under the standard extension set every MkDocs
and Python-Markdown site already loads.
\item[{D, degrades}] Foreign renderers show something readable but unstyled: a code block, a
literal \tscodeinline{!!! note} line, a \tscodeinline{Table:} paragraph.
\item[{X, diverges}] The same bytes \emph{mean something else} in GFM. There are five, and they are
listed below.
\end{description}
\begin{center}
\begin{tabularx}{\linewidth}{>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X}
\toprule
\textbf{\#} & \textbf{Syntax} & \textbf{GFM meaning} & \textbf{TMark meaning} \\
\midrule
X1 & \tscodeinline{\_\_text\_\_} & bold & small caps \\
X2 & \tscodeinline{-\allowbreak{}-\allowbreak{}-\allowbreak{}} & horizontal rule & divider; a page break in paged media \\
X3 & \tscodeinline{\textasciitilde{}x\textasciitilde{}} & strikethrough & subscript \\
X4 & \tscodeinline{@word} & literal & reference or citation \\
X5 & \tscodeinline{\#[…]}, \tscodeinline{\#(…)} & literal & index entry, counter item \\
\bottomrule
\end{tabularx}
\end{center}
X1 and X2 are disabled by the \tscodeinline{strict} profile, for teams that co-render their
sources on GitHub.

\section{Raw passthrough}
Escape hatches are explicit, backend-tagged and invisible to other backends.
They are all spelled with the one word \tscodeinline{raw}.

Block form --- a data directive whose node word is \tscodeinline{raw}:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{l+s+sb}{```}\PY{l+s+sb}{latex}\PY{+w}{ }raw
\PY{k}{\PYZbs{}newcommand}\PY{n+nb}{\PYZob{}}\PY{k}{\PYZbs{}R}\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}\PY{k}{\PYZbs{}mathbb}\PY{n+nb}{\PYZob{}}R\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZcb{}}
\PY{l+s+sb}{```}
\end{Verbatim}
\end{tscode}
Inline form --- a role whose payload is an argument, hence the parentheses:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
Section break \PYZob{}raw latex\PYZcb{}(\PYZbs{}clearpage) before the next topic.
\end{Verbatim}
\end{tscode}
\tscodeinline{typst raw} / \tscodeinline{\{raw typst\}(…)} and \tscodeinline{html raw} / \tscodeinline{\{raw html\}(…)} work the same
way. A \tscodeinline{latex raw} fence is ignored by the Typst and HTML backends, and vice
versa, which is precisely how one document targets three outputs.
\begin{tscallout}[kind=note, title={The 0.6 spellings are deprecated}]
\tscodeinline{/// latex … ///} and \tscodeinline{\{latex\}[…]} are still parsed with a deprecation
warning. \tscodeinline{tmark lint -\allowbreak{}-\allowbreak{}fix} rewrites both; see
Migrating to TMark.
\end{tscallout}
\section{Includes}
A block include is the \tscodeinline{include} role alone on its line; the path is an
argument.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PYZob{}include\PYZcb{}(chapters/boot.md)

\PYZob{}include base=chapters\PYZcb{}(boot.md)
\end{Verbatim}
\end{tscode}
The included file is parsed as TMark and its blocks are spliced into the
document, so a fenced block inside it is content and cannot close anything in
the including file. Relative paths inside it resolve against its own directory;
\tscodeinline{base=} overrides. Fenced code takes \tscodeinline{include="file"} on its info string
instead of inlining content.
\begin{tscallout}[kind=note, title={\tscodeinline{-\allowbreak{}-\allowbreak{}8<-\allowbreak{}-\allowbreak{} \textbackslash{}"file\textbackslash{}"} is deprecated}]
The PyMdownX snippet syntax is accepted as sugar. It pastes text \emph{before}
parsing, which breaks on nested fences, and it never rebases paths.
\tscodeinline{tmark lint -\allowbreak{}-\allowbreak{}fix} rewrites it to \tscodeinline{\{include\}(file)}.
\end{tscallout}
