Code fences are one of Markdown's greatest hits: drop a triple backtick block,
label it, and you get nicely formatted snippets. A fenced code block is the
degenerate case of TMark's \href{index.md\#four-syntactic-families}{data-directive family}:
its info string is \tscodeinline{<lang> <node>}, and the node word defaults to \tscodeinline{code}.
\section{Code Blocks}
You can insert code snippets and specify options in the info string.
\begin{itemize}
\item Line numbers with \tscodeinline{linenums="1"}
\item Title with \tscodeinline{title="filename.ext"}
\item Highlight specific lines with \tscodeinline{hl\_lines="2-\allowbreak{}3"}
\item An external source with \tscodeinline{include="path/to/file"}
\end{itemize}
The info string may also end with a full attribute list in braces, which is
where a class or an id lives:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{l+s+sb}{```}\PY{l+s+sb}{python}\PY{+w}{ }\PYZob{}.wide title=\PYZdq{}hanoi.py\PYZdq{}\PYZcb{}
\PY{n+nb}{print}\PY{p}{(}\PY{l+m+mi}{1}\PY{p}{)}
\PY{l+s+sb}{```}
\end{Verbatim}
\end{tscode}
The highlighting engine is global, set with \tscodeinline{press.code.engine}: \tscodeinline{pygments}
(the default, Tectonic-safe), \tscodeinline{listings}, \tscodeinline{verbatim} or \tscodeinline{minted} (which needs
shell escape).

\subsection{External sources}
Put \tscodeinline{include=} on the info string to read the code from a file at render time,
keeping samples reusable across docs. The file is never pasted into the source,
so a fence inside it is just text.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{l+s+sb}{```}\PY{l+s+sb}{python}\PY{+w}{ }include=\PYZdq{}examples/code/bubble\PYZus{}sort.py\PYZdq{} title=\PYZdq{}bubble\PYZus{}sort.py\PYZdq{}
\PY{l+s+sb}{```}
\end{Verbatim}
\end{tscode}
To splice a whole Markdown file into the document instead, use the \tscodeinline{include}
role on a line of its own:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PYZob{}include\PYZcb{}(examples/code/bubble\PYZus{}sort.md)
\end{Verbatim}
\end{tscode}
The PyMdownX snippet syntax \tscodeinline{-\allowbreak{}-\allowbreak{}8<-\allowbreak{}-\allowbreak{} "file"} is accepted as deprecated sugar; it
pastes text before parsing, which breaks on nested fences, and it never rebases
relative paths. See Migrating to TMark.
\subsubsection{Any dash count is the same marker}
The marker is PyMdownX's own, \tscodeinline{-\allowbreak{}\{2,\}8<-\allowbreak{}\{2,\}}: \textbf{two or more dashes on each
side, the two sides free to differ}. \tscodeinline{-\allowbreak{}-\allowbreak{}8<-\allowbreak{}-\allowbreak{}}, \tscodeinline{-\allowbreak{}-\allowbreak{}-\allowbreak{}8<-\allowbreak{}-\allowbreak{}-\allowbreak{}}, \tscodeinline{-\allowbreak{}-\allowbreak{}8<-\allowbreak{}-\allowbreak{}-\allowbreak{}-\allowbreak{}} and
\tscodeinline{-\allowbreak{}-\allowbreak{}-\allowbreak{}-\allowbreak{}-\allowbreak{}8<-\allowbreak{}-\allowbreak{}-\allowbreak{}-\allowbreak{}-\allowbreak{}} are one spelling, and none of them is a divider. This matters
because TeXSmith's own corpus writes three dashes throughout: for a long time
only the two-dash form was recognised, so every one of those includes quietly
stayed literal text.

A \tscodeinline{;} before the marker is PyMdownX's escape: the line includes nothing and is
the text it spells, less one \tscodeinline{;}, with no diagnostic --- writing the marker is
not the deprecated act. The rule holds for a fence whose body is one snippet
line, and there the \tscodeinline{;} is also what the printer writes, a fence body having no
backslash escape of its own; in a paragraph the printer escapes the literal
marker with a backslash instead.

\section{Inline Code}
You can also include inline code snippets using backticks \tscodeinline{`} like this:
\subsection{Unformatted}
\begin{tscode}[lang=markdown, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
To sort a list in Python, you can use the \PY{l+s+sb}{`sorted()`} function.
\end{Verbatim}
\end{tscode}
It will simply be rendered as monospaced text in \LaTeX{}:
\begin{tscode}[lang=text, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
To sort a list in Python, you can use the \PYZbs{}texttt\PYZob{}sorted()\PYZcb{} function.
\end{Verbatim}
\end{tscode}
\subsection{Highlighted}
Inline code can also be highlighted. The canonical spelling is the \tscodeinline{code} role,
whose positional argument is the language; the PyMdownX \tscodeinline{\#!lang} shebang is
sugar for the same node.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
You can use \PYZob{}code py\PYZcb{}[print(\PYZdq{}Hello, World!\PYZdq{})] to display a message in Python.

You can use \PY{l+s+sb}{`\PYZsh{}!py print(\PYZdq{}Hello, World!\PYZdq{})`} to display a message in Python.
\end{Verbatim}
\end{tscode}
With TeXSmith this example renders as follows:
\begin{tscode}[lang=markdown, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{g+gh}{\PYZsh{} Inline Code}

In C the \PY{l+s+sb}{`strstr`} function defined with the prototype
\PYZob{}code lang=c\PYZcb{}[char \PY{g+ge}{*strstr(const char *}haystack, const char *needle);] is
used to locate a substring within a string. It returns a pointer to the first occurrence of the substring
\PY{l+s+sb}{`needle`} in the string \PY{l+s+sb}{`haystack`}, or \PY{l+s+sb}{`NULL`} if the substring is not found.

In Python, you can achieve similar functionality using the \PY{l+s+sb}{`find`} method of strings for example: \PYZob{}code lang=python\PYZcb{}[haystack.find(sub: int) \PYZhy{}\PYZgt{} int]. This method returns the lowest index of the substring if found in the string, otherwise it returns \PY{l+s+sb}{`\PYZhy{}1`}.
\end{Verbatim}
\end{tscode}
