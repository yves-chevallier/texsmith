TMark has \textbf{one sigil for referring}: \tscodeinline{@}. Whatever the target --- a section, a
figure, a table, an equation, a custom counter, a glossary term, a bibliography
entry, another document --- you write \tscodeinline{@key}, and the registry the key belongs to
decides what the reference renders as.

The mnemonic is short: \textbf{\tscodeinline{\#} defines, \tscodeinline{@} refers.}

We define several types of references that can be used throughout the documentation:
\begin{description}
\item[{Internal References}] Links that point to other sections within the same document or to other documents within the same project.
\item[{External References}] Links that point to resources outside of the current project, such as websites or external documents.
\item[{Bibliographic References}] Citations that refer to external publications, articles, or books. They are formatted using a citation style (APA, MLA, ...) and gather into a bibliography.
\item[{Footnotes}] Additional information parked at the bottom of the page, marked with a superscript number.
\item[{Equations, Tables, Figures, Listings}] Numbered floats with an anchor, referenced by their key.
\item[{Tags/Index}] Keywords associated with a section or topic, gathered into a printed index.
\end{description}
\section{The two forms of \tscodeinline{@}}
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{n+ni}{@sec:intro}                   bare, in\PYZhy{}text: \PYZdq{}section 2\PYZdq{}
\PY{n+ni}{@Sec:intro}                   capitalised prefix, for the start of a sentence
@[fig:boot; fig:crash]       grouped → \PYZdq{}figures 1 and 2\PYZdq{}
@[tbl:stock, column 3]       with a suffix → \PYZdq{}table 4, column 3\PYZdq{}
[](\PYZsh{}sec:intro)               empty\PYZhy{}link form, for pure\PYZhy{}Markdown toolchains
[](other.md)                 section number of another document\PYZsq{}s main heading
\end{Verbatim}
\end{tscode}
The brackets follow the sigil and are \textbf{optional}: a bare \tscodeinline{@key} takes one word
of \tscodeinline{[A-\allowbreak{}Za-\allowbreak{}z0-\allowbreak{}9\_:.-\allowbreak{}]} and ends on an alphanumeric, so trailing sentence
punctuation stays out (\tscodeinline{…voir @sec:intro.} references \tscodeinline{sec:intro}). The
bracketed form is required as soon as the reference contains a space --- a
locator, a suffix, or several keys separated by \tscodeinline{;}.

E-mail addresses, URLs and \tscodeinline{@} inside a word never match; write \tscodeinline{\textbackslash{}@} to force a
literal \tscodeinline{@} where the sigil would otherwise fire. An unresolved reference
renders visibly as \tscodeinline{[?key]} and warns.
\section{Internal References}
You can reference another section in the same document or cross-link to other files in the project.

Linking to another file? TeXSmith targets the destination's main heading and drops a proper hyperlink---handy for navigation-friendly PDFs without any manual tinkering.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
See the [\PY{n+nt}{Code Examples}](\PY{n+na}{code.md}) for more details.
\end{Verbatim}
\end{tscode}
Skip the link text and TeXSmith injects the section number for the print build automatically.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
See the section [](code.md) for more details.
\end{Verbatim}
\end{tscode}
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{g+gu}{\PYZsh{}\PYZsh{} Section Title \PYZob{}\PYZsh{}sec:section\PYZhy{}title\PYZcb{}}

Placeholder text that other sections can reference.

\PY{g+gu}{\PYZsh{}\PYZsh{} Other Section}

Check \PY{n+ni}{@sec:section\PYZhy{}title} for more details.
\end{Verbatim}
\end{tscode}
A heading with no \tscodeinline{\{\#id\}} still has an \emph{implicit} id --- GitHub's slug of its
plain text --- so \tscodeinline{[](\#other-\allowbreak{}section)} resolves. Because that id changes whenever
the title is edited, referring to one raises the \tscodeinline{ref-\allowbreak{}implicit-\allowbreak{}id} hint: give
the heading an explicit \tscodeinline{\{\#sec:…\}}. See Headings for the slug
rule and for \tscodeinline{.unnumbered} / \tscodeinline{.unlisted}.
\subsection{Custom counters}
Document-specific series (findings, requirements, bugs) declared under
\tscodeinline{press.declare.counters} in the front matter reuse the very same \tscodeinline{@prefix:key}
form, resolving to their formatted number instead of a section number. See
Custom counters.
\subsection{Cross-document references}
\tscodeinline{@alias:key} resolves against another document's published inventory, declared
under \tscodeinline{press.sources.crossrefs} in the front matter. See
Cross-document references.
\subsection{Autorefs}
When the \tscodeinline{mkdocs-\allowbreak{}autorefs} extension is enabled, you can use the \tscodeinline{[text][label]} syntax to generate automatic references to headings.
\section{External References}
Reference external resources (HTTP/HTTPS) with vanilla Markdown link syntax:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]

You can also check our repository at https://github.com/yves\PYZhy{}chevallier/texsmith.
\end{Verbatim}
\end{tscode}

\begin{tscode}[lang=latex, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
For more information, visit the \PY{k}{\PYZbs{}href}\PY{n+nb}{\PYZob{}}https://texsmith.org\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}TeXSmith Website\PY{n+nb}{\PYZcb{}}.
You can also check our repository at \PY{k}{\PYZbs{}url}\PY{n+nb}{\PYZob{}}https://github.com/yves\PYZhy{}chevallier/texsmith\PY{n+nb}{\PYZcb{}}.
\end{Verbatim}
\end{tscode}
\section{Bibliographic References}
A citation is the same sigil against the bibliography registry. A bare \tscodeinline{@key}
is the \textbf{short, parenthetical} citation by default --- \tscodeinline{\textbackslash{}cite\{key\}} in \LaTeX{},
\tscodeinline{\#cite(<key>)} in Typst --- and \tscodeinline{@[key, locator]} is the same short form with a
locator attached.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PYZhy{}\PYZhy{}\PYZhy{}
press:
  sources:
    bibliography:
\PY{g+gu}{      ein05: https://doi.org/10.1002/andp.19053221004}
\PY{g+gu}{\PYZhy{}\PYZhy{}\PYZhy{}}

Einstein\PYZsq{}s theory of relativity revolutionized physics \PY{n+ni}{@ein05}.
As shown by @[ein05, p. 33], and elsewhere @[see ein05, pp. 33\PYZhy{}35].
\end{Verbatim}
\end{tscode}
Locators follow Pandoc: a recognised locator word (\tscodeinline{p.}, \tscodeinline{pp.}, \tscodeinline{ch.}, \tscodeinline{sec.},
\tscodeinline{§}...) followed by a range, or free suffix text.
\subsection{Narrative citations}
A document written in a narrative voice (\enquote{Einstein [3] showed...} rather than
\enquote{...was shown [3]}) switches its bare citations with the \tscodeinline{citations.narrative}
feature:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PYZhy{}\PYZhy{}\PYZhy{}
press:
  features:
\PY{g+gu}{    citations.narrative: true}
\PY{g+gu}{\PYZhy{}\PYZhy{}\PYZhy{}}

As \PY{n+ni}{@ein05} showed, the effect is real.
\end{Verbatim}
\end{tscode}
turns the bare \tscodeinline{@ein05} into \tscodeinline{\textbackslash{}textcite\{ein05\}} (\LaTeX{}) or
\tscodeinline{\#cite(<ein05>, form: "prose")} (Typst). The feature is document-wide, but
either form is always spellable per citation regardless of the switch: inside
brackets, a plain item stays short and parenthetical, \tscodeinline{@[+key]} forces the
narrative form, and \tscodeinline{@[-\allowbreak{}key]} forces the year alone (suppressing the author).
A locator still attaches to any of them, so \tscodeinline{@[+ein05, p. 33]} reads "Einstein
[3, p. 33]" even in a document whose bare keys are short.

A DOI can be cited in place through the predeclared \tscodeinline{doi} prefix, without a
front-matter entry: \tscodeinline{@doi:10.1002/andp.19053221004}.
\begin{tscallout}[kind=note, title={A key that starts with a digit needs the brackets}]
A bare \tscodeinline{@key} must begin with a letter, so the keys Zotero and Better
\tslogo{BibTeX} generate (\tscodeinline{1RgTv}, \tscodeinline{7HA7H}) are only reachable bracketed:
\tscodeinline{@[1RgTv]}. The printer writes such a key that way too, never bare. An
all-digit label stays a footnote.
\end{tscallout}
\begin{tscallout}[kind=note, title={The footnote spelling of a citation is deprecated}]
TeXSmith 0.6 spelled citations \tscodeinline{[\^{}key]} and \tscodeinline{\^{}[k1,k2]}, borrowing the
footnote syntax. Both are still accepted with a deprecation warning; once
they are retired, \tscodeinline{\^{}[…]} becomes an inline footnote (Pandoc's meaning).
\tscodeinline{tmark lint -\allowbreak{}-\allowbreak{}fix} rewrites them to \tscodeinline{@key} and \tscodeinline{@[k1; k2]}. Real footnotes
(\tscodeinline{[\^{}1]} with a definition) are untouched.
\end{tscallout}
See Bibliography management for the
sources, and Migrating to TMark for the rewrite.
\section{Footnotes}
Use footnotes to park side comments without cluttering the main text. Markdown marks them with superscript numbers; the rendered document moves the details to the bottom of the page or section.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
This is a sample sentence with a footnote.[\PYZca{}1]

[\PY{n+nl}{\PYZca{}1}]: \PY{n+na}{This is the footnote text that provides additional information.}
\end{Verbatim}
\end{tscode}
Footnotes are limited to one line in print---keep them tight.
\section{Equations}
Display math takes an anchor after the closing delimiter, Quarto-style, and is
referenced like any other numbered object:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PYZdl{}\PYZdl{}
E = mc\PYZca{}2
\PYZdl{}\PYZdl{} \PYZob{}\PYZsh{}eq:einstein\PYZcb{}

As shown in \PY{n+ni}{@eq:einstein}, energy is equal to mass times the speed of light
squared.
\end{Verbatim}
\end{tscode}
The \LaTeX{}-flavoured compatibility forms keep working: \tscodeinline{\textbackslash{}begin\{equation\}
\textbackslash{}label\{eq:x\} … \textbackslash{}end\{equation\}} inside \tscodeinline{\$\$}, referenced with \tscodeinline{\$\textbackslash{}eqref\{eq:x\}\$}.
\section{Figures}
Give a figure a caption line with an id and refer to it with \tscodeinline{@}:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
![\PY{n+nt}{Sample Figure}](\PY{n+na}{image\PYZhy{}url.jpg})

Figure: This is the caption for the figure. \PYZob{}\PYZsh{}fig:sample\PYZcb{}

As shown in \PY{n+ni}{@fig:sample}, the data illustrates…
\end{Verbatim}
\end{tscode}
The id is emitted verbatim as the \LaTeX{} \tscodeinline{\textbackslash{}label}. Both web and print outputs
number figures automatically, though the actual numbers may differ because each
layout floats content differently.
\section{Tables}
Tables take a caption line too; the canonical position is after the table.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
| Header 1 | Header 2 |
|\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}|\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}|
| Cell 1   | Cell 2   |

Table: A sample table for cross\PYZhy{}references. \PYZob{}\PYZsh{}tbl:sample\PYZcb{}

Check \PY{n+ni}{@tbl:sample} for more details.
\end{Verbatim}
\end{tscode}
\section{Code Block References}
A \tscodeinline{Listing:} caption line promotes a fenced code block to a numbered,
referenceable listing:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{l+s+sb}{```}\PY{l+s+sb}{python}\PY{+w}{ }title=\PYZdq{}bubble\PYZus{}sort.py\PYZdq{}
\PY{k}{def}\PY{+w}{ }\PY{n+nf}{bubble\PYZus{}sort}\PY{p}{(}\PY{n}{items}\PY{p}{)}\PY{p}{:} \PY{o}{.}\PY{o}{.}\PY{o}{.}
\PY{l+s+sb}{```}

Listing: Bubble sort, naive version. \PYZob{}\PYZsh{}lst:bubble\PYZcb{}

\PY{n+ni}{@lst:bubble} is quadratic in the worst case.
\end{Verbatim}
\end{tscode}
\section{Tags and Index Entries}
Add index entries to associate keywords with specific topics. Defining is the
other sigil:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
This section covers advanced sorting algorithms. \PYZsh{}[algorithm]
\end{Verbatim}
\end{tscode}
The canonical role form is \tscodeinline{\{index\}[algorithm]}; \tscodeinline{\#[…]} is its shorthand, and
both produce the same node. See Index / Tags for
nesting, main entries and named registries.
\section{Naming Conventions}
Before hypertext, references revolved around numbers: pages, figures, tables, equations.
\begin{tscode}[lang=text, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
1. Section

  Some Text

  Table 7: An example table
         +\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}+
         | Table |
         +\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}+

         +\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}+
         | Figure |
         +\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}\PYZhy{}+
  Figure 42: An example figure

2. Another Section

  See Table 7 for more details. The Figure 42 illustrates the concept.
  Everything is explained in Section 1.
\end{Verbatim}
\end{tscode}
The counter registry carries the label word per language, so the same \tscodeinline{@}
reference reads correctly in every locale.
\subsection{French}
In French, the reference type stays lowercase unless it begins the sentence.
\begin{displayquote}
Voir le tableau 7 pour plus de détails. La figure 42 illustre le concept.
Le tout est expliqué à la section 1.
\end{displayquote}
\subsection{English}
In English we capitalize the reference type and skip the article (``Table 7,'' not ``the Table 7'').
\begin{displayquote}
See Table 7 for more details. Figure 42 illustrates the concept.
Everything is explained in Section 1.
\end{displayquote}
\subsection{German}
German capitalizes the reference type too.
\begin{displayquote}
Siehe Tabelle 7 für weitere Details. Abbildung 42 veranschaulicht das Konzept.
Alles wird in Abschnitt 1 erklärt.
\end{displayquote}
