\title{Notes, asides, index and glossary}
\author{}\date{}
\begin{document}
\maketitle
This page collects the constructs that close the \LaTeX{}-sized gaps stock Markdown
leaves behind: index entries, asides, citations, theorems, the glossary and the
acronym list. They cooperate with MkDocs and MkDocs Material, and carry enough
structure for the paged writers to finish the job.
\begin{itemize}
\item Index entries double as Lunr tags in MkDocs and page references in \LaTeX{}.
\item Glossary entries and acronyms keep terminology consistent.
\item Citations and cross-references wire figures, tables, equations and
bibliography entries together.
\item Raw fences and roles let you sprinkle precise \TeX{} without polluting the web
build.
\end{itemize}
\section{Syntax at a glance}
The syntax follows a few rules: easy to type, friendly with standard Markdown
parsers, collision-free, and quiet in the raw text.
\begin{description}
\item[{\tscodeinline{@key}, \tscodeinline{@[key, p. 3]}}] Refer. The registry the key belongs to decides what it renders as: a figure
becomes ``Figure 3'', a table ``Table 4'', a section ``Section 2'', a
bibliography key a citation, \tscodeinline{@gls:term} a glossary reference.
\item[{\tscodeinline{\{index\}[term]} / \tscodeinline{\#[term]}}] Define an index entry. Invisible in the flow, a tag in Lunr, an \tscodeinline{\textbackslash{}index\{\}}
entry in \LaTeX{}.
\item[{\tscodeinline{\#(prefix:key)} / \tscodeinline{\{counter\}(prefix:key)}}] Define \emph{and print} a numbered item where no host element exists.
\item[{\tscodeinline{\{aside\}[…]} / \tscodeinline{\{aside side=left\}[…]}}] A remark tangential to the flow. The print templates put it in the margin;
a web template may render a sidebar.
\item[{\tscodeinline{[\^{}1]} with a \tscodeinline{[\^{}1]: …} definition}] A real footnote, CommonMark's own spelling, untouched.
\end{description}
\begin{tscallout}[kind=note, title={0.6 spellings}]
\tscodeinline{\^{}[key]} / \tscodeinline{[\^{}key]} for citations, \tscodeinline{\{margin\}[…]\{l\}} for asides and
\tscodeinline{\{index:reg\}[…]\{b\}} for index options are still parsed with a deprecation
warning. \tscodeinline{tmark lint -\allowbreak{}-\allowbreak{}fix} rewrites them; the table is in
Migrating to TMark.
\end{tscallout}
\section{Index}
Printed indexes convey intent with typography:
\begin{itemize}
\item Normal text: the topic is discussed.
\item Italic: quick mention only.
\item Bold: this section focuses on the topic.
\item Nested entries: group related terms.
\end{itemize}
The canonical spelling is the \tscodeinline{index} role. Extra bracket groups nest (three
levels at most); \tscodeinline{main=true} marks the main topic (a bold page number);
\tscodeinline{registry=} files the entry under a named index, which is created on first use
and printed where the template chooses.
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
Do you know the Gulliver\PYZsq{}s Travels tale about the egg dispute? \PYZob{}index\PYZcb{}[endianness]

\PYZob{}index\PYZcb{}[*endianness*]

\PYZob{}index main=true\PYZcb{}[endianness]

\PYZob{}index\PYZcb{}[byte order][endianness]

\PYZob{}index registry=physics main=true\PYZcb{}[relativity]
\end{Verbatim}
\end{tscode}
Emphasis inside the term is content markup, so the italic form is simply
\tscodeinline{\{index\}[*term*]}. The shorthand \tscodeinline{\#[…]} is the same node:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
The device is little\PYZhy{}endian. \PYZsh{}[endianness]

\PY{g+gh}{\PYZsh{}[byte order][endianness]}
\end{Verbatim}
\end{tscode}
\section{Asides (margin notes)}
Drop a short remark out of the flow with the \tscodeinline{aside} role. \tscodeinline{side=} is a layout
hint of the same standing as \tscodeinline{width=} on an image; the default lives in
\tscodeinline{press.aside} (right in \tscodeinline{oneside}, outer in \tscodeinline{twoside}).
\begin{center}
\begin{tabularx}{\linewidth}{>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X}
\toprule
\textbf{\tscodeinline{side=}} & \textbf{Semantics} \\
\midrule
(none) & document default \\
\tscodeinline{left} & force the left margin (scoped \tscodeinline{\textbackslash{}reversemarginpar}) \\
\tscodeinline{right} & force the right margin \\
\tscodeinline{outer} & outer margin \\
\tscodeinline{inner} & inner margin \\
\bottomrule
\end{tabularx}
\end{center}
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
Hooke\PYZsq{}s law \PYZob{}aside\PYZcb{}[linear only at small strain] holds below the yield point,
but non\PYZhy{}linear effects \PYZob{}aside side=left\PYZcb{}[see \PY{g+gs}{**Prandtl 1921**} for the classical
derivation] dominate above it.
\end{Verbatim}
\end{tscode}
An aside has \textbf{zero width} in the flow: the whitespace on both sides collapses
to one space and disappears before punctuation, so
\tscodeinline{Je suis un chien \{aside\}[remarque].} renders as ``Je suis un chien.'' with the
note attached to the preceding word.

Longer asides are a container:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
::: aside
A \PY{g+gs}{**marginal note**} attached to the preceding paragraph.
:::
\end{Verbatim}
\end{tscode}
Inline Markdown inside the note (\tscodeinline{**bold**}, \tscodeinline{*italic*}, \tscodeinline{`code`},
\tscodeinline{[links](…)}) is preserved all the way to \LaTeX{}, where the node becomes
\tscodeinline{\textbackslash{}tsaside[side=left]\{…\}} from the \tscodeinline{ts-\allowbreak{}typesetting} fragment, over the
\tscodeinline{marginnote} package.
\subsection{Width}
Margin notes never bleed past the page edge. The fragment ships three defensive
layers alongside \tscodeinline{\textbackslash{}usepackage\{marginnote\}}:
\begin{enumerate}
\item \textbf{Geometry-aware clamp.} An \tscodeinline{\textbackslash{}AtBeginDocument} hook clamps
\tscodeinline{\textbackslash{}marginparwidth} to whatever horizontal space the document's geometry
actually reserves for the margin --- the smaller of the recto outer
margin and, in \tscodeinline{twoside} documents, the verso outer margin as well ---
minus \tscodeinline{\textbackslash{}marginparsep} and a 6 mm safety buffer.
\item \textbf{Line-breaker tolerance.} \tscodeinline{\textbackslash{}marginfont} includes \tscodeinline{\textbackslash{}sloppy},
\tscodeinline{\textbackslash{}emergencystretch=1em} and \tscodeinline{\textbackslash{}hyphenpenalty=50} so a long technical
word, URL or German compound hyphenates (or stretches inter-word
spacing) rather than poking past the margin box edge.
\item \textbf{Footnote-size body.} Notes default to \tscodeinline{\textbackslash{}footnotesize} so multi-word
notes still fit in narrow margins.
\end{enumerate}
That means a \tscodeinline{geometry} block like
\begin{tscode}[lang=yaml, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{n+nt}{press}\PY{p}{:}
\PY{+w}{  }\PY{n+nt}{geometry}\PY{p}{:}
\PY{+w}{    }\PY{n+nt}{left}\PY{p}{:}\PY{+w}{ }\PY{l+lScalar+lScalarPlain}{3cm}
\PY{+w}{    }\PY{n+nt}{right}\PY{p}{:}\PY{+w}{ }\PY{l+lScalar+lScalarPlain}{4cm}
\end{Verbatim}
\end{tscode}
automatically yields notes that fit on both recto and verso pages --- no
manual \tscodeinline{marginparwidth=…} tweak needed.
\subsection{Font size}
Because printed margins are narrow, asides default to \tscodeinline{\textbackslash{}footnotesize} so
multi-word notes fit without overflowing. Override the default from your own
preamble if you want a different treatment:
\begin{tscode}[lang=latex, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{k}{\PYZbs{}renewcommand}\PY{k}{*}\PY{n+nb}{\PYZob{}}\PY{k}{\PYZbs{}marginfont}\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}\PY{k}{\PYZbs{}small}\PY{k}{\PYZbs{}itshape}\PY{n+nb}{\PYZcb{}}
\end{Verbatim}
\end{tscode}
\section{Citations}
Bibliographic references land in two ways:
\begin{enumerate}
\item Point TeXSmith at one or more \tscodeinline{.bib} files and cite entries with \tscodeinline{@key}.
\item Declare references directly in front matter via DOIs or inline metadata.
\end{enumerate}

\section{Math}
Inline math is \tscodeinline{\$…\$}; \tscodeinline{\textbackslash{}(…\textbackslash{})} is accepted as a \LaTeX{}-habit compatibility layer.
Display math is \tscodeinline{\$\$…\$\$}, with \tscodeinline{\textbackslash{}[…\textbackslash{}]} accepted the same way. Skip the space
right after the opening delimiter.

Numbered equations attach an anchor to the display block, Quarto-style:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PYZdl{}\PYZdl{}
a\PYZca{}2 + b\PYZca{}2 = c\PYZca{}2
\PYZdl{}\PYZdl{} \PYZob{}\PYZsh{}eq:pythagoras\PYZcb{}

From \PY{n+ni}{@eq:pythagoras}, we know that…
\end{Verbatim}
\end{tscode}
Equations have an anchor but no caption line: print never captions them.
\section{Theorems}
Theorem environments are callout types with a counter. \tscodeinline{theorem}, \tscodeinline{lemma},
\tscodeinline{corollary}, \tscodeinline{proposition}, \tscodeinline{definition} and \tscodeinline{proof} are predeclared (\tscodeinline{proof}
has no counter).
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
::: theorem \PYZob{}title=\PYZdq{}Pythagorean theorem\PYZdq{} \PY{n+ni}{\PYZsh{}thm:pythagoras}\PYZcb{}
This is a theorem about right triangles and can be summarized in the next
equation.

\PYZdl{}\PYZdl{} x\PYZca{}2 + y\PYZca{}2 = z\PYZca{}2 \PYZdl{}\PYZdl{}
:::

\PY{n+ni}{@thm:pythagoras} is the oldest of them all.
\end{Verbatim}
\end{tscode}
It renders as:
\begin{tscode}[lang=latex, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{k}{\PYZbs{}begin}\PY{n+nb}{\PYZob{}}theorem\PY{n+nb}{\PYZcb{}}[Pythagorean theorem]
\PY{k}{\PYZbs{}label}\PY{n+nb}{\PYZob{}}thm:pythagoras\PY{n+nb}{\PYZcb{}}
This is a theorem about right triangles and can be summarized in the next
equation.
\PY{l+s+sb}{\PYZbs{}[}\PY{n+nb}{ x}\PY{n+nb}{\PYZca{}}\PY{l+m}{2}\PY{n+nb}{ }\PY{o}{+}\PY{n+nb}{ y}\PY{n+nb}{\PYZca{}}\PY{l+m}{2}\PY{n+nb}{ }\PY{o}{=}\PY{n+nb}{ z}\PY{n+nb}{\PYZca{}}\PY{l+m}{2}\PY{n+nb}{ }\PY{l+s}{\PYZbs{}]}
\PY{k}{\PYZbs{}end}\PY{n+nb}{\PYZob{}}theorem\PY{n+nb}{\PYZcb{}}
\end{Verbatim}
\end{tscode}
Declare your own, and say whether it shares a series:
\begin{tscode}[lang=yaml, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{n+nt}{press}\PY{p}{:}
\PY{+w}{  }\PY{n+nt}{declare}\PY{p}{:}
\PY{+w}{    }\PY{n+nt}{admonitions}\PY{p}{:}
\PY{+w}{      }\PY{n+nt}{remark}\PY{p}{:}\PY{+w}{ }\PY{p+pIndicator}{\PYZob{}}\PY{n+nt}{name}\PY{p}{:}\PY{+w}{ }\PY{n+nv}{Remark}\PY{p+pIndicator}{,}\PY{n+nt}{ counter}\PY{p}{:}\PY{+w}{ }\PY{n+nv}{eq}\PY{p+pIndicator}{\PYZcb{}}\PY{+w}{   }\PY{c+c1}{\PYZsh{} Springer style: shares the equation counter}
\end{Verbatim}
\end{tscode}
\section{Glossary}
Specific terms live in the glossary; shorthand belongs in the acronym list. Keep
them separate so TeXSmith can decide when to expand, hyperlink, or index each
one.
\begin{description}
\item[{Glossary entries}] Definitions for full terms, whether single words or multi-word concepts.
\item[{Acronyms}] Shortened forms such as NASA or UNESCO, often with an expanded description.
\end{description}
Declare both under \tscodeinline{press.declare}:
\begin{tscode}[lang=yaml, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{n+nt}{press}\PY{p}{:}
\PY{+w}{  }\PY{n+nt}{declare}\PY{p}{:}
\PY{+w}{    }\PY{n+nt}{acronyms}\PY{p}{:}
\PY{+w}{      }\PY{n+nt}{nasa}\PY{p}{:}
\PY{+w}{        }\PY{n+nt}{name}\PY{p}{:}\PY{+w}{ }\PY{l+lScalar+lScalarPlain}{NASA}
\PY{+w}{        }\PY{n+nt}{description}\PY{p}{:}\PY{+w}{ }\PY{l+lScalar+lScalarPlain}{National}\PY{l+lScalar+lScalarPlain}{ }\PY{l+lScalar+lScalarPlain}{Aeronautics}\PY{l+lScalar+lScalarPlain}{ }\PY{l+lScalar+lScalarPlain}{and}\PY{l+lScalar+lScalarPlain}{ }\PY{l+lScalar+lScalarPlain}{Space}\PY{l+lScalar+lScalarPlain}{ }\PY{l+lScalar+lScalarPlain}{Administration}
\PY{+w}{      }\PY{n+nt}{unesco}\PY{p}{:}
\PY{+w}{        }\PY{n+nt}{name}\PY{p}{:}\PY{+w}{ }\PY{l+lScalar+lScalarPlain}{UNESCO}
\PY{+w}{        }\PY{n+nt}{description}\PY{p}{:}\PY{+w}{ }\PY{l+lScalar+lScalarPlain}{United}\PY{l+lScalar+lScalarPlain}{ }\PY{l+lScalar+lScalarPlain}{Nations}\PY{l+lScalar+lScalarPlain}{ }\PY{l+lScalar+lScalarPlain}{Educational,}\PY{l+lScalar+lScalarPlain}{ }\PY{l+lScalar+lScalarPlain}{Scientific}\PY{l+lScalar+lScalarPlain}{ }\PY{l+lScalar+lScalarPlain}{and}\PY{l+lScalar+lScalarPlain}{ }\PY{l+lScalar+lScalarPlain}{Cultural}\PY{l+lScalar+lScalarPlain}{ }\PY{l+lScalar+lScalarPlain}{Organization}
\PY{+w}{    }\PY{n+nt}{glossary}\PY{p}{:}
\PY{+w}{      }\PY{n+nt}{solid}\PY{p}{:}
\PY{+w}{        }\PY{n+nt}{name}\PY{p}{:}\PY{+w}{ }\PY{l+lScalar+lScalarPlain}{S.O.L.I.D.}
\PY{+w}{        }\PY{n+nt}{description}\PY{p}{:}\PY{+w}{ }\PY{p+pIndicator}{|}
\PY{+w}{          }\PY{n+no}{Acronym for five design principles intended to make software designs}
\PY{+w}{          }\PY{n+no}{more understandable, flexible, and maintainable.}
\PY{+w}{      }\PY{n+nt}{liskov}\PY{p}{:}

\PY{+w}{        }\PY{n+nt}{description}\PY{p}{:}\PY{+w}{ }\PY{p+pIndicator}{|}

\PY{+w}{          }\PY{n+no}{subclass without affecting the correctness of the program.}

A glossary entry is a referenceable object like any other, so it uses \tscodeinline{@} and
the predeclared \tscodeinline{gls} prefix:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
From the well\PYZhy{}known \PY{n+ni}{@gls:solid} principles, the following class must comply with
\PY{n+ni}{@gls:liskov}.
\end{Verbatim}
\end{tscode}
The 0.6 spelling \tscodeinline{[](gls:term)} is still accepted with a deprecation warning.

\section{Other constructs}
\begin{itemize}
\item \textbf{Epigraphs}: tag a blockquote \tscodeinline{\{.epigraph\}}, or set the front-matter
\tscodeinline{epigraph:} key to place one before the first heading.
\item \textbf{Lead-ins}: \tscodeinline{\{lead\}[Boot sequence.] The device powers…} sets a run-in
heading. A paragraph that opens with a short strong span is promoted to one
automatically while the \tscodeinline{paragraph.lead} feature is on.
\item \textbf{Comments}: \tscodeinline{<!-\allowbreak{}-\allowbreak{} note to self -\allowbreak{}-\allowbreak{}>}, inline or block. The node survives the
round-trip and is stripped in every backend by default.
\end{itemize}
