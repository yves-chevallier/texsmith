\title{Supported Markdown Syntax}
\author{}\date{}
\begin{document}
\maketitle
TeXSmith reads TMark: CommonMark plus the extension set every
MkDocs site already loads, plus the four families that cover what print needs.
This page is the quick tour; each row links to the page that explains the
construct.
\begin{tscallout}[kind=info, title={One dialect, no configuration}]
There is no extension list to enable. The parser is the same for the CLI,
the Python API and the MkDocs plugin, and \tscodeinline{tmark check FILE} tells you
exactly what it read.
\end{tscallout}
\section{Core Markdown (Always On)}
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{g+gh}{\PYZsh{} Heading 1}
\PY{g+gu}{\PYZsh{}\PYZsh{} Heading 2}
\PY{g+gu}{\PYZsh{}\PYZsh{}\PYZsh{} Heading 3}

\PY{g+gs}{**bold**}, \PY{g+ge}{*italic*}, \PY{g+gd}{\PYZti{}\PYZti{}strikethrough\PYZti{}\PYZti{}}, \PY{l+s+sb}{`inline code`}

[\PY{n+nt}{Links}](\PY{n+na}{https://www.example.com}) and ![\PY{n+nt}{images}](\PY{n+na}{assets/logo.svg})

\PY{k}{\PYZgt{} }\PY{g+ge}{Blockquote text}

\PY{k}{\PYZhy{}}\PY{+w}{ }Unordered item
\PY{+w}{  }\PY{k}{\PYZhy{}}\PY{+w}{ }Nested item

\PY{k}{1.} Ordered item
\PY{k}{2.} Next item

Dividers:

\PYZhy{}\PYZhy{}\PYZhy{}
\end{Verbatim}
\end{tscode}
All standard CommonMark constructs render as you would expect. A \tscodeinline{-\allowbreak{}-\allowbreak{}-\allowbreak{}} line is
a \textbf{divider}: the web shows \tscodeinline{<hr>}, and the paged writers emit \tscodeinline{\textbackslash{}tsdivider},
which the \tscodeinline{ts-\allowbreak{}typesetting} fragment defines as a page break --- a template
redefines it at will. Inside a container --- a block quote, a callout, a figure,
a \tscodeinline{:::} div, a list item --- the same \tscodeinline{-\allowbreak{}-\allowbreak{}-\allowbreak{}} emits \tscodeinline{\textbackslash{}tsrule} instead (\tscodeinline{<hr
class="rule">} on the web): a separator, never a page break, because a page
break there would tear the container in two.

\section{Working with callouts}
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
::: warning \PYZob{}title=\PYZdq{}LaTeX toolchain\PYZdq{}\PYZcb{}
Remember to install TeX Live, MiKTeX, or MacTeX before running \PY{l+s+sb}{`texsmith \PYZhy{}\PYZhy{}build`}.
:::
\end{Verbatim}
\end{tscode}
The PyMdownX spelling stays accepted indefinitely, because MkDocs Material
renders it natively:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
!!! warning \PYZdq{}LaTeX toolchain\PYZdq{}
    Remember to install TeX Live, MiKTeX, or MacTeX before running \PY{l+s+sb}{`texsmith \PYZhy{}\PYZhy{}build`}.
\end{Verbatim}
\end{tscode}
Callouts render as highlighted boxes in HTML and as \tscodeinline{tcolorbox} blocks in the
\LaTeX{} output. See Admonitions.

\section{Embedding raw \LaTeX{}}
Use a \tscodeinline{latex raw} fence when native \LaTeX{} is required:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{l+s+sb}{```}\PY{l+s+sb}{latex}\PY{+w}{ }raw
\PY{k}{\PYZbs{}begin}\PY{n+nb}{\PYZob{}}\PY{n+nb}{align}\PY{n+nb}{\PYZcb{}}
\PY{n+nb}{E }\PY{n+nb}{\PYZam{}}\PY{o}{=}\PY{n+nb}{ mc}\PY{n+nb}{\PYZca{}}\PY{l+m}{2}\PY{n+nb}{ }\PY{n+nv}{\PYZbs{}\PYZbs{}}
\PY{n+nv}{\PYZbs{}nabla}\PY{n+nb}{ }\PY{n+nv}{\PYZbs{}cdot}\PY{n+nb}{ }\PY{n+nv}{\PYZbs{}vec}\PY{n+nb}{\PYZob{}}\PY{n+nb}{E}\PY{n+nb}{\PYZcb{}}\PY{n+nb}{ }\PY{n+nb}{\PYZam{}}\PY{o}{=}\PY{n+nb}{ }\PY{n+nv}{\PYZbs{}frac}\PY{n+nb}{\PYZob{}}\PY{n+nv}{\PYZbs{}rho}\PY{n+nb}{\PYZcb{}}\PY{n+nb}{\PYZob{}}\PY{n+nv}{\PYZbs{}varepsilon}\PY{n+nb}{\PYZus{}}\PY{l+m}{0}\PY{n+nb}{\PYZcb{}}
\PY{k}{\PYZbs{}end}\PY{n+nb}{\PYZob{}}\PY{n+nb}{align}\PY{n+nb}{\PYZcb{}}
\PY{l+s+sb}{```}
\end{Verbatim}
\end{tscode}
TeXSmith passes the block straight to the \LaTeX{} writer; the Typst and HTML
writers ignore it. For inline adjustments, use the \tscodeinline{raw} role:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
The chapter ends here \PYZob{}raw latex\PYZcb{}(\PYZbs{}clearpage) before appendices.
\end{Verbatim}
\end{tscode}
\tscodeinline{/// latex … ///} and \tscodeinline{\{latex\}[…]} are the 0.6 spellings: still parsed, now
deprecated. See Migrating to TMark.
\section{Includes}
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PYZob{}include\PYZcb{}(includes/built\PYZhy{}in\PYZhy{}tasks.md)
\end{Verbatim}
\end{tscode}
The file is parsed as TMark and spliced into the document, so nested fences are
safe and relative paths inside it are rebased. To pull a code sample from a
file without inlining it, put \tscodeinline{include=} on the fence:
\begin{tscode}[lang=md, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{l+s+sb}{```}\PY{l+s+sb}{python}\PY{+w}{ }include=\PYZdq{}examples/code/bubble\PYZus{}sort.py\PYZdq{}
\PY{l+s+sb}{```}
\end{Verbatim}
\end{tscode}
The PyMdownX snippet syntax \tscodeinline{-\allowbreak{}-\allowbreak{}8<-\allowbreak{}-\allowbreak{} "file"} is accepted as deprecated sugar.
Its marker is \tscodeinline{-\allowbreak{}\{2,\}8<-\allowbreak{}\{2,\}}, so any dash count on either side is the same
spelling (\tscodeinline{-\allowbreak{}-\allowbreak{}-\allowbreak{}8<-\allowbreak{}-\allowbreak{}-\allowbreak{}} included), and a leading \tscodeinline{;} disables the line. See
\href{code.md\#external-sources}{Code}.
\section{Foreign directives}
\tscodeinline{[TOC]} and a \textbf{dotted} \tscodeinline{::: pkg.module} line --- mkdocstrings' syntax, its
options in the indented YAML that follows --- are directives for a processor
other than TMark. Both are kept verbatim, and both are \textbf{dropped by the paged
writers}: the printed table of contents is \tscodeinline{press.toc}, and an API reference
has no print form. A dotted directive raises the hint \tscodeinline{directive-\allowbreak{}foreign} so a
print document does not lose a block without notice. See
\href{admonitions.md\#foreign-directives}{Admonitions}.
\section{When you need more}
\begin{itemize}
\item \tscodeinline{tmark check FILE} parses, resolves and lints a document; \tscodeinline{-\allowbreak{}-\allowbreak{}strict} turns
warnings into failures.
\item \tscodeinline{tmark lint -\allowbreak{}-\allowbreak{}fix FILE} rewrites deprecated spellings.
\item \tscodeinline{tmark parse FILE} prints the intermediate representation as JSON --- the
ground truth about what the parser read.
\item If a feature relies on a third-party executable (Mermaid to PDF, draw.io
export), make sure the binary is available on the build worker before running
\tscodeinline{texsmith -\allowbreak{}-\allowbreak{}build}.
\end{itemize}
