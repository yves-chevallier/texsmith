In our journey to typeset beautiful documents with TeXSmith, we'll start with the basics:
\begin{enumerate}
\item Turn Markdown or HTML into \LaTeX{}/PDF.
\item Drop TeXSmith into an existing MkDocs site.
\item Drive it from Python.
\end{enumerate}
Hop to the section you need or read straight through for the big picture.
\section{Installation}
To install TeXSmith, use your preferred Python package manager:
\begin{tsdiv}{tab}[title=pip]
\begin{tscode}[lang=bash, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
pip\PY{+w}{ }install\PY{+w}{ }texsmith
\end{Verbatim}
\end{tscode}
\end{tsdiv}
\begin{tsdiv}{tab}[title=pipx]
\begin{tscode}[lang=bash, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
pipx\PY{+w}{ }install\PY{+w}{ }texsmith
\end{Verbatim}
\end{tscode}
\end{tsdiv}
\begin{tsdiv}{tab}[title=uv]
\begin{tscode}[lang=bash, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
uv\PY{+w}{ }tool\PY{+w}{ }install\PY{+w}{ }texsmith
\end{Verbatim}
\end{tscode}
\end{tsdiv}
For basic use, you don't need anything else. TeXSmith bundles Tectonic for \LaTeX{} builds and will auto-install the required tools on demand.

To build with the \textbf{Typst} backend (\tscodeinline{-\allowbreak{}-\allowbreak{}format typst}), install the embedded compiler as an extra so no system binary is required:
\begin{tsdiv}{tab}[title=pip]
\begin{tscode}[lang=bash, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
pip\PY{+w}{ }install\PY{+w}{ }\PY{l+s+s2}{\PYZdq{}texsmith[typst]\PYZdq{}}
\end{Verbatim}
\end{tscode}
\end{tsdiv}
\begin{tsdiv}{tab}[title=uv]
\begin{tscode}[lang=bash, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
uv\PY{+w}{ }tool\PY{+w}{ }install\PY{+w}{ }\PY{l+s+s2}{\PYZdq{}texsmith[typst]\PYZdq{}}
\end{Verbatim}
\end{tscode}
\end{tsdiv}
A system \tscodeinline{typst} binary on your \tscodeinline{PATH} is detected automatically as a fallback. See Output backends for details and the math caveat.
\section{Convert a Markdown file to \LaTeX{}}
By default TeXSmith writes \LaTeX{} to stdout. Pipe it or direct it into a folder. HTML works too:
\begin{tsdiv}{tab}[title={Here document}]
\begin{tscode}[lang=text, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PYZdl{} cat \PYZlt{}\PYZlt{} EOF | texsmith
\PYZsh{} Title

Some **bold** text.

\PYZhy{} Foo
\PYZhy{} Bar
EOF
\PYZbs{}section\PYZob{}Title\PYZcb{}

Some \PYZbs{}textbf\PYZob{}bold\PYZcb{} text.

\PYZbs{}begin\PYZob{}itemize\PYZcb{}
\PYZbs{}item Foo
\PYZbs{}item Bar
\PYZbs{}end\PYZob{}itemize\PYZcb{}
\end{Verbatim}
\end{tscode}
\end{tsdiv}
\begin{tsdiv}{tab}[title={From file}]
\begin{tscode}[lang=text, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PYZdl{} printf \PYZsq{}\PYZsh{} Title\PYZbs{}n\PYZbs{}nSome **bold** text.\PYZbs{}n\PYZsq{} \PYZgt{} sample.md
\PYZdl{} texsmith sample.md
\PYZbs{}section\PYZob{}Title\PYZcb{}

Some \PYZbs{}textbf\PYZob{}bold\PYZcb{} text.
\end{Verbatim}
\end{tscode}
Add \tscodeinline{-\allowbreak{}-\allowbreak{}output build/} to write \tscodeinline{build/sample.tex} instead of printing.
\end{tsdiv}
\begin{tsdiv}{tab}[title=HTML]
\begin{tscode}[lang=text, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PYZdl{} echo \PYZdq{}\PYZlt{}h1\PYZgt{}Title\PYZlt{}/h1\PYZgt{}\PYZlt{}p\PYZgt{}Some \PYZlt{}strong\PYZgt{}bold\PYZlt{}/strong\PYZgt{} text.\PYZlt{}/p\PYZgt{}\PYZdq{} \PYZgt{} sample.html
\PYZdl{} texsmith sample.html
\PYZbs{}section\PYZob{}Title\PYZcb{}

Some \PYZbs{}textbf\PYZob{}bold\PYZcb{} text.
\end{Verbatim}
\end{tscode}
\end{tsdiv}
\section{Generate a PDF}
Want the full PDF? Start with our playful \href{https://en.wikipedia.org/wiki/Booby}{booby} example or create your own \tscodeinline{booby.md}:
\begin{tscode}[lang=markdown, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PYZhy{}\PYZhy{}\PYZhy{}
press:
  title: Booby
  author: Yves Chevallier
  date: 2025\PYZhy{}11\PYZhy{}16
\PY{g+gu}{  template: article}
\PY{g+gu}{\PYZhy{}\PYZhy{}\PYZhy{}}
\PY{g+gu}{\PYZsh{}\PYZsh{} Introduction}

Boobies are seabirds in the genus \PY{g+ge}{*Sula*}, family Sulidae. They are
large, long\PYZhy{}winged birds that plunge\PYZhy{}dive for fish. The name \PYZdq{}booby\PYZdq{}
originates from the Spanish word \PYZdq{}bobo\PYZdq{}, meaning \PYZdq{}stupid\PYZdq{} or \PYZdq{}clown\PYZdq{},
due to the birds\PYZsq{} apparent lack of fear of humans.

![\PY{n+nt}{Booby}](\PY{n+na}{booby.png})\PYZob{}width=30\PYZpc{}\PYZcb{}

\PY{g+gu}{\PYZsh{}\PYZsh{} Particularities}

Boobies have several distinctive features:

\PY{k}{\PYZhy{}}\PY{+w}{ }They have brightly colored feet, which they use in mating displays.
\PY{k}{\PYZhy{}}\PY{+w}{ }They are known for their spectacular diving ability, plunging into
  the water from great heights to catch fish.
\end{Verbatim}
\end{tscode}
Notice the front matter up top: it carries the title, author, date, and template to use.

Then let TeXSmith crunch it:
\begin{tscode}[lang=bash, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
texsmith\PY{+w}{ }booby.md\PY{+w}{ }\PYZhy{}\PYZhy{}output\PY{+w}{ }build/\PY{+w}{ }\PYZhy{}apaper\PY{o}{=}a5\PY{+w}{ }\PYZhy{}\PYZhy{}build
\end{Verbatim}
\end{tscode}
With Tectonic as the default engine, fonts, packages, and dependencies resolve themselves on demand (including Tectonic if it is missing). Nothing else to install.

Enjoy a fresh PDF at \tscodeinline{build/booby.pdf}:
\begin{figure}[H]
\centering
\includegraphics[width=0.7\linewidth]{snippet-<HASH>.pdf}
\caption[Demo]{Demo}
\end{figure}
Peek inside \tscodeinline{build/} to find \tscodeinline{booby.tex}. Swap \tscodeinline{-\allowbreak{}-\allowbreak{}template} when you want a different \LaTeX{} project layout or polish level:
\begin{tscode}[lang=bash, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
texsmith\PY{+w}{ }booby.md\PY{+w}{ }\PYZhy{}\PYZhy{}template\PY{+w}{ }article\PY{+w}{ }\PYZhy{}\PYZhy{}output\PYZhy{}dir\PY{+w}{ }build
\end{Verbatim}
\end{tscode}
The default toolchain is \tscodeinline{tectonic}, which auto-installs itself and required packages. If you prefer using your system \LaTeX{} installation, specify \tscodeinline{-\allowbreak{}-\allowbreak{}engine lualatex} or \tscodeinline{-\allowbreak{}-\allowbreak{}engine xelatex} instead. Both commands yield \tscodeinline{doc.pdf} in the current directory. Open it to see the rendered output.

If you want to customize the layout, choose a template with \tscodeinline{-\allowbreak{}-\allowbreak{}template article}, \tscodeinline{-\allowbreak{}-\allowbreak{}template book} or \tscodeinline{-\allowbreak{}-\allowbreak{}template your-\allowbreak{}own-\allowbreak{}template}.

\section{Check a document before you build}
TeXSmith reads TMark, and the \tscodeinline{tmark} toolchain checks a
document without rendering anything:
\begin{tscode}[lang=bash, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
tmark\PY{+w}{ }check\PY{+w}{ }\PYZhy{}\PYZhy{}strict\PY{+w}{ }document.md\PY{+w}{   }\PY{c+c1}{\PYZsh{} parse, resolve and lint; exit 1 on any finding}
tmark\PY{+w}{ }lint\PY{+w}{ }\PYZhy{}\PYZhy{}fix\PY{+w}{ }\PYZhy{}\PYZhy{}diff\PY{+w}{ }document.md\PY{+w}{ }\PY{c+c1}{\PYZsh{} preview the rewrite of deprecated spellings}
tmark\PY{+w}{ }lint\PY{+w}{ }\PYZhy{}\PYZhy{}fix\PY{+w}{ }document.md\PY{+w}{        }\PY{c+c1}{\PYZsh{} apply it in place}
\end{Verbatim}
\end{tscode}
\tscodeinline{check} reports what the converter will see: unresolved references, undeclared
counter prefixes, malformed tables, deprecated spellings. Coming from TeXSmith
0.6? Every spelling you know still works, and
Migrating to TMark lists what changed and what rewrites it.

\tscodeinline{texsmith} reports the same findings in the same shape while it renders. Add
\tscodeinline{-\allowbreak{}-\allowbreak{}strict} to refuse to build a PDF from a document that has any, \tscodeinline{-\allowbreak{}q} to hide
the hints and info lines, and \tscodeinline{-\allowbreak{}-\allowbreak{}diagnostics-\allowbreak{}json FILE} to hand the lot to an
editor or to CI:
\begin{tscode}[lang=bash, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
texsmith\PY{+w}{ }report.md\PY{+w}{ }\PYZhy{}\PYZhy{}build\PY{+w}{ }\PYZhy{}\PYZhy{}strict\PY{+w}{ }\PYZhy{}\PYZhy{}deprecated\PY{+w}{ }info
\end{Verbatim}
\end{tscode}
\tscodeinline{-\allowbreak{}-\allowbreak{}deprecated info} keeps the 0.6 spellings from failing a strict run while you
work through them. See Diagnostics.
\section{Optional prerequisites}
\begin{description}
\item[{\LaTeX{} distribution}] Install \TeX{} Live, MiKTeX, or MacTeX if you want TeXSmith to hand off builds to \tscodeinline{latexmk} (\tscodeinline{-\allowbreak{}-\allowbreak{}engine lualatex} / \tscodeinline{-\allowbreak{}-\allowbreak{}engine xelatex}). The default route uses Tectonic, which auto-installs itself and required packages.
\item[{Typst compiler}] Needed only for \tscodeinline{-\allowbreak{}-\allowbreak{}format typst -\allowbreak{}-\allowbreak{}build}. Install the embedded compiler with \tscodeinline{pip install "texsmith[typst]"}, or put a \tscodeinline{typst} binary on your \tscodeinline{PATH}. Emitting the \tscodeinline{.typ} source (without \tscodeinline{-\allowbreak{}-\allowbreak{}build}) needs no compiler. See Output backends.
\item[{Diagram tooling}] Mermaid-to-PDF (\tscodeinline{minlag/mermaid-\allowbreak{}cli}) conversion falls back to Docker. Install Docker Desktop (with WSL integration on Windows) or register your own converter if Mermaid diagrams are common in your docs.
\end{description}
Draw.io and Mermaid diagrams try a Playwright exporter first (cached under \tscodeinline{\textasciitilde{}/.cache/texsmith/playwright}), then the local CLI, then Docker (\tscodeinline{rlespinasse/drawio-\allowbreak{}desktop-\allowbreak{}headless} / \tscodeinline{minlag/mermaid-\allowbreak{}cli}). Use \tscodeinline{-\allowbreak{}-\allowbreak{}diagrams-\allowbreak{}backend=playwright|local|docker} to pin a specific backend.
\begin{description}
\item[{Fonts}] TeXSmith ships with Noto fallback for wide Unicode coverage. Add your own fonts if you want a specific script or branded look.
\item[{Legacy \LaTeX{} accents}] By default TeXSmith emits Unicode glyphs. If you need legacy \LaTeX{} accent macros, pass \tscodeinline{-\allowbreak{}-\allowbreak{}legacy-\allowbreak{}latex-\allowbreak{}accents} on the CLI or set \tscodeinline{ConversionRequest(legacy\_latex\_accents=True)} in the API.
\end{description}
\section{Use the Python API}
TeXSmith also ships as a Python library. Create \tscodeinline{demo.py}:
\begin{tscode}[lang=python, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{k+kn}{from}\PY{+w}{ }\PY{n+nn}{pathlib}\PY{+w}{ }\PY{k+kn}{import} \PY{n}{Path}
\PY{k+kn}{from}\PY{+w}{ }\PY{n+nn}{texsmith}\PY{+w}{ }\PY{k+kn}{import} \PY{n}{Document}\PY{p}{,} \PY{n}{convert\PYZus{}documents}

\PY{n}{bundle} \PY{o}{=} \PY{n}{convert\PYZus{}documents}\PY{p}{(}
    \PY{p}{[}\PY{n}{Document}\PY{o}{.}\PY{n}{from\PYZus{}markdown}\PY{p}{(}\PY{n}{Path}\PY{p}{(}\PY{l+s+s2}{\PYZdq{}}\PY{l+s+s2}{intro.md}\PY{l+s+s2}{\PYZdq{}}\PY{p}{)}\PY{p}{)}\PY{p}{]}\PY{p}{,}
    \PY{n}{output\PYZus{}dir}\PY{o}{=}\PY{n}{Path}\PY{p}{(}\PY{l+s+s2}{\PYZdq{}}\PY{l+s+s2}{build}\PY{l+s+s2}{\PYZdq{}}\PY{p}{)}\PY{p}{,}
\PY{p}{)}

\PY{n+nb}{print}\PY{p}{(}\PY{l+s+s2}{\PYZdq{}}\PY{l+s+s2}{Fragments:}\PY{l+s+s2}{\PYZdq{}}\PY{p}{,} \PY{p}{[}\PY{n}{fragment}\PY{o}{.}\PY{n}{stem} \PY{k}{for} \PY{n}{fragment} \PY{o+ow}{in} \PY{n}{bundle}\PY{o}{.}\PY{n}{fragments}\PY{p}{]}\PY{p}{)}
\PY{n+nb}{print}\PY{p}{(}\PY{l+s+s2}{\PYZdq{}}\PY{l+s+s2}{Preview:}\PY{l+s+s2}{\PYZdq{}}\PY{p}{,} \PY{n}{bundle}\PY{o}{.}\PY{n}{combined\PYZus{}output}\PY{p}{(}\PY{p}{)}\PY{p}{[}\PY{p}{:}\PY{l+m+mi}{120}\PY{p}{]}\PY{p}{)}

\section{Convert a MkDocs site}
Point TeXSmith at a MkDocs site after \tscodeinline{mkdocs build} renders clean HTML:
\begin{tscode}[lang=bash, engine=pygments]
\begin{Verbatim}[commandchars=\\\{\},breaklines, breakanywhere, commandchars=\\\{\}]
\PY{c+c1}{\PYZsh{} Build your MkDocs site into a disposable directory}
mkdocs\PY{+w}{ }build

\PY{c+c1}{\PYZsh{} Convert one page into LaTeX/PDF\PYZhy{}ready assets}
texsmith\PY{+w}{ }build/site/guides/overview/index.html\PY{+w}{ }\PY{l+s+se}{\PYZbs{}}
\PY{+w}{  }\PYZhy{}\PYZhy{}template\PY{+w}{ }article\PY{+w}{ }\PY{l+s+se}{\PYZbs{}}
\PY{+w}{  }\PYZhy{}\PYZhy{}output\PYZhy{}dir\PY{+w}{ }build/press\PY{+w}{ }\PY{l+s+se}{\PYZbs{}}
\PY{+w}{  }docs/references.bib
\end{Verbatim}
\end{tscode}
\begin{tscallout}[kind=tip]
When your site spans multiple documents, repeat the command per page and stitch them together with template slots (for example, \tscodeinline{-\allowbreak{}-\allowbreak{}slot mainmatter:docs/manual/index.md}).

For live previews, point TeXSmith at the temporary site directory that \tscodeinline{mkdocs serve} prints on startup.

Once the \LaTeX{} bundle looks good, add \tscodeinline{-\allowbreak{}-\allowbreak{}build} to invoke your engine of choice or wire it into CI so MkDocs HTML \tsscript{symbols}{\(\rightarrow\) }TeXSmith PDF runs on every build.
\end{tscallout}
