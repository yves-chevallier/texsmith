\section{Attribute ownership \& consumers}
\begin{itemize}
\item \textbf{Owner}: each attribute belongs to either the template (default) or a fragment (\tscodeinline{fragment.toml} attributes set \tscodeinline{owner = <fragment name>} implicitly). Conflicting owners raise a \tscodeinline{TemplateError}.
\item \textbf{Emitter}: templates can surface derived attributes through \tscodeinline{emit} in \tscodeinline{manifest.toml} so renderers see both declared attributes and emitted helpers (for example, \tscodeinline{callout\_style} or \tscodeinline{code.engine}).
\item \textbf{Consumer}: any template/fragment/renderer code that reads the attribute. Consumers should only read attributes they own or that are explicitly emitted.
\item Precedence: CLI/front matter overrides \tsscript{symbols}{\(\rightarrow\) }attribute resolver (type coercion, normaliser, escape) \tsscript{symbols}{\(\rightarrow\) }emitted defaults \tsscript{symbols}{\(\rightarrow\) }render-time context.
\end{itemize}
When adding new attributes, pick a single owner (template or fragment) and document the sources that are allowed to override it.
