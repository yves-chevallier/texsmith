\title{Troubleshooting \LaTeX{} Builds}
\author{}\date{}
\begin{document}
\maketitle
Running \tscodeinline{texsmith -\allowbreak{}-\allowbreak{}build} shells out to your selected engine (Tectonic by default, \tscodeinline{latexmk} when \tscodeinline{-\allowbreak{}-\allowbreak{}engine} is set to \tscodeinline{xelatex}/\tscodeinline{lualatex}), \tscodeinline{bibtex}/\tscodeinline{biber}, and any template assets declared in \tscodeinline{manifest.toml}. When those tools fail, the CLI will highlight the failing step and (optionally) open the log file. Use this page to decode the most common issues.
\section{Enable rich diagnostics}
\begin{itemize}
\item Add \tscodeinline{-\allowbreak{}v} or \tscodeinline{-\allowbreak{}vv} to surface structured diagnostics from the conversion pipeline (missing slots, unresolved citations, asset copy failures).
\item Pass \tscodeinline{-\allowbreak{}-\allowbreak{}debug} to print full Python tracebacks if TeXSmith itself throws.
\item Combine \tscodeinline{-\allowbreak{}-\allowbreak{}classic-\allowbreak{}output} with CI logs when you need deterministic engine output, or keep the default rich output locally for incremental updates.
\item When the engine exits non-zero, re-run with \tscodeinline{-\allowbreak{}-\allowbreak{}open-\allowbreak{}log} to jump directly into the \tscodeinline{.log} file.
\end{itemize}
\section{latexmk not found}
\textbf{Symptom:} \tscodeinline{latexmk: command not found} or TeXSmith reports it cannot spawn the binary.

\textbf{Fix:} Ensure your \TeX{} Live/MacTeX/MiKTeX distribution added \tscodeinline{latexmk} to \tscodeinline{PATH}. On macOS, \tscodeinline{eval "\$(/usr/libexec/path\_helper -\allowbreak{}s)"} after installing MacTeX. On Windows, open the ``\LaTeX{} apps'' PowerShell and run TeXSmith from there.
\section{tectonic not found}
\textbf{Symptom:} \tscodeinline{tectonic: command not found} or TeXSmith reports missing dependencies before starting the build.

\textbf{Fix:} Install Tectonic from your package manager (\tscodeinline{brew install tectonic}, \tscodeinline{apt install tectonic}, or \tscodeinline{cargo install tectonic}) or download a prebuilt binary from \url{https://tectonic-typesetting.github.io/}. Ensure the \tscodeinline{tectonic} executable is on \tscodeinline{PATH} before re-running TeXSmith. You can also switch to \tscodeinline{-\allowbreak{}-\allowbreak{}engine lualatex}/\tscodeinline{xelatex} to keep using \tscodeinline{latexmk}.
\section{Missing tlmgr packages}
\textbf{Symptom:} \tscodeinline{LaTeX Error: File <package>.sty not found}.

\textbf{Fix:} Run \tscodeinline{texsmith -\allowbreak{}-\allowbreak{}template <NAME> -\allowbreak{}-\allowbreak{}template-\allowbreak{}info} and install the listed tlmgr packages (\tscodeinline{tlmgr install ...}). Distributions with minimal profiles (BasicTeX, MikTeX) require this step for every template.
\section{Shell-escape blocked}
\textbf{Symptom:} \tscodeinline{shell escape feature is not enabled} when templates run \tscodeinline{minted}, \tscodeinline{gnuplot}, or diagram converters.

\textbf{Fix:} \tscodeinline{texsmith -\allowbreak{}-\allowbreak{}template-\allowbreak{}info} indicates whether \tscodeinline{shell\_escape} is required. Re-run \tscodeinline{texsmith -\allowbreak{}-\allowbreak{}build -\allowbreak{}-\allowbreak{}classic-\allowbreak{}output} to confirm the flag. With \tscodeinline{-\allowbreak{}-\allowbreak{}engine lualatex}/\tscodeinline{xelatex}, edit your \TeX{} Live config or pass \tscodeinline{latexmk -\allowbreak{}shell-\allowbreak{}escape} by exporting \tscodeinline{LATEXMKOPT="-\allowbreak{}shell-\allowbreak{}escape"}. If you're using Tectonic, switch to \tscodeinline{-\allowbreak{}-\allowbreak{}engine lualatex} when you need tighter control over \tscodeinline{-\allowbreak{}shell-\allowbreak{}escape}.
\section{Bibliography failures}
\textbf{Symptom:} \tscodeinline{biber}/\tscodeinline{bibtex} errors such as \tscodeinline{I couldn't open database file} or duplicate citation keys.

\tslead{Fix:}
\begin{itemize}
\item Run \tscodeinline{texsmith references.bib -\allowbreak{}-\allowbreak{}list-\allowbreak{}bibliography} to validate files before building.
\item Make sure every bibliography file you pass as input exists and is UTF-8 encoded.
\item If \tscodeinline{biber} complains about encoding, add \tscodeinline{encoding = "UTF-\allowbreak{}8"} to your template manifest bibliography section or normalise via \tscodeinline{pybtex}.
\end{itemize}
\section{Figures or diagrams missing}
\textbf{Symptom:} Placeholder boxes in the PDF and warnings like \tscodeinline{Converter 'mermaid' is disabled}.

\textbf{Fix:} Install optional converters (Docker + \tscodeinline{minlag/mermaid-\allowbreak{}cli}, Draw.io CLI, etc.) or register custom converters in \tscodeinline{texsmith.adapters.transformers}. Pin the backend with \tscodeinline{-\allowbreak{}-\allowbreak{}diagrams-\allowbreak{}backend playwright|local|docker} to see which one is failing instead of letting the automatic fallback swallow it, and add \tscodeinline{-\allowbreak{}vv} to print what each attempt tried.
\section{Fonts or language mismatches}
\textbf{Symptom:} \tscodeinline{Package polyglossia Error} or \tscodeinline{fontspec} warnings after switching languages.

\textbf{Fix:} Ensure the \tscodeinline{press.language} metadata (front matter or CLI \tscodeinline{-\allowbreak{}-\allowbreak{}language}) maps to a Babel/Polyglossia identifier. Refer to \tscodeinline{texsmith -\allowbreak{}-\allowbreak{}template-\allowbreak{}info} to confirm defaults and install any necessary language packages (e.g., \tscodeinline{tlmgr install babel-\allowbreak{}french}).
\section{Still stuck?}
\begin{enumerate}
\item Re-run with \tscodeinline{-\allowbreak{}-\allowbreak{}debug -\allowbreak{}-\allowbreak{}classic-\allowbreak{}output -\allowbreak{}vv} to capture both TeXSmith diagnostics and raw \tscodeinline{latexmk} logs.
\item Attach the failing \tscodeinline{.log} plus your template manifest when filing an issue.
\item Mention your \TeX{} distribution and operating system so maintainers can reproduce the environment.
\end{enumerate}
