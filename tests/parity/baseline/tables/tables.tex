\thispagestyle{plain}
One true missing feature in Markdown and in most \LaTeX{} documents is the
ability to describe complex tables without tedious boilerplate. The standard
Markdown specification is too restrictive --- no multi-line cells, no multi-row
or multi-column cells, no meta-information --- and raw \LaTeX{} tables require too
much scaffolding. TeXSmith keeps Markdown for simple tables and introduces a
YAML-based description for the complex ones.

The supported features are:

\begin{itemize}
\item{} Multi-line cells
\item{} Multi-row and multi-column cells, both in headers and in the body
\item{} Horizontal separators, with optional section label
\item{} Footer rows (summary rows)
\item{} Column alignment (\texttt{l}, \texttt{c}, \texttt{r}) with per-cell override
\item{} Width groups (columns sharing the same width)
\item{} Overall table width (\texttt{auto}, a percentage of \texttt{\textbackslash{}linewidth}, or a fixed length)
\item{} Markdown formatting preserved inside cells
\item{} Captions and labels via the standard \texttt{Table: …} syntax
\item{} Full HTML output with enough meta-information for the LaTeX renderer to
  pick the right environment (\texttt{tabular}, \texttt{tabularx}, or \texttt{longtable})

\end{itemize}
Each section below shows the YAML source on the left and the rendered table
right after, so you can compare input and output at a glance.

\section{Captions and labels}\label{captions-and-labels}

A YAML table is written as a fenced code block whose info string is
\texttt{yaml table}. Captions follow the standard TeXSmith \texttt{Table: …} syntax placed
on the line directly above the fence; an optional \texttt{\{\#tbl:foo\}} adds a
referenceable label.

Notable attributes:

\begin{itemize}
\item{} The first column is the \textbf{label column} (its values become the row
  headers); subsequent columns hold data.
\item{} \texttt{\textasciitilde{}} (YAML null) marks an empty cell.
\item{} A \texttt{separator:} row inserts a horizontal rule and may carry a \texttt{label:} for
  a section title.
\item{} The \texttt{footer:} block produces summary rows separated from the body by an
  extra rule.

\end{itemize}

\section{Complex grouped headers}\label{complex-grouped-headers}

A column can either be a leaf (a string or \texttt{\{name, …\}} mapping) or a group
(\texttt{\{name, columns: [...]\}}). Groups can carry their own metadata that
propagates to their leaves.

Notable attributes:

\begin{itemize}
\item{} \texttt{table.width: 100\%} forces the table to span \texttt{\textbackslash{}linewidth} and selects
  \texttt{tabularx} as the LaTeX environment.
\item{} \texttt{width-\allowbreak{}group: <id>} makes every column carrying the same identifier share
  the same width --- perfect for keeping the FY23 and FY24 quarters aligned.
\item{} The label column (\texttt{Product}) is left auto-sized; only the columns inside
  width-groups absorb the remaining horizontal space.
\item{} A list cell \texttt{[120, 135, 150, 140]} fills a grouped column's leaves
  positionally; \texttt{\textasciitilde{}} inside such a list leaves an empty leaf.

\end{itemize}

\section{Named-row mode}\label{named-row-mode}

The same data can be written declaratively, where each row explicitly names
the columns it fills. Unspecified columns are left empty and typos in column
names are caught as validation errors.

Notable attributes:

\begin{itemize}
\item{} Shorthand form \texttt{\{Apples: \{FY23: [...], FY24: [...]\}\}} --- the row's only key
  is the label, mapped to a dict of column-name \(\rightarrow\) value.
\item{} Explicit form \texttt{\{label: …, cells: \{…\}\}} lets you spell things out and
  document each row.
\item{} Listing only some columns is fine; the others render as empty cells.

\end{itemize}

\section{Three-level headers}\label{three-level-headers}

Headers can nest arbitrarily deeply. The example below shows a
year \(\rightarrow\) quarter \(\rightarrow\) month hierarchy that produces three header rows with
\texttt{\textbackslash{}cmidrule} strokes between groupings.

Notable attributes:

\begin{itemize}
\item{} Each \texttt{name + columns} block adds one extra header level.
\item{} A single list cell \texttt{[10, 12, 15, 18, 20, 22]} flattens across all leaves of
  the outer group regardless of nesting depth.

\end{itemize}

\section{Multi-row cell in the body}\label{multi-row-cell-in-the-body}

\texttt{cols} and/or \texttt{align}). Setting \texttt{rows: N} makes the cell span \texttt{N} consecutive
rows; the next \texttt{N-\allowbreak{}1} rows must use \texttt{\textasciitilde{}} at the same column position to

\begin{itemize}
\item{} \texttt{\{value: Maria, rows: 2\}} --- span two rows, value rendered via LaTeX
  \texttt{\textbackslash{}multirow}.

  there with a clear error).

\end{itemize}

\section{Width control}\label{width-control}

By default the table width is \texttt{auto} (natural column widths, \texttt{tabular}).
Setting \texttt{table.width} to a percentage of \texttt{\textbackslash{}linewidth} forces the table to
span that width and selects \texttt{tabularx}, with at least one column kept
flexible (\texttt{X}) to absorb the remainder. Individual columns can carry a fixed
\texttt{width} (an absolute length or a percentage of the table); columns sharing
the same \texttt{width-\allowbreak{}group} are forced to match.

\subsection{Fixed columns + flexible description}\label{fixed-columns-flexible-description}

Notable attributes:

\begin{itemize}
\item{} \texttt{align: j} (justified) is applied to the \texttt{Description} column, which is
  the only one without an explicit width --- it becomes the flexible \texttt{X}
  column that absorbs the remainder.
\item{} \texttt{align: l} and \texttt{align: c} set left and centre alignment on the fixed
  columns.

\end{itemize}

\section{Headerless tables}\label{headerless-tables}

Sometimes a table is just a two-column key/value summary --- no real column
headers, only the rows themselves. Omit the \texttt{name} field on every column and
the renderer drops the \texttt{<thead>} (and the corresponding \LaTeX{} \texttt{\textbackslash{}midrule})
so the body sits directly under the \texttt{\textbackslash{}toprule}. The columns still accept
\texttt{align}, \texttt{width}, and \texttt{width-\allowbreak{}group} exactly as in a regular table.

Notable attributes:

\begin{itemize}
\item{} No \texttt{name:} on any column \(\rightarrow\) no header rows emitted.
\item{} The first column remains the \textbf{label column}; row labels still take the
  first cell of each row.

\end{itemize}

\section{Plain Markdown tables, qualified by \texttt{yaml table-\allowbreak{}config}}\label{plain-markdown-tables-qualified-by-texttt-yaml-table-allowbreak-config}

Markdown's pipe table syntax stays the most ergonomic input format for short,
literal tables. To give those tables real \LaTeX{} semantics --- picking
\texttt{tabularx}, choosing alignment per column, marking one column as the
flexible (\texttt{X}) one --- drop a \texttt{yaml table-\allowbreak{}config} fence right below the
markdown table:

Notable attributes:

\begin{itemize}
\item{} The fence is a regular code block whose info string is \texttt{yaml table-\allowbreak{}config}.
  It must directly follow the table (only the standard blank line in
  between).
\item{} \texttt{columns} is matched \textbf{positionally} to the markdown columns; no \texttt{name}
  is required.
\item{} \texttt{align} accepts both short forms (\texttt{l}, \texttt{c}, \texttt{r}, \texttt{j}) and long forms
  (\texttt{left}, \texttt{center}, \texttt{right}, \texttt{justify}).
\item{} \texttt{width: X} (case-insensitive) marks a column as the flexible one --- it
  becomes the LaTeX \texttt{X} column that absorbs the remaining width. Other
  columns size to their content. The renderer automatically switches the
  table to \texttt{tabularx\{\textbackslash{}linewidth\}\{…\}}.
\item{} Standard \texttt{width} values (percentages, lengths) and \texttt{width-\allowbreak{}group} work
  the same as in full yaml-tables.

\end{itemize}
