\title{Advanced Tables Formatting}
\author{}\date{}
\begin{document}
\maketitle
One true missing feature in Markdown and in most \LaTeX{} documents is the
ability to describe complex tables without tedious boilerplate. The standard
Markdown specification is too restrictive --- no multi-line cells, no multi-row
or multi-column cells, no meta-information --- and raw \LaTeX{} tables require too
much scaffolding. TeXSmith keeps Markdown for simple tables and introduces a
YAML-based description for the complex ones.

The supported features are:
\begin{itemize}
\item Multi-line cells
\item Multi-row and multi-column cells, both in headers and in the body
\item Horizontal separators, with optional section label
\item Footer rows (summary rows)
\item Column alignment (\tscodeinline{l}, \tscodeinline{c}, \tscodeinline{r}) with per-cell override
\item Width groups (columns sharing the same width)
\item Overall table width (\tscodeinline{auto}, a percentage of \tscodeinline{\textbackslash{}linewidth}, or a fixed length)
\item Markdown formatting preserved inside cells
\item Captions and labels via the standard \tscodeinline{Table: …} syntax
\item Full HTML output with enough meta-information for the \LaTeX{} renderer to
pick the right environment (\tscodeinline{tabular}, \tscodeinline{tabularx}, or \tscodeinline{longtable})
\end{itemize}
Each section below shows the YAML source on the left and the rendered table
right after, so you can compare input and output at a glance.
\section{Captions and labels}
A YAML table is written as a fenced code block whose info string is
\tscodeinline{yaml table}. Captions follow the standard TeXSmith \tscodeinline{Table: …} syntax placed
on the line directly above the fence; an optional \tscodeinline{\{\#tbl:foo\}} adds a
referenceable label.

Notable attributes:
\begin{itemize}
\item The first column is the \textbf{label column} (its values become the row
headers); subsequent columns hold data.
\item \tscodeinline{\textasciitilde{}} (YAML null) marks an empty cell.
\item A \tscodeinline{separator:} row inserts a horizontal rule and may carry a \tscodeinline{label:} for
a section title.
\item The \tscodeinline{footer:} block produces summary rows separated from the body by an
extra rule.
\end{itemize}

\section{Complex grouped headers}
A column can either be a leaf (a string or \tscodeinline{\{name, …\}} mapping) or a group
(\tscodeinline{\{name, columns: [...]\}}). Groups can carry their own metadata that
propagates to their leaves.

Notable attributes:
\begin{itemize}
\item \tscodeinline{table.width: 100\%} forces the table to span \tscodeinline{\textbackslash{}linewidth} and selects
\tscodeinline{tabularx} as the \LaTeX{} environment.
\item \tscodeinline{width-\allowbreak{}group: <id>} makes every column carrying the same identifier share
the same width --- perfect for keeping the FY23 and FY24 quarters aligned.
\item The label column (\tscodeinline{Product}) is left auto-sized; only the columns inside
width-groups absorb the remaining horizontal space.
\item A list cell \tscodeinline{[120, 135, 150, 140]} fills a grouped column's leaves
positionally; \tscodeinline{\textasciitilde{}} inside such a list leaves an empty leaf.
\end{itemize}

\section{Named-row mode}
The same data can be written declaratively, where each row explicitly names
the columns it fills. Unspecified columns are left empty and typos in column
names are caught as validation errors.

Notable attributes:
\begin{itemize}
\item Shorthand form \tscodeinline{\{Apples: \{FY23: [...], FY24: [...]\}\}} --- the row's only key
is the label, mapped to a dict of column-name \tsscript{symbols}{\(\rightarrow\) }value.
\item Explicit form \tscodeinline{\{label: …, cells: \{…\}\}} lets you spell things out and
document each row.
\item Listing only some columns is fine; the others render as empty cells.
\end{itemize}

\section{Three-level headers}

year \tsscript{symbols}{\(\rightarrow\) }quarter \tsscript{symbols}{\(\rightarrow\) }month hierarchy that produces three header rows with
\tscodeinline{\textbackslash{}cmidrule} strokes between groupings.

Notable attributes:
\begin{itemize}
\item Each \tscodeinline{name + columns} block adds one extra header level.
\item A single list cell \tscodeinline{[10, 12, 15, 18, 20, 22]} flattens across all leaves of
the outer group regardless of nesting depth.
\end{itemize}

\section{Multi-row cell in the body}
Any cell can be promoted to a \emph{rich cell} (a mapping with \tscodeinline{value}, \tscodeinline{rows},
\tscodeinline{cols} and/or \tscodeinline{align}). Setting \tscodeinline{rows: N} makes the cell span \tscodeinline{N} consecutive
rows; the next \tscodeinline{N-\allowbreak{}1} rows must use \tscodeinline{\textasciitilde{}} at the same column position to
acknowledge the absorption --- the validator refuses anything else.

Notable attributes:
\begin{itemize}
\item \tscodeinline{\{value: Maria, rows: 2\}} --- span two rows, value rendered via \LaTeX{}
\tscodeinline{\textbackslash{}multirow}.
\item The absorbing \tscodeinline{\textasciitilde{}} is required (the validator rejects a stray real value
there with a clear error).
\end{itemize}

\section{Width control}
By default the table width is \tscodeinline{auto} (natural column widths, \tscodeinline{tabular}).
Setting \tscodeinline{table.width} to a percentage of \tscodeinline{\textbackslash{}linewidth} forces the table to
span that width and selects \tscodeinline{tabularx}, with at least one column kept
flexible (\tscodeinline{X}) to absorb the remainder. Individual columns can carry a fixed
\tscodeinline{width} (an absolute length or a percentage of the table); columns sharing
the same \tscodeinline{width-\allowbreak{}group} are forced to match.
\subsection{Fixed columns + flexible description}
Notable attributes:
\begin{itemize}
\item \tscodeinline{align: j} (justified) is applied to the \tscodeinline{Description} column, which is
the only one without an explicit width --- it becomes the flexible \tscodeinline{X}
column that absorbs the remainder.
\item \tscodeinline{align: l} and \tscodeinline{align: c} set left and centre alignment on the fixed
columns.
\end{itemize}

\section{Headerless tables}
Sometimes a table is just a two-column key/value summary --- no real column
headers, only the rows themselves. Omit the \tscodeinline{name} field on every column and
the renderer drops the \tscodeinline{<thead>} (and the corresponding \LaTeX{} \tscodeinline{\textbackslash{}midrule})
so the body sits directly under the \tscodeinline{\textbackslash{}toprule}. The columns still accept
\tscodeinline{align}, \tscodeinline{width}, and \tscodeinline{width-\allowbreak{}group} exactly as in a regular table.

Notable attributes:
\begin{itemize}
\item No \tscodeinline{name:} on any column \tsscript{symbols}{\(\rightarrow\) }no header rows emitted.
\item The first column remains the \textbf{label column}; row labels still take the
first cell of each row.
\item Per-column \tscodeinline{align} and \tscodeinline{width} keep their usual meaning, so a typical
headerless layout is a fixed-width key column plus a justified value
column that absorbs the remainder of the line.
\end{itemize}

\section{Plain Markdown tables, qualified by \tscodeinline{yaml table-\allowbreak{}config}}
Markdown's pipe table syntax stays the most ergonomic input format for short,
literal tables. To give those tables real \LaTeX{} semantics --- picking
\tscodeinline{tabularx}, choosing alignment per column, marking one column as the
flexible (\tscodeinline{X}) one --- drop a \tscodeinline{yaml table-\allowbreak{}config} fence right below the
markdown table:

Notable attributes:
\begin{itemize}
\item The fence is a regular code block whose info string is \tscodeinline{yaml table-\allowbreak{}config}.
It must directly follow the table (only the standard blank line in
between).
\item \tscodeinline{columns} is matched \textbf{positionally} to the markdown columns; no \tscodeinline{name}
is required.
\item \tscodeinline{align} accepts both short forms (\tscodeinline{l}, \tscodeinline{c}, \tscodeinline{r}, \tscodeinline{j}) and long forms
(\tscodeinline{left}, \tscodeinline{center}, \tscodeinline{right}, \tscodeinline{justify}).
\item \tscodeinline{width: X} (case-insensitive) marks a column as the flexible one --- it
becomes the \LaTeX{} \tscodeinline{X} column that absorbs the remaining width. Other
columns size to their content. The renderer automatically switches the
table to \tscodeinline{tabularx\{\textbackslash{}linewidth\}\{…\}}.
\item Standard \tscodeinline{width} values (percentages, lengths) and \tscodeinline{width-\allowbreak{}group} work
the same as in full yaml-tables.
\end{itemize}

builds, but a clearly identified block tells you exactly what went wrong and
where. Each error case below is a deliberate mistake.
